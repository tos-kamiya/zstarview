# Session 2026-07-20

Scope: Document the night-light altitude/azimuth blur separation.

- Topic: Reflect direction-specific night-light blur in documentation
  - Decision: Document that distance-dependent altitude sigma remains unchanged while azimuth sigma uses `NIGHT_LIGHTS_AZIMUTH_SIGMA_SCALE` (currently `0.75`).
  - Rationale: The implementation separates vertical glow visibility from horizontal source spreading so the effect of the trial setting is explicit in both the user-facing specification and internal design reference.

- Topic: Interpret the GUI `PLATEAU 7304` status
  - Decision: Treat `7304` as the number of rendered PLATEAU urban outlines, not as a municipality code. The PLATEAU preparation CLI still accepts the five-digit municipality code separately.
  - Rationale: The GUI sets `base_outline_count` to `len(outlines)` for a prepared PLATEAU cache, and the status formatter renders `PLATEAU <base_outline_count>`. Confusing this count with the source municipality code makes the status difficult to reconcile with e-Stat.

- Topic: Design a cache listing mode for the PLATEAU preparation CLI
  - Decision: Add a read-only `--list` mode to `zstarview-download-plateau-buildings`, with optional `--json`, `--all`, `--city-code`, and existing `--output-root` filtering. Keep the default listing limited to complete, structurally valid active caches.
  - Rationale: A flag preserves the existing command and avoids network access or mutation. The existing cache metadata already provides the useful summary fields; cache validation should reuse the same completion and tile-index criteria used by runtime discovery. Archived `.outdated-*`, `.replaced-*`, and `.incomplete-*` directories should be hidden by default but inspectable with `--all`.

- Topic: Simplify the PLATEAU cache listing interface
  - Decision: Make `--list` enumerate all valid caches by default, across municipalities and dataset years. The plain output contains only `city_code`, dataset `year`, and the saved path, one record per line. `--city-code` acts as a filter; an explicit `--all` option is unnecessary because all valid entries are already the default.
  - Rationale: The command should behave like a small Unix inventory tool. Invalid, incomplete, and malformed caches are omitted. Use `--jsonl` for detailed metadata because one JSON object per line preserves the line-oriented and streaming nature of the listing; the object includes the saved path and cache metadata.

- Topic: Implement the PLATEAU cache listing mode
  - Decision: Add `--list` and `--jsonl` to the preparation CLI, reuse runtime cache validation, add city-code filtering, and document the read-only behavior in both READMEs and the specification/design references.
  - Rationale: The implementation keeps normal download behavior unchanged while exposing the requested concise inventory view and detailed machine-readable view. Validation prevents incomplete or malformed caches from appearing in the listing.
  - Result: The focused PLATEAU tests (18) and the full test suite (1287) pass; ruff and `git diff --check` also pass.
