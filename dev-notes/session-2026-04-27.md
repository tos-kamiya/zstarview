# Session 2026-04-27

Scope: Compare earth guide latitude rendering with celestial equator/ecliptic rendering and investigate fullscreen jagged lines.

- Topic: Celestial reference line sampling
  - Decision: Increase celestial equator and ecliptic sampling from 5 degree steps to 1 degree steps.
  - Rationale: The reference-line renderer feeds precomputed alt/az points directly into `drawPolyline()`, so coarse sampling shows up as visible kinks when the window is large. Earth guide outlines already use much denser, projection-aware subdivision, so the two systems differed materially in smoothness.
- Topic: Celestial reference line adaptive subdivision
  - Decision: Move equator/ecliptic smoothing into the renderer and subdivide by screen-space error instead of fixed angular spacing.
  - Rationale: Screen-space error is the right trigger because the same angular segment occupies more pixels as the window grows. The first implementation kept the error check in normalized coordinates, which did not actually scale with window size; switching the error metric to screen coordinates fixed that.
