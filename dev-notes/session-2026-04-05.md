# Session 2026-04-05

- Scope: Adjust day-theme text readability.

- Topic: Day theme outline width
  - Decision: Add a theme-aware text outline width and increase the `day` preset from the default `3.0` to `3.6`.
  - Rationale: The day palette needs a slightly stronger outline to keep labels legible against brighter backgrounds, and a shared width helper keeps label rendering consistent across modules.

- Topic: White theme outline width
  - Decision: Increase the `white` preset outline width from the default `3.0` to `3.6` for both normal text and the status line.
  - Rationale: The white theme uses a similarly bright background palette, so matching the day-theme outline width improves readability and keeps the bright themes visually consistent.

- Topic: Splash background opacity by theme
  - Decision: Make the splash background alpha vary by visual preset using the average alpha of the main window's themed radial background stops.
  - Rationale: The splash already changes color by theme, and deriving alpha from the main window background keeps the startup surface aligned with the app's actual theme translucency instead of relying on hand-tuned opacity values.

- Topic: Theme style consolidation
  - Decision: Introduce a shared `ThemeStyle` data structure that owns normal text, status-line text, window background, and splash background settings for each preset.
  - Rationale: Theme color and alpha values had been split across multiple modules. Consolidating them in one place lets both the main renderer and the splash screen reference the same source of truth and makes future tuning less error-prone.
