- Scope: Verify whether Voyager 1/2 search results and the always-on cross marker use different position sources or cached Horizons data.
- Topic: Voyager 1/2 search position mismatch
  - Decision: The search dialog computes Voyager 1/2 positions on demand from JPL Horizons at the current target time, while the always-on persistent marker reuses the last resolved `alt/az` in memory and only refreshes on the JPL timer path.
  - Rationale: The search callback goes through `search_jpl_targets(..., target_time_utc=self._target_time_utc())`, whereas the persistent overlay is drawn from `state.persistent_search_target` and refreshed through `JplSmallBodyController` / hourly scheduling only when the target is treated as a JPL small body. The persistent overlay is not reading a separate file cache, but it is still stale relative to a fresh search.
- Topic: Align JPL body refresh behavior
  - Decision: Treat `jpl_body` persistent markers the same as `jpl_small_body` markers and schedule the hourly refresh for both.
  - Rationale: Voyager 1/2 are resolved through the JPL search path as `jpl_body` targets, so leaving them out of the periodic refresh path makes the persistent marker drift from the search result. The update keeps the marker in sync with the same Horizons-based resolution path used by search.
