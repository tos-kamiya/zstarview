# Session 2026-04-22

- Topic: Cloud stripe density scaling
  - Decision: Treat `--cloud-stripe COUNT` as the stripe density for the default 600x600 render buffer, and scale the effective stripe count with the actual buffer size during rendering.
  - Rationale: This keeps the default appearance unchanged at the normal window size while making larger render buffers denser instead of preserving a fixed absolute stripe count.
  - Alternatives Considered: Keep the count fixed and only document it as a default; rejected because it does not satisfy the requested size-dependent density.

- Topic: Cloud density anchored to star render surface
  - Decision: Re-anchor cloud stripe density to the star layer's downsampled render surface size instead of the raw viewport size.
  - Rationale: The star layer already shrinks on larger windows, so using the same reduced surface keeps the cloud hatch granularity aligned with the actual star rendering pipeline.
  - Alternatives Considered: Continue scaling against the viewport/client rect; rejected because it diverges from the star layer's effective pixel density.

- Topic: Symmetric cloud stripe expansion
  - Decision: For the width-based cloud stripe mode, expand each stripe symmetrically around the baseline and double the stripe spacing by using a doubled period.
  - Rationale: This makes the band grow to both the upper-right and lower-left instead of only one side, while preserving the previous overall density by spacing the stripe centers farther apart.
  - Alternatives Considered: Mirror only the drawn pixels without changing the period; rejected because it makes the stripes look too dense.

- Summary
  - Updated cloud stripe rendering to scale the effective count with buffer size.
  - Updated CLI help, README, and specification text to describe `COUNT` as density.
  - Switched the density reference from the viewport to the star layer's reduced render surface.
  - Made width-mode cloud stripes symmetric about the baseline and doubled the spacing between stripe centers.
