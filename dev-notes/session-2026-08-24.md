# Session 2026-08-24

Scope: 調査 — 恒星画像で地平線下の星が描画される経路とFOVフィルタリング。

## Investigation

- 恒星の座標変換、可視判定、描画前フィルタリングの実装を確認する。

## Findings

- `astro.calculate_visible_stars()` は赤道座標をalt/azへ変換した後、通常の
  `scenic_view_scoped`では`is_in_fov_vectorized()`だけを適用し、altitude >= 0
  の地平線判定をしていない。
- `render.stars`側も同じcontent FOV判定を行うだけで、地平線下を除外していない。
- 既定の`content_fov_deg=115`では、天頂中心の場合でも高度-25度まで角距離条件に
  入り得る。Atlasの`positional_static`では計算時のFOVフィルタ自体も無効になる。
- 矢印キーのviewport interactionでは`render_view_center`を更新するたびに
  `_update_viewport_interaction_stars()`が新しい中心で恒星を再計算する。ここで
  `scenic_view_scoped`のFOV選別が働くため、カメラ移動中の恒星集合が中心位置に
  依存して変化し、空の一部が欠けて見える可能性がある。

## Implementation

- 恒星のデータ生成、通常/fast描画、明るい星の下地、恒星ラベルからFOV選別を
  除去し、投影後の画面クリッピングに一本化した。
- 関連テスト15件とruffは成功した。全体pytestは1615 passedだが、既存の
  `test_label_layer.py`と`test_window_render_context.py`が、今回の変更と無関係な
  `asterism_*`/`asterism_opacity`属性不足で失敗した。

## Follow-up: discrete celestial positions

- 恒星の補間メッシュ生成を無効化し、恒星は計算済みスナップショット位置で
  更新時まで静止させる。
- 補間メッシュに追随していたアステリズム、恒星twinkle位置の変換も無効化した。
- twinkleの2秒tick、マウスホバーの更新、太陽系天体の2秒表示tickは変更しない。
- 補間用のpresent-frame cache bucketを削除した。
- 関連46テストとruffは成功した。

## Investigation: 4K mouse-hover latency

- Topic: 4K最大化時のマウスホバー処理経路
  - Decision: 現時点では修正を行わず、全面再描画とホバー対象探索を主要な
    ボトルネック候補として切り分けた。
  - Rationale: `SkyWindowClientWidget.mouseMoveEvent()` は各mouse-moveで
    `_handle_client_mouse_move()`から`request_client_update()`を呼び、dirty regionを
    限定せずclient全体の`paintEvent()`を起動する。paint側はキャッシュ済みの通常
    フレームを利用するが、4K完成画像の全面blit、twinkle/planet/HUDの可変レイヤー
    描画、恒星/DSO/衛星/台風のhover探索をUI threadで毎回実行する。
  - Alternatives Considered: 基本シーンの再生成が原因という仮説は、通常フレームが
    mouse位置をcache keyに含めず再利用されるため主因から除外した。
- Topic: コストの簡易分離計測
  - Decision: 既定Vmag 7相当の14,117星で恒星hover探索は平均3.641 ms/call、
    3840x2160 ARGB32 QImage間blitは平均4.419 ms/callだった。両者だけで約8.1 ms/event
    となり、実ウィンドウへの転送と可変レイヤー描画を含める前から120 Hz入力の
    8.33 ms budgetにほぼ達する。
  - Rationale: 同一環境のoffscreen QPainterによる30回/100回の平均。無制限の
    535,116星ではhover探索が116.477 ms/callまで増え、探索が全恒星数に比例する
    ことも確認した。
- Topic: 追加の増幅要因
  - Decision: 衛星データが存在する場合、hover探索はmouse-moveごとに
    `project_satellite_records()`を呼び、Skyfield timescale/observer/satelliteを
    再構築して全レコードのalt/azを再計算するため、構成依存で主要因になり得る。
    DSO表示時も有効DSOごとに48点ellipseを再生成する。方位マーカー上では既定の
    `sky_disc_altaz_rings_hover=altaz`によりgrid全体も可変レイヤーへ追加描画される。

## Summary

- コード変更は行わず、調査結果のみを記録した。
- 主要因はmouse-moveごとの4K client全面再paint。恒星hover全件走査が定常的な
  副因で、衛星投影、DSO形状判定、方位gridは設定・位置依存の増幅要因。

## Follow-up: coalesced hover repaint

- Topic: mouse-moveと4K全面再描画の分離
  - Decision: mouse-moveでは最新座標だけを保存し、single-shot timerで33 ms以内の
    連続イベントを1回の再描画へ合流する。client leaveはtimerを停止し、hover表示を
    即時消去するため従来どおり直ちに再描画する。
  - Rationale: hover応答を約30 fpsに保ちながら、高polling-rate mouseの各イベントが
    4K全面blitとhover探索を発生させる経路を断つ。既存のpresent/base frame cacheや
    hover描画内容は変更しないため、変更範囲と回帰リスクを入力スケジューリングに
    限定できる。
  - Alternatives Considered: hover対象が変わった場合だけ再描画する方式は、対象判定
    自体に恒星全件走査や衛星投影が含まれるため、今回の主要なUI thread負荷を
    mouse-move側へ移すだけになるので採用しなかった。

## Final summary

- mouse hover repaintを最大約30 fpsへ合流した。
- 入力テスト13件、変更したsourceのruff、compileall、diff checkに成功した。
- pytest初回実行はdisplay未指定でQtがabortしたため、`QT_QPA_PLATFORM=offscreen`を
  指定して再実行した。

## Follow-up: Diffuse sky artificial-light attenuation

- Topic: Diffuse skyと人工照明の強度関係
  - Decision: Diffuse skyの設定opacityを最大値とし、night lightと同じ太陽高度係数を
    基本カーブに使う。人工照明が有効な場合は夕方側を40%へ抑え、下方南中後の活動量
    低下に反比例して明け方側で100%へ戻す。night light、road night lights、建物
    屋根面のいずれも描画されない場合はこの減光を適用しない。
  - Rationale: 人工照明とDiffuse skyの合計を一定にするのではなく、人工照明が強い
    時間帯にDiffuse skyの色が全体的に弱く見え、人工照明が弱まる明け方には設定値を
    最大限使うという意図を表現できる。
  - Alternatives Considered: night lightの有効設定だけを見る方式は、road lightsや
    建物屋根面の人工照明、およびデータ未取得で実際には描画されない状態を反映しない
    ため採用しなかった。ridge glowは自然光として減光判定から除外した。
  - Compatibility: 旧Diffuse sky係数を共有していたsky discのアンビエント色は専用の
    `-18`度から`-9`度の係数へ分離し、今回の変更対象に含めず従来挙動を保った。
  - Validation: 関連するnight light、overlay、sky discテスト105件、変更sourceの
    ruff、compileall、`git diff --check`に成功した。既存のstar importを使うoverlay
    テストは既知の`F403`/`F405`だけ除外してruffを実行した。

- Topic: Diffuse skyの既定opacity
  - Decision: GaiaとAKARIで共有する既定値を`0.15`から`0.30`へ引き上げ、CLI、GUI、
    描画style、ユーザー向け文書のfallbackを揃える。
  - Rationale: 人工照明が強い夕方側では40%の減光が適用されるため、既定値`0.30`でも
    実効opacityは`0.12`となり、明け方側では最大値を使ってDiffuse skyを見やすくできる。
