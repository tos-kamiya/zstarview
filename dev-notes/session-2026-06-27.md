## Decision Log
- Topic: Thin asterism lines
  - Decision: Reduced the active asterism stroke widths from `2.6` to `2.0` for the dim pass and from `3.2` to `2.2` for the hover pass. Also matched the DSO hover stroke to `2.2`.
  - Rationale: The overlay read heavier than the other sky layers, so a smaller cosmetic pen width keeps asterisms readable without overpowering nearby drawing elements. Rounded values keep the change easy to reason about and maintain.

## Addendum
- Topic: GUI screen update and cache documentation
  - Decision: Added a dedicated design note at `docs/design/gui-screen-update-and-cache.md` and linked it from the design index.
  - Rationale: The runtime doc already covers the update loop at a high level, but the GUI cache layers and invalidation points are easier to explain in a focused document that maps directly to `window_updates.py`, `window_render.py`, and `composite.py`.
- Topic: Simplified redraw policy and optional atomic publish
  - Decision: Documented a simplified redraw policy that limits frame-cache-triggering updates to user actions, view/resize changes, and 1-minute refreshes, while keeping aircraft/satellite updates separate. Also added an optional atomic-publish note for cases where the current generation can be published as a single input set without conflicting with the simplification.
  - Rationale: Reducing the number of redraw triggers should shrink the space for ordering bugs during view changes. Atomic publication is useful only if it does not add back the same complexity, so it is explicitly subordinate to the simplification.
- Topic: Search and hover overlay classification
  - Decision: Classified search targets, mouse hover, labels, and HUD as a separate immediate UI overlay layer rather than a 2-second refresh layer.
  - Rationale: These elements must track mouse and selection state immediately, so they should stay tied to interaction-driven repaints instead of the short-lived aircraft/satellite refresh cadence.
