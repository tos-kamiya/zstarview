# Session 2026-05-17

- Scope: Inspect how sea-surface `.tiff` tiles are stored in memory.
- Summary: Sea-mask GeoTIFFs are not retained as full raster payloads in memory.
  The code opens each tile with `rasterio`, reads only the needed window or
  samples, converts the result into boolean flags or `WaterOverlayPoint`
  tuples, and caches only those derived point sets plus stats in controller
  state.
- Summary: Added `scripts/find_water_tile_intersections.py` and

  points whose surrounding tiles are all `.tif` across 125m/250m/500m roots.
  Verified the current dataset yields 5 shared intersections with `pytest` and
  `ruff check`.
- Summary: Moved the runnable sample to
  `dev-samples/find_water_tile_intersections.py` so it sits with the other
  exploratory scripts in this repository.
- Summary: Added `dev-samples/README.md` as a small index for exploratory

- Summary: Added `dev-samples/debug_water_surface_probe.py` as a temporary
  probe script. It prints direct tile lookups and ray-scan summaries around a

  in the GUI.
- Summary: Added `dev-samples/debug_water_controller_probe.py` to show the
  controller's distance bands. For `@0,135` with 5 m eye height, the probe
  showed that the controller routes 0-2 km to 125m, 2-6 km to 250m, and only
  6-8.98 km to 500m. The 125m/250m tiles are 0 at this location while 500m
  tiles are 1, which explains the 0-dot GUI result.
- Summary: Corrected the water-mask tile lookup to use resolution-specific
  grids: 125m = 16x32, 250m = 8x16, and 500m = 4x8. This fixed the bug where
  the code had been using the coarse 45-degree grid for all roots, causing the
  finer bands to sample the wrong tiles. Added tests to lock in the per-root
  key mapping and verified `tests/test_water_mask_interface.py` plus
  `ruff check` pass.
