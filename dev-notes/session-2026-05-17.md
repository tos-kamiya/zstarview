# Session 2026-05-17

- Scope: Inspect how sea-surface `.tiff` tiles are stored in memory.
- Summary: Sea-mask GeoTIFFs are not retained as full raster payloads in memory.
  The code opens each tile with `rasterio`, reads only the needed window or
  samples, converts the result into boolean flags or `WaterOverlayPoint`
  tuples, and caches only those derived point sets plus stats in controller
  state.

- Topic: Observation height option naming
  - Decision: Reframed the CLI around `--height-add-m` as the additive height
    above the active observation base, with `--use-building-top` switching the
    base to a nearby building top when available. Kept `--observer-height-m`
    as the compatibility alias.
  - Rationale: This separates "base selection" from "extra height", so the GUI
    and docs can explain the final elevation as ground plus structure plus the
    additive height without overloading `elevation` or `eye height`.
- Topic: Compact height summary
  - Decision: Switched the location summary to a compact `Height: ground ...,
    [building ... , ]add ...` form and omit the building segment when it is 0.
  - Rationale: This keeps the summary short enough for the main window and
    export overlays while still preserving the full additive-height breakdown.
- Topic: Explicit height split
  - Decision: Carried `height_add_m` as an explicit field on location and
    viewer data, while keeping `observer_height_m` as the total above-ground
    height used by the physics and rendering code.
  - Rationale: The display-time deduction path was too brittle and could
    double-count tower/building heights. Keeping the additive height and
    structural height separate removes the ambiguity and gives the splash,
    GUI, and cache keys a single source of truth.
