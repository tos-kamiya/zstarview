- Topic: Lower-cost alternative to sky-disc grid coloring
  - Decision: Prefer a smooth sky disc plus sparse Alt 10-degree ring overlays, with the rings rendered as transparent holes or very thin low-alpha strokes rather than cell coloring.
  - Rationale: This keeps the visual cue people want while avoiding the denser grid-color workflow. It also preserves the existing smooth-disc look as the base layer, so the change can be isolated to an overlay path instead of reworking the full sky-disc color sampler.
  - Note: True transparent lines only reveal the desktop when the window/background stack is actually transparent; on opaque themes they will reveal the theme background instead.
- Topic: Sky-disc grid replacement implementation
  - Decision: Removed the visible grid fill mode, added `--sky-disc-alt-rings`, and routed the ring overlay through the final render pass so it can punch through transparent themes or fall back to a subtle contrast stroke.
  - Rationale: The overlay path is cheaper than per-cell color quantization and keeps the base smooth disc reusable across themes.
  - Verification: Targeted pytest runs passed, including CLI arg parsing, terrain/UI option normalization, sky-disc ring overlay behavior, and export-image argument wiring.
- Topic: Alt-ring appearance simplification
  - Decision: Standardize Alt rings as transparent cutouts for every theme; drop the dark-theme stroke fallback.
  - Rationale: The fallback stroke was visually noisy in dark themes and made the new option feel inconsistent. A single cutout behavior is easier to reason about and matches the original transparency-oriented idea.
- Topic: Alt-ring background matching

  - Decision: Move Alt-ring rendering into the sky-disc compositing step and attenuate the sky-disc alpha along the rings instead of drawing a colored overlay stroke.
  - Rationale: A partial alpha reduction keeps the cue tied to the sky layer itself while avoiding the hard background contrast that a full cutout produces on bright themes.
- Topic: Alt-ring shared constants

  - Rationale: This removes duplicated literals and keeps the two rendering paths aligned when the ring appearance is tuned.

  - Decision: Replace the alpha-reduction approach with a subtle brightness highlight over both the sky disc and the background.
  - Rationale: The cutout-style treatment was visually hard to tune across themes. A low-alpha highlight keeps the ring cue visible without creating a mismatched dark band or an apparent hole in the background.
  - Verification: Updated the CLI help, README, specification, design notes, and the renderer tests to assert brightness increase instead of alpha reduction.
