# Session 2026-06-10

Scope: Revisit the night-lights overlay design; specifically, whether and how to reintroduce the earlier thick-line overpainting style instead of the current polygon-based fill.

- Topic: Night-light renderer shape strategy
  - Decision: Keep the current polygon band as the base fill, but add a multi-pass thick-line stack along the lower edge so the glow is visually anchored to the ridge line instead of centered in the band.
  - Rationale: The polygon still provides a stable filled band, while the lower-edge line stack restores the layered glow and makes the ridge-side attachment read more clearly. Reusing the existing sample ordering, gap splitting, and distance-based band assignment avoids reopening the profile-generation logic. The added line stack is rendered in red to make the separation obvious while the base fill remains unchanged. The stroke centerline is offset toward the guide side so the lower edge sits on the current ring's ridge line, not the previous ring.
  - Validation: Ran `uv run -p .venv/bin/python pytest tests/test_night_lights.py -q` and `uv run -p .venv/bin/python ruff check src/zstarview/render/night_lights.py tests/test_night_lights.py`.

- Topic: Night-light ridge debug toggle
  - Decision: Temporarily disable ridge polygon filling with a local debug flag so the red line stack can be compared in isolation.
  - Rationale: The comparison is easier when the filled band is removed from the frame. Keeping the toggle local and default-off makes it easy to restore the original fill after inspection.

- Topic: Terrain secondary-ridge debug toggle
  - Decision: Temporarily disable terrain secondary-ridge drawing with a local debug flag so the night-light overlay can be compared without the blue ridge layer.
  - Rationale: The blue ridge layer was obscuring the comparison, so turning it off isolates the night-light result. Keeping the toggle local and default-off makes it easy to revert once the screenshots are compared.

- Topic: Night-light low-strength debug color
  - Decision: Render night-light fragments that fall below the brightness threshold in a separate debug color instead of skipping them outright.
  - Rationale: This makes it possible to see where the profile drops below the threshold while keeping the normal threshold logic intact. The behavior is controlled by a local debug flag so it can be reverted without changing the main render path.

- Topic: Night-light single-layer debug mode
  - Decision: Add a local layer-index debug toggle so only one night-light ring is shown at a time, starting from the innermost ring.
  - Rationale: This reduces visual noise while investigating missing segments and makes it easy to step outward by changing a single index constant.
