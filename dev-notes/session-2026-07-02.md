# Session 2026-07-02

Scope: clarify how zstarview changes the visible sky region when the client-area aspect ratio changes.

- Topic: Document client-area aspect ratio behavior
  - Decision: Added a new specification section stating that `edge_fov_deg` is the projection baseline, `content_fov_deg` is overscan only, and the client-area aspect ratio can change how the sky disc is clipped and positioned.
  - Rationale: The behavior was implemented but not explicitly documented. Making the `edge_fov_deg` vs `content_fov_deg` split and the wide/tall layout rule explicit reduces ambiguity for users and future maintenance.
- Topic: Restore simplified-view terrain horizon line
  - Decision: Re-enabled the main terrain horizon line in simplified view only, using the fast-mode-style thin rendering path, while keeping it omitted in normal view.
  - Rationale: The earlier behavior expected by the simplified view is to preserve the primary terrain horizon as a lightweight orientation cue. Secondary ridges, water, and urban outline remain suppressed to keep the simplified mode sparse.
- Topic: Considered moving terrain-adjacent overlays into compositor
  - Decision: Kept the current split unchanged. Secondary ridges, water, and urban outline remain on the frame-cache side rather than being folded into the sky/cloud compositor.
  - Rationale: Re-enabling the main terrain horizon in simplified view reduced the pressure to widen the compositor boundary, but not enough to justify a cache-role change for the adjacent overlays. The current split still matches their separate invalidation and visibility rules.
