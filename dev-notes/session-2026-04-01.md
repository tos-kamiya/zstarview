- Topic: Accept comma-separated copied coordinates in CLI location input
  - Decision: Expanded direct coordinate parsing so CLI `location` accepts `lat, lon` and `@lat, lon` in addition to the existing `lat;lon` and `@lat,lon` forms.
  - Rationale: Google Maps copies plain `lat, lon` strings from the right-click menu. Accepting that format avoids forcing users to rewrite pasted coordinates while keeping the parser strict to numeric two-field input.
  - Alternatives Considered: Supporting only `@lat, lon` would not cover the actual copied Google Maps string, and requiring semicolons would keep the current paste friction.
