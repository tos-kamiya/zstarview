# Session 2026-04-18

Scope: Investigate whether the app can display dwarf planets as satellite-sized cross markers, and determine the data source / accuracy tradeoff before implementation.

- Topic: Dwarf planet rendering
  - Decision: Current solar-system ephemeris data covers Pluto, but not other dwarf planets in a way that can be confirmed locally.
  - Rationale: The existing `de442s.bsp` path supports the major planets and Pluto barycenter. Adding Ceres / Eris / Haumea / Makemake would require either another data source or an approximate orbital model.
  - Status: Awaiting user confirmation on which bodies to show and whether approximate positions are acceptable.

- Topic: JPL Horizons sample sequence
  - Decision: Implement the prototype in the requested order, starting with an observer-ephemeris sample that reuses the existing `zstarview.satellites.fetch` Horizons helpers.
  - Rationale: The repository already has working lookup and observer CSV helpers for Horizons. Reusing them keeps the sample aligned with the eventual app code and avoids duplicate API plumbing.
  - Status: In progress.

- Topic: Horizons sample completion
  - Decision: Added `dev-samples/jpl_horizons_observer.py` for a single alt/az sample and `dev-samples/jpl_horizons_trajectory.py` for a 1-hour repeated-sample trajectory.
  - Rationale: The observer sample proved the lookup-to-ephemeris flow works once the small-body command is sent as `DES=<spkid>;`. The trajectory sample keeps the implementation simple by repeating the single-time query at fixed intervals.
  - Validation: Both scripts compiled cleanly and returned live `Ceres` results from Horizons for a Tokyo observer location.
