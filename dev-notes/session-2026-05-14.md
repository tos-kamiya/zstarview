# Session 2026-05-14

- Scope: urban outline performance discussion and potential pruning strategy.

- Topic: 近距離優先で建物アウトライン数を打ち切る案
  - Decision: 方針としては妥当。ただし、打ち切り条件は単純な建物件数よりも、距離順に並べたうえでの「描画コスト予算」や「投影後の輪郭件数」を使う方が安全。
  - Rationale: 現行実装は `compute_urban_outlines()` で各建物を投影・サンプリングしており、`src/zstarview/data/urban_outline_from_buildings.py` 側で早めに止めるほど効果が大きい。一方で、単純な件数上限だけだと、複雑な多角形や近距離の高密度街区で効き方がぶれやすい。

- Topic: terrain horizon の DEM 地盤高の保持
  - Decision: `terrain horizon` の表示ON/OFFとは独立して、DEM 取得済みの `ground_elevation_m` は保持する。OFF 時はレイヤー表示だけ止め、保持済み地盤高は water overlay と将来の再描画に残す。
  - Rationale: 観測地点の緯度経度と observer height は起動後に固定でよく、DEM 由来の地盤高だけを遅延確定値として扱える。これにより、初回DEM取得後は表示切替で基準高度が巻き戻らず、キャッシュキーや補助レイヤーの再利用も安定する。

- Topic: 起動中の DEM 完了待ち
  - Decision: スプラッシュ相当の startup overlay は、初期 sky データに加えて DEM の取得完了または失敗まで保持する。
  - Rationale: 初回起動時に `ground_elevation_m` を確定させてから通常表示へ移行すれば、以後の建物アウトラインや水面補助レイヤーの基準が安定する。実装上は `viewer.py` の起動ゲートで `initial_data_loaded` と terrain の完了をまとめて扱う。

- Topic: 都市アウトラインのベクトル化中間表現
  - Decision: raw footprint は `lon/lat` のまま保持し、描画前の中間表現として observer-centric の `numpy` 配列または同等のベクトル化配列を許可する。`view_center` は再生成条件ではなく再投影条件として扱う。
  - Rationale: 建物は時刻で動かず、`lat/lon/observer_height_m/ground_elevation_m` が不変なら観測者基準の配列は再利用できる。`view_center` だけが変わる場面では、地理座標からの再計算ではなく回転と最終投影だけを行う方が描画に向く。

- Topic: 都市アウトラインの実装境界
  - Decision: `compute_urban_outlines()` は選別と topocentric 中間表現の生成を担い、`resolve_urban_outline_layer_for_viewer()` と描画層は最終投影のみを担う。
  - Rationale: raw / observer-centric / render の3層に分けると、`view_center` 変更時に geospatial 再計算を避けられる。キャッシュキーも「地理入力」と「画面向き」を分離して定義でき、DEM 取得済み地盤高の保持とも整合する。

- Topic: intermittent PySide6 segmentation fault triage
  - Decision: Harden the NumPy-to-Qt image boundary by forcing contiguous `uint8` RGBA input in `src/zstarview/render/qt_image.py`, and add a regression test for non-contiguous views.
  - Rationale: The current runtime path already keeps painting on the GUI thread and uses `QImage` rather than `QPixmap` outside the splash screen, so the most suspicious remaining boundary is the conversion helper that feeds Qt image constructors from NumPy buffers. Making the helper validate shape/dtype and copy non-contiguous input removes a class of lifetime/stride issues that can show up as rare crashes.
- Topic: splash-screen sky rendering suppression
  - Decision: Skip frame rendering entirely while the startup log overlay is visible, so the initial sky frame is not drawn behind the splash state.
  - Rationale: `--use-building-top` and the startup bootstrap still resolve observer data before the first render, but the startup overlay should remain a true non-rendering phase. Early-returning before `QPainter` creation keeps the UI from drawing the sky until the splash is dismissed.
- Topic: export-image water surface support
  - Decision: Added an export-image water fetch path and passed the sampled points into `RenderSceneData.water_overlay_points`, so `zstarview-export-image` now draws the same water overlay layer as the GUI path when `--water-surface-opacity` is enabled.
  - Rationale: the CLI already exposed the shared water opacity option, and the render pipeline already knew how to draw water points; export-image was only missing the data-fetch step.
  - Validation: `uv run -p .venv/bin/python pytest tests/test_cli_export_image_args.py tests/test_export_image_layer_gating.py` and `uv run -p .venv/bin/python pytest tests/test_water_overlay.py` both passed; `uv run -p .venv/bin/python ruff check src/zstarview/cli/export_image.py tests/test_cli_export_image_args.py tests/test_export_image_layer_gating.py` passed.
