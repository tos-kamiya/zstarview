# Session 2026-05-14

- Scope: urban outline performance discussion and potential pruning strategy.

- Topic: 近距離優先で建物アウトライン数を打ち切る案
  - Decision: 方針としては妥当。ただし、打ち切り条件は単純な建物件数よりも、距離順に並べたうえでの「描画コスト予算」や「投影後の輪郭件数」を使う方が安全。
  - Rationale: 現行実装は `compute_urban_outlines()` で各建物を投影・サンプリングしており、`src/zstarview/data/urban_outline_from_buildings.py` 側で早めに止めるほど効果が大きい。一方で、単純な件数上限だけだと、複雑な多角形や近距離の高密度街区で効き方がぶれやすい。

- Topic: terrain horizon の DEM 地盤高の保持
  - Decision: `terrain horizon` の表示ON/OFFとは独立して、DEM 取得済みの `ground_elevation_m` は保持する。OFF 時はレイヤー表示だけ止め、保持済み地盤高は water overlay と将来の再描画に残す。
  - Rationale: 観測地点の緯度経度と observer height は起動後に固定でよく、DEM 由来の地盤高だけを遅延確定値として扱える。これにより、初回DEM取得後は表示切替で基準高度が巻き戻らず、キャッシュキーや補助レイヤーの再利用も安定する。

- Topic: 起動中の DEM 完了待ち
  - Decision: スプラッシュ相当の startup overlay は、初期 sky データに加えて DEM の取得完了または失敗まで保持する。
  - Rationale: 初回起動時に `ground_elevation_m` を確定させてから通常表示へ移行すれば、以後の建物アウトラインや水面補助レイヤーの基準が安定する。実装上は `viewer.py` の起動ゲートで `initial_data_loaded` と terrain の完了をまとめて扱う。
