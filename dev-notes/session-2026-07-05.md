# Session 2026-07-05

Scope: FOV invariant handling for viewer/render projection types.

- Topic: Enforce `content_fov_deg >= edge_fov_deg` across all construction paths
  - Decision: Normalize `ViewerData` and `ViewProjection` in `__post_init__` so `content_fov_deg` is never smaller than `edge_fov_deg`.
  - Rationale: This makes the invariant hold for direct instantiation, GUI-derived objects, and any other internal path that bypasses CLI parsing.
  - Validation: `uv run -p .venv/bin/python pytest tests/test_fov_invariants.py tests/test_gui_composite_halftone.py -q`
  - Validation: `uv run -p .venv/bin/python ruff check src/zstarview/types.py tests/test_fov_invariants.py`

- Topic: Tall-window sky-disc presentation
  - Decision: Use a `ScreenGeometry` rule where tall windows center the disc, let the edge FOV extend beyond the left/right window edges, and linearly adjust the radius between `R = 1` and `R = 1 / 2` so that `height / 2` moves from the edge-FOV radius to the content-FOV radius.
  - Rationale: This preserves a large vertical presentation for near-square tall windows while making the circular crop visually legible in 1:2-and-taller portrait layouts by showing content-FOV exterior regions in the corners.
  - Alternatives Considered: Keeping the old width-limited tall geometry avoids horizontal overflow but hides the circular crop presentation goal.

- Topic: Implement tall-window sky-disc radius rule
  - Decision: Extend `get_screen_geometry()` with `edge_fov_deg` and `content_fov_deg`, keep the existing wide-window geometry, and replace the tall-window width-limited radius with the documented height-based interpolation.
  - Rationale: The geometry function is the single shared source for GUI, export, worker payload validation, and hover lookup. Passing FOV values from `ViewerData` keeps all render paths consistent while preserving defaults for tests and helper scripts.
  - Validation: `uv run -p .venv/bin/python pytest tests/test_sky_disc_viewport_and_ground_tint.py`
  - Validation: `uv run -p .venv/bin/python pytest tests/test_window_render_sync.py tests/test_fov_invariants.py`
  - Validation: `uv run -p .venv/bin/python ruff check src/zstarview/render/geometry.py src/zstarview/gui/window_render.py src/zstarview/gui/window_updates.py src/zstarview/gui/window.py src/zstarview/cli/export_image.py tests/test_sky_disc_viewport_and_ground_tint.py`

- Topic: Tall-window interpolation threshold tuning
  - Decision: Change the tall-window content-fit threshold from `R = 3 / 4` to `R = 1 / 2`.
  - Rationale: Manual GUI validation showed the corner gaps became larger than intended at 3:4. Moving the threshold to 1:2 keeps the edge-FOV-radius presentation over more portrait window shapes and delays the content-FOV fit until a much taller aspect ratio.
