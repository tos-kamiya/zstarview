- Topic: Diagnose OSM road-data failure in scheduled export
  - Decision: Interpret the reported `HTTP 504` as an Overpass API request
    failure, not an empty road dataset.
  - Rationale: `fetch_road_night_lights()` converts `urllib.error.HTTPError`
    into `RuntimeError("HTTP {code}")`. An empty successful Overpass payload
    (`elements: []`) is accepted by `parse_road_night_lights_payload()` and
    produces an empty snapshot; it does not enter the export layer failure
    path. The cache lookup also preceded the request, so this run had no valid
    scope cache for the requested location/radius.
  - Validation: Reviewed `src/zstarview/road_night_lights.py` and
    `src/zstarview/cli/export_image.py` against the supplied log.

- Topic: Live Overpass check for the Mt. Fuji export location
  - Decision: Confirm that the area does contain matching OSM road ways; the
    failure is caused by the geometry response timing out at the public
    Overpass endpoint.
  - Rationale: The exact 10 km `out tags geom` query returned HTTP 504 with
    an Overpass dispatcher timeout message. A 1 km count query returned 124
    matching highway ways, and a 10 km count query returned 608 matching
    ways. Thus the empty-result explanation is ruled out.
  - Validation: Queried `https://overpass-api.de/api/interpreter` on

    filter.

- Topic: Fallback after an oversized Overpass road request
  - Decision: Retry the default 10 km request once at 5 km when the request
    returns HTTP 504 or a generic road-request failure, then cache the result
    under the 5 km scope key.
  - Rationale: A smaller geometry response can succeed when the 10 km query
    is rejected by Overpass, while limiting the retry to one smaller radius
    avoids repeated load and preserves the existing failure behavior when the
    fallback also fails.

- Topic: Document a 30-day road-cache policy

    after failed refreshes and the existing 10 km to 5 km fallback sequence.
  - Rationale: OSM road geometry changes continuously, but this visual layer
    does not require navigation-grade freshness. Thirty days aligns the road
    cache policy with the Overture building cache while retaining useful data
    during temporary API outages.

- Topic: fast-mode coastline rendering
  - Decision: Confirmed that the viewport-interaction fast path draws
    `scene.water_overlay_polylines`; coastline tile polylines are included in
    that collection with `water_category="coastline"`.
  - Rationale: `zstarview_pipeline._draw_viewport_interaction_layers()` calls
    `draw_water_overlay_polylines()` even while `viewport_interaction_mode` is
    active. The water-overlay controller loads coastline polylines both for
    cached and freshly built water scopes. The fast-mode flag only selects the
    sparse water-dot sampling path; it does not suppress coastline polylines.
  - Validation: `pytest tests/test_coastline_tiles.py
    tests/test_water_overlay_controller.py tests/test_water_overlay.py` ->
    60 passed.
