- Topic: Add a short option for building-top viewpoints
  - Decision: Add `-B` as an alias for `--use-building-top` to both the main
    and export-image parsers.
  - Rationale: `B` is mnemonic for building and is currently available.

- Topic: fast-mode coastline rendering
  - Decision: Confirmed that the viewport-interaction fast path draws
    `scene.water_overlay_polylines`; coastline tile polylines are included in
    that collection with `water_category="coastline"`.
  - Rationale: `zstarview_pipeline._draw_viewport_interaction_layers()` calls
    `draw_water_overlay_polylines()` even while `viewport_interaction_mode` is
    active. The water-overlay controller loads coastline polylines both for
    cached and freshly built water scopes. The fast-mode flag only selects the
    sparse water-dot sampling path; it does not suppress coastline polylines.
  - Validation: `pytest tests/test_coastline_tiles.py
    tests/test_water_overlay_controller.py tests/test_water_overlay.py` ->
    60 passed.

- Topic: Suppress water boundaries in fast-mode
  - Decision: Keep water dots in fast-mode, but skip all water overlay
    polylines, including coastline and inland-water boundaries. Normal mode
    continues to draw the polylines.
  - Rationale: Fast interaction frames should retain the inexpensive point
    layer without the extra linework.
  - Validation: `pytest tests/test_window_render_overlays.py
    tests/test_coastline_tiles.py tests/test_water_overlay_controller.py` ->
    41 passed.

- Topic: Restore normal-mode water boundaries
  - Decision: Keep polyline drawing enabled in `_draw_terrain_layers()` even
    when its `fast_mode` sampling flag is true. Suppress polylines only in the
    dedicated `_draw_viewport_interaction_layers()` path.
  - Rationale: Normal presentation builds its cached base frame with
    `draw_fast_overlays=False`, which also passed `fast_mode=True` to terrain.
    Using that flag to suppress polylines incorrectly removed boundaries from
    normal-mode cached frames.
  - Validation: The same 41 related tests passed after the correction.

- Topic: Prevent duplicate solar-system bodies in fast-mode
  - Decision: Do not draw the planet layer in the fast-mode cached base image;
    leave it to the final volatile overlay layer, which draws the Sun, Moon,
    and other solar-system bodies once.
  - Rationale: The viewport interaction renderer drew planets unconditionally,
    while `_draw_volatile_overlay_layers()` drew the same dynamic planet layer
    again after compositing the fast base image.
  - Validation: `pytest tests/test_window_render_overlays.py
    tests/test_window_render_context.py` -> 30 passed.
