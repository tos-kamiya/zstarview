- Topic: Night light alpha grid logging
  - Decision: Emit a terminal log line with `logger.info("[INFO] Night light alpha grid computed")` only when the alpha grid is actually built.
  - Rationale: The user wanted the timing signal in the terminal, not in the GUI. Logging from the worker keeps the signal aligned with the actual compute boundary and avoids adding UI-only status plumbing.

- Topic: Night light profile reuse
  - Decision: Pass the cached `night_light_glow_profile` back into the sky worker and reuse it across sky refreshes until terrain context changes.
  - Rationale: The observer position and loaded terrain inputs are stable across many refreshes, so rebuilding the profile every time only adds work. Resetting the cache when terrain changes keeps the profile valid without forcing repeated recomputation.

- Topic: Cache invalidation on terrain changes
  - Decision: Clear the cached night-light profile when terrain horizon data is refreshed or fails.
  - Rationale: The profile depends on the terrain horizon inputs, so a terrain update must invalidate it to keep the rendered glow consistent.
