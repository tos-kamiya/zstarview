# Session 2026-08-26

Scope: Compare Sandwich Harbour reference imagery with zstarview output and tune sky/sea color rendering.

- Topic: Default sky opacity
  - Decision: Raise the default `-S/--sky-opacity` from `0.16` to `0.25`
    across CLI parsing, GUI input defaults, documentation, and regression tests.
  - Rationale: Make the calibrated blue sky more readable without changing
    explicitly supplied `-S` values.

- Topic: Daytime sky colour balance
  - Decision: Reduce the intensity-to-luminance blend from 0.30 to 0.18 and
    set `SUN_RADIANCE_RGB` to `[0.45, 0.625, 1.0]`, midway between the
    previous moderate and strong corrections. Keep the standard
    Rec. 709 luminance weights unchanged.
  - Rationale: The supplied zstarview image at `-S0.5` measured approximately
    RGB (59, 86, 118) in the upper sky, while the reference was approximately
    (3, 49, 111). The simpler change weakens the white-making correction at
    high `-S` values, while the sunlight adjustment reduces the red/green
    cast in the scattered sky radiance itself to approach shot2.

- Topic: Bottom status line overflow
  - Decision: Keep bottom status text on explicit lines only and allow long
    lines to extend beyond the right edge; retain width-based wrapping for
    other HUD text.
  - Rationale: Status text is auxiliary and should remain readable as a
    complete line, while ordinary HUD text still needs to fit the viewport.

Summary: Updated status-line rendering, reservation height calculation,
specification, and regression tests. Targeted rendering tests and source
lint passed; the broader selected test run has one pre-existing test-stub
failure unrelated to this change (`asterism_opacity` is missing).

- Topic: Default cloud opacity
  - Decision: Lower the default cloud opacity from `0.18` to `0.12` in the
    shared runtime constant, regression test, and current CLI/design/user
    documentation.
  - Rationale: Apply the requested softer default while preserving explicit
    `--cloud-opacity` values and historical release notes.

- Topic: Low-resolution cloud compositing
  - Decision: Render regular-viewer clouds at the same internal surface size
    as faint stars, composite them after faint stars, and draw bright stars
    afterward. Scale the halftone minimum grid spacing with the surface scale
    so the enlarged result keeps the window-sized visual density.
  - Rationale: Reduce resize-time cloud cost while allowing clouds to affect
    the sky and faint stars without softening bright stars.
  - Validation: Cloud, CLI, HUD, and overlay tests passed except for the
    pre-existing window-stub failure involving missing `asterism_opacity`.

- Topic: Missing clouds after compositing change
  - Decision: Move the cloud-overlay call into the presentation path, after
    the cached faint-star surface is transformed and before bright stars are
    drawn.
  - Rationale: The normal cached-frame path calls base-scene rendering with
    `draw_stars=False`; the initial placement inside the base-scene star block
    was therefore skipped during actual presentation.
  - Validation: HUD and overlay rendering tests pass with the offscreen Qt
    backend.

- Topic: Cloud shell grid phase regression
  - Decision: Restore the three shell phases `(0.000, 0.000)`,
    `(0.500, 0.500)`, and `(-0.183, 0.683)` in the low-resolution cloud
    overlay path.
  - Rationale: The first overlay implementation rendered every shell with
    phase zero, removing the deliberate shell separation from the previous
    renderer.

- Topic: Default cloud opacity adjustment
  - Decision: Lower the default cloud opacity from `0.12` to `0.09`.
  - Rationale: Apply the requested softer cloud appearance while keeping
    explicitly supplied opacity values unchanged.

- Topic: Cloud surface side padding
  - Decision: Stretch the guarded low-resolution cloud surface directly to
    the viewport, matching the star-surface presentation path, instead of
    preserving aspect ratio with transparent padding.
  - Rationale: The star-surface guard changes the source aspect ratio slightly;
    aspect-preserving scaling introduced transparent gaps at the window sides.
  - Validation: Cloud, HUD, and overlay tests passed; compileall and diff
    checks passed.

- Topic: Cloud interaction latency
  - Decision: Skip transparent pixels while compositing the three cloud-shell
    RGBA layers and cache the completed regular-viewer cloud raster while its
    projection, source, style, tint, opacity, and internal size remain equal.
  - Rationale: Profiling found that full-frame float shell compositing consumed
    about 65 ms of a 113 ms cloud redraw at 1600 x 900. Sparse integer
    compositing reduced complete redraw time from about 94 ms to 75 ms in the
    warm benchmark, while the raster cache removes projection and compositing
    entirely for HUD-only presentation refreshes.
  - Alternatives Considered: A cache alone would not reduce the first redraw
    after a direction change. Integer full-frame compositing preserved output
    but did not improve elapsed time, so the implementation also limits work
    to nontransparent cloud pixels.
  - Validation: 30 cloud rendering tests pass, including float-reference
    output comparison and raster-cache reuse. The broader targeted run passes
    43 tests and retains one pre-existing window-stub failure because
    `asterism_opacity` is absent.
