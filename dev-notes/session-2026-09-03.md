# Session 2026-09-03

Scope: Audit rendering-pipeline function arguments for duplicated data and values
that could be derived by the callee.

- Topic: Rendering argument ownership audit
  - Decision: Treat duplicated frame/scene state and unused compatibility
    parameters as the primary cleanup targets; retain geometry and viewport as
    separate values because they can describe different coordinate spaces.
  - Rationale: `FrameContext` and `RenderSceneData` receive the same `ViewerData`
    and time object in both GUI and export construction. Several lower-level
    functions also receive projection scalars already available from
    `ViewerData`, and `SkyCompositorCache.draw` receives both `sun_altaz` and its
    derivable altitude. Static AST inspection found currently unused parameters
    in active rendering functions, including sky-disc time/timezone, urban
    outline time, old interpolation matrices, twinkle viewport size, hovered
    moon outline mode, and water-dot fast mode.
  - Alternatives Considered: Do not collapse `ScreenGeometry` into the viewport
    or recompute every low-resolution surface size locally. Those values can
    represent scaled/guarded render targets and keeping them explicit prevents
    coordinate-space ambiguity.

## Summary

- Follow-up: remove unused parameters, introduce one canonical frame viewer/time
  owner, then replace compositor scalar bundles with typed projection/scene

- Topic: Process-global runtime state safeguard
  - Decision: Audit and classify mutable module state before reducing renderer
    arguments. Do not replace explicit arguments with implicit globals.
  - Rationale: Active examples include the process-wide star `QImage` cache,
    mutable molecular-cloud source selection, GUI worker-pool singleton,
    ephemeris singleton cache, and a process-wide native-work lock. Constants
    and bounded caches of pure results have different risks and should not be
    removed mechanically.
  - Alternatives Considered: Moving all render inputs into module variables was
    rejected because it would hide dependencies, couple multiple windows and
    exports, and make cache lifetime and tests order-dependent.

- Topic: Mutable rendering globals refactor
  - Decision: Replace mutable diffuse-sky source globals with explicit source to
    asset-path resolution, and move the last-star-image cache into each
    `SkyCompositorCache` instance.
  - Rationale: CLI parsing no longer changes renderer behavior process-wide,
    while GUI windows and headless exports can no longer overwrite one another's
    star image cache. Direct low-level star calls remain valid without caching
    by omitting the explicit cache.
  - Alternatives Considered: The GUI worker pool, ephemeris provider, and heavy
    native-work lock were not folded into this change. They are shared lifecycle
    resources rather than rendering state; changing their ownership requires a
    separate application-services design and controller-construction update.
