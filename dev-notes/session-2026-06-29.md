- Scope: Inspect current specification and implementation for terrain secondary ridge rendering, then propose a change for depth-aware dimming of ridges behind higher-altitude ridges. No implementation yet.
- Topic: Secondary ridge visibility attenuation
  - Decision: Keep the change scoped to the secondary-ridge renderer and document the behavior first; do not alter the main terrain horizon.
  - Rationale: The current spec only says secondary ridges may be shown, while the renderer already tracks a per-azimuth max altitude envelope but does not use it to modulate visible prominence. The appropriate fix is to connect that envelope to segment-level alpha/width handling rather than changing terrain generation.
- Topic: Debug main horizon suppression
  - Decision: Leave the main terrain profile call commented out in `render/pipeline.py` for debugging while introducing the secondary-ridge attenuation change.
  - Rationale: The user wanted to inspect the scene without the main profile, so keeping that path disabled preserves the intended debugging setup while the new secondary-ridge behavior is exercised.
- Topic: Validation
  - Decision: Verified the new secondary-ridge attenuation with targeted pytest and ruff runs.
  - Rationale: The secondary-ridge tests now cover dimming of occluded segments, color blending toward the horizon line, and the updated segment-level drawing counts.
- Topic: Secondary ridge render refinement
  - Decision: Replace smooth alpha-based color blending with a hard 0.1-degree occlusion threshold and merge contiguous same-strength segments into polylines.
  - Rationale: The previous gradual blend changed the ridge color and introduced visible dots at segment joints. Hard classification keeps the ridge hue stable while still making hidden segments weaker, and polyline runs preserve continuity.
- Topic: Secondary ridge color
  - Decision: Use the same beige tone as the terrain horizon for secondary ridges.
  - Rationale: The user wanted the ridge color to match the fast-mode terrain appearance, so using the horizon color keeps the overlay visually coherent while leaving the visibility attenuation intact.
- Topic: Secondary ridge cleanup
  - Decision: Remove the temporary debug comment, localize ridge-only tuning values, delete unused seam helpers, and rename the remaining ridge-run helper/tests for clarity.
  - Rationale: The requested fixed behavior is now stable, so the implementation should no longer carry debug scaffolding or ridge-specific global constants that are only used in one place.

- Topic: Cloud render request deduplication
  - Decision: Suppress duplicate in-flight cloud source/render requests when the request signature matches the one already running or already queued.
  - Rationale: The scheduler can tick while a long Himawari projection is still running, which was incrementing `request_id` and replacing pending work even when the request inputs had not changed.
  - Notes: The dedupe key covers source slot + observer location for source fetches, and source key + view parameters for render updates.

- Topic: Sky worker request behavior
  - Decision: Keep the sky worker's existing single-flight behavior; add a regression test that verifies it refuses a second update while already running.
  - Rationale: Sky calculations already serialize by `_running`, so they do not create the same burst of duplicate in-flight requests as cloud rendering.
