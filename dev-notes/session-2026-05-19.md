- Topic: satellite / aircraft の 2 秒再投影が busy 時に止まる問題の修正
  - Decision: scheduler の busy 判定で projection 更新まで早期 return しないようにし、背景更新の開始だけを抑制する一方、`reproject_*` は idle ワークとして継続実行するようにした。
  - Rationale: 取得済みデータの再投影は重いバックグラウンド fetch とは独立して更新できるため、busy で丸ごと止めると 2 秒周期が失われる。今回の症状は取得時に計算した座標の流用ではなく、scheduler 側の早期 return が原因だった。
  - Validation: `uv run -p .venv/bin/python pytest tests/test_scheduler_idle.py -q` と `uv run -p .venv/bin/python ruff check src/zstarview/gui/window_updates.py tests/test_scheduler_idle.py`
- Topic: satellite / aircraft の描画時投影への責務戻し
  - Decision: satellite / aircraft は、取得済みの軌道・状態データを保持し、描画関数が現在時刻と観測条件から画面上の位置を決めて描画する責務へ戻す方針にした。scheduler 上では、これらを fast-mode に似た latest-win の 2 秒タスクとして扱う。
  - Rationale: 投影済み座標を状態として持つよりも、描画直前に再計算した方が、視点変更や現在時刻の変化に対して責務が明確になる。2 秒周期の更新も、描画時投影として整理した方が設計上の整合が取りやすい。
- Topic: satellite / aircraft の描画時投影の実装切り替え
  - Decision: `RenderSceneData` に raw の軌道要素 / snapshot と描画時刻を渡し、`render/satellites.py` と `render/aircraft.py` が描画直前に alt/az と screen position を計算するよう切り替えた。`reproject_*` は座標を保持するのではなく、次回期限の更新と redraw 要求に役割を縮めた。
  - Rationale: 描画責務を render 層へ寄せることで、controller/state に投影済み座標を持つ必要がなくなり、`latest-win` の 2 秒再描画と視点変更の扱いが単純になる。衛星の古い要素は描画時に抑止し、航空機は snapshot の age に応じた予測表示を render 側で継続できる。
