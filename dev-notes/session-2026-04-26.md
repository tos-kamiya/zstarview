# Session 2026-04-26

- Topic: Label dropout in crowded narrow viewports
  - Decision: Investigate the final label placement pass and expand the search
    space for `hide_on_overlap` labels so crowded scenes can still surface more
    labels before falling back to hiding them.
  - Rationale: The screenshots show labels reappearing when the window is
    wider, which points to a placement/search limitation rather than missing
    label generation.
- Topic: Verification
  - Decision: Added a regression test for dense label clusters and verified the
    updated placement logic with targeted pytest and ruff runs.
  - Rationale: The change touches shared label placement code, so the focused
    label tests were the fastest way to confirm the broader search still keeps
    existing priority behavior intact.
- Topic: Follow-up plan
  - Decision: Next implementation will keep the current priority/overlap
    pipeline and add a lightweight clustering pass so dense labels are ordered
    by proximity to their local centroid.
  - Rationale: This keeps the behavior predictable, avoids a new user-facing
    option, and limits the change to the shared label placement layer.
- Topic: Tie-break rule
  - Decision: When a dense label cluster contains exactly two items, prefer
    the upper item first.
  - Rationale: Labels anchor from the upper-left of the target, so pushing the
    lower item further down tends to preserve perceived proximity to the
    original object while keeping the layout easier to parse.
- Topic: Implementation
  - Decision: Added a lightweight label clustering pass in the final label
    layout stage and kept the existing priority/overlap fallback behavior.
  - Rationale: The implementation keeps the change localized to
    `render/text.py`, preserves the old search offsets, and only changes the
    ordering of dense clusters before overlap avoidance runs.
- Topic: Bright-star diamond sizing
  - Decision: Set the outline-mode bright-star diamond scale to `1.00` and
    leave the fill-mode diamond scale unchanged.
  - Rationale: The bright-star diamond should read as a distinct visual marker
    without making the outline mode's 2px rectangles look larger at high render
    scales. The shared star size is already clipped once before both branches,
    so there is no diamond-only upper bound; the smaller visual footprint came
    from the diamond scale being too conservative relative to the rectangle
    outline.
- Topic: Verification
  - Decision: Added a regression test that renders a bright diamond and a
    comparable outline rectangle at a high outline render scale and checks
    that the diamond is not smaller.
  - Rationale: This captures the reported 4k-style regression without locking
    the code to one exact pixel footprint.
