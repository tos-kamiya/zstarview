- Topic: Simplify the clipping pattern for boundary perception
  - Decision: Limit the diagnostic to near-black and near-white patterns, using
    contiguous tone bands with values aligned below them and no borders, gaps,
    or card treatment.
  - Rationale: Directly adjacent tones make clipping and Mach-band boundary
    perception easier to inspect without unrelated color tests or visual
    separators influencing the result.

- Topic: Specify display tone compensation and calibration
  - Decision: Keep the existing layer-level visibility boost and add a separate
    `--display-tone-curve off|BLACK,WHITE` option at the final present-frame
    display boundary. Add a reusable uncorrected PySide calibration pattern;
    `zstarview-gui` stores its result in the GUI launch profile, while
    `zstarview --calibrate-display-tone-curve` copies and prints only the
    resulting option fragment, then exits without launching or restarting the
    viewer.
  - Rationale: A final display-only LUT can compensate near-black and
    near-white clipping without changing layer color design. Keeping CLI
    calibration diagnostic-only avoids ambiguous option inheritance,
    reconstructed commands, and confusing shell history.
  - Alternatives Considered: Automatically restarting the viewer with the
    calibration result was rejected because it would need to reconstruct or
    discard unrelated CLI arguments and would leave a misleading calibration
    command in shell history. Applying the curve to screenshots or volatile HUD
    overlays was rejected because those outputs should remain portable and the
    UI is already bright.
  - Status: Specification and design documentation updated; implementation is
    intentionally deferred.
