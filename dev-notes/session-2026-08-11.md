- Topic: Choose the precipitation refresh and cache interval
  - Decision: Poll Open-Meteo at most once every ten minutes for an unchanged
    24-point observer scope, coalesce concurrent requests, and give successful
    in-memory responses a ten-minute freshness lifetime.
  - Rationale: Forecast values are normally hourly or 15-minute model-derived
    intervals, so a five-minute poll would often repeat the same target
    interval. Ten minutes can still expose a changed 15-minute value promptly
    and is somewhat more responsive than the approximately 20-minute weather
    satellite update cycle used as a comparison. It produces 144 HTTP requests
    per day; even if usage is conservatively estimated as 24 location units per
    request, it is 3,456 location units per day and 103,680 per 30-day month,
    below the documented Free API limits.
  - Follow-up: Key memory entries by provider mode and the complete ordered
    request scope (rounded coordinates, requested variables, units,
    `cell_selection`, and a cache schema version), never by API key. Preserve
    the API target time separately from the ten-minute fetch freshness time.
