## Summary

- Topic: Night-light ray sampling interval
  - Decision: Reduce the default night-light distance sampling interval from 3 km to 1 km.
  - Rationale: The VNL source tiles have roughly 15-arcsecond pixels (about 500 m), so 3 km ray steps were unnecessarily coarse for visual inspection. Keep the distance-dependent smoothing reference at 3 km so this trial isolates sampling density from the existing visual blur behavior.
  - Trade-off: Night-light source sampling increases by about three times for the same 128 km maximum range.

- Topic: Normalize night-light accumulation by sample width
  - Decision: Multiply each distance sample's accumulated strength and field by its representative distance interval.
  - Rationale: Refining the ray interval must not increase total source strength merely because more samples are summed. The implementation uses the median distance difference, with the configured 1 km step for a single-sample input.

- Topic: Reduce night-light log compression
  - Decision: Blend linear and logarithmic normalization equally with compression strength 0.5.
  - Rationale: The fully logarithmic normalization made weak and strong light regions too similar after increasing sampling density. A 50/50 blend restores contrast while retaining dynamic-range control.

- Topic: Increase default night-light opacity
  - Decision: Raise `NIGHT_LIGHT_DEFAULT_OPACITY` from 0.05 to 0.1 and align CLI, GUI test fallback, specification, and overlay documentation.
  - Rationale: Make the improved night-light contrast more visible at the default setting.

- Topic: Separate night-light altitude and azimuth blur
  - Decision: Keep the distance-dependent altitude sigma unchanged and set the azimuth sigma to 0.75 times that value for visual comparison.
  - Rationale: The VNL source already has finite ground resolution, so reducing only the azimuth spread provides a sharper horizontal distribution without narrowing the useful vertical glow above the ground line. A 0.75 trial checks whether 0.5 made the individual glow patches too vertically elongated.

  - Decision: Introduce the feature incrementally. Separate the dark-star surface and bright-star direct pass first, then connect a 9-point 3x3 homography approximation to the regular scenic viewer in 10-second cache buckets.
  - Rationale: This makes the composition modes and alpha behavior testable before optimizing away all base-frame work. Atlas remains on its existing path during the trial.

- Topic: Cache the faint-star surface separately from interpolated presentation
  - Decision: Cache the `vmag > 4` star surface with the sky snapshot and apply the homography during presentation; render bright stars and their underlay directly at the current interpolated position.
  - Rationale: Changing the interpolation cache bucket must not regenerate the expensive faint-star raster. The separate direct pass preserves crisp bright stars and keeps the underlay on `SourceOver`.

## Star interpolation update-interval guard

- Topic: Disable star-position interpolation for long snapshot intervals
  - Decision: Keep the 2D homography interpolation enabled when `sky_update_interval` is 90 seconds or less, and disable it when the interval exceeds 90 seconds.
  - Rationale: The interpolation amount was tuned conservatively for the default 60-second snapshot interval; applying it across longer intervals could introduce excessive positional approximation.
  - Implementation: Carry the configured interval in `FrameContext` and gate the shared scenic interpolation matrix, including bright stars, asterisms, and simplified named-star labels.

- Topic: Align interpolation midpoint with the configured update interval
  - Decision: Compute the star snapshot time at `update_start + sky_update_interval / 2` and clamp presentation interpolation to the corresponding `+/- sky_update_interval / 2` range.
  - Rationale: The previous implementation used a fixed 30-second midpoint and limit, which was correct only for the default 60-second interval and incorrect at the supported 90-second boundary.
  - Verification: Related worker and interpolation tests passed (`15 passed`); Ruff passed.
