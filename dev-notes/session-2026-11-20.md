- Topic: 計測基盤と実操作でのキャッシュ利用頻度 (Step 1)
  - Decision: `dev-samples/benchmark_star_render.py`（下位関数のhit/brighthit/miss/pos/split、画素スナップショット比較）、`trace_star_render_cache.py`（GUIキャッシュと下位キャッシュのカウンタ）、`drive_star_render_trace.sh`（xdotoolで実ウィンドウをidle/hover/rotate操作）を追加。
  - Rationale: 固定条件（2026-01-15T12:00Z、35.47N 133.05E、視線 alt45/az180、edge 95/content 115、base radius 3、DPR 1）で再測定できるようにする。時間計測中は tracemalloc を無効にし、割当ピークは別の1回で測る（tracemalloc有効だと明背景のPythonループが約30倍遅く見えた）。
  - Alternatives Considered: オフスクリーンQPAでのGUI計測は paintEvent が発生せず不可。利用者の許可を得て実ウィンドウ（XWayland, `QT_QPA_PLATFORM=xcb`、設定は一時 `XDG_CONFIG_HOME`）で計測した。
  - 結果（実ウィンドウ 1600x900 scenic, 変更前）: アイドル時は present-frame が約0.5回/秒再生成され、明るい星パスが下位キャッシュに命中（3.0ms）。ホバーでは恒星描画なし。回転確定後は faint 66.6ms + bright 89.8ms の再生成。操作中は fast 経路でキャッシュなし 13ms。
  - 支配項（2560x1440 v7 miss, 約216ms）: RGBA変換の `np.max(axis=2)` が約95ms/回、全画面の除算・マスク代入、レイヤー確保。キー生成・投影ではない。

- Topic: キャッシュ契約の不足修正 (Step 2)
  - Decision: 暗背景キーに `edge_fov_deg`、描画サイズ、`bv`/`vmag`/`star_index` を追加。`screen_positions` 指定時はキャッシュへ保存しない。
  - Rationale: 契約テスト `tests/test_star_render_cache.py` で、視野角・B-V変更後の古い画像再利用と、独自座標で描いた画像が後続の通常呼び出しに命中する汚染を再現した。明背景経路は投影後座標でキー化しており問題なし。

- Topic: A キャッシュ判定の前倒し / B 不変スナップショットの識別
  - Decision: 選別前の全配列と等級上下限でキーを作り、選別・投影・色計算の前に判定する(A)。`calculate_visible_stars` の出力配列を読み取り専用にし、読み取り専用かつデータ所有の配列は同一性で比較、それ以外はMD5へフォールバック(B)。
  - Rationale: A単独では明るい星パス（数百行）でも全行をハッシュするため悪化した（2560x1440 v9 brighthit 2.2→8.9ms）。A+Bで hit 29→1.4ms、brighthit 2.2→1.2ms。キャッシュエントリが配列参照を保持するため id 再利用は起きない。
  - Alternatives Considered: `id(array)` のみは再利用・in-place変更を検出できず不採用。ビューは基底の変更を検出できないためハッシュ方式を維持。

- Topic: C 作業バッファの所有者単位再利用
  - Decision: 不採用。
  - Rationale: canvas のみ、canvas+レイヤー+RGBA のいずれでも、A+B と A+B+D の双方で時間差は誤差内（例 2560x1440 v7 miss 53.4/54.3ms vs 52.1/52.8ms）。一時確保ピークは 170→23MB に下がるが、2560x1440で約100MBを所有者ごとに常駐させる。大きな確保は毎回mmapで解放されるため、常駐させる利点が時間に現れなかった。

- Topic: D RGBA変換の非ゼロ画素限定（計画外の追加）
  - Decision: 採用。`max(axis=2)` を `np.maximum` 連鎖に、un-premultiply を非ゼロ画素だけに同じ float32 演算で適用。
  - Rationale: Step 1 の支配項。出力はビット一致（54スナップショット完全一致）。2560x1440 v7 miss 216→54ms、960x720 48→16ms、割当ピーク 362→170MB。
