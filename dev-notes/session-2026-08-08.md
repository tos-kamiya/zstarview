- Topic: Urban buildings and sky colour
  - Decision: Treat buildings primarily as a direction-dependent obstruction/horizon mask, not as a uniform 50 m increase to observer elevation. A 50 m assumption can be useful as a fallback building-height parameter, but it should be projected per building distance and azimuth.
  - Rationale: Raising the observer changes every atmospheric path and the geometric horizon globally, while buildings only block selected low-altitude directions. A 50 m building subtends `atan(50 / distance)`; its effect is about 26.6 degrees at 100 m, 5.7 degrees at 500 m, and 1.4 degrees at 2 km.

- Follow-up: The current urban renderer draws sampled building-top outlines with translucent line/optional fill geometry. Therefore, if visual consistency is required, a separate opaque or cutout obstruction mask should be considered; changing the Rayleigh/Mie/aerosol model is not necessary for this purpose.

- Follow-up: The bundled CAMS grid value at Beijing (39.9042 N, 116.4074 E) is about `0.904` for August, versus the model reference `0.15`; this corresponds to roughly six times the aerosol density scale. Therefore, exponential vertical decay alone does not rule out an overly strong visual result.

- Topic: Memory estimate for per-shell cloud grids

  - Rationale: The persistent observer-centric grid is small; the main additional cost is three `float32` arrays of 64,800 cells. Temporary ingestion arrays and screen-sized render buffers remain separate considerations.

- Topic: Initial parameters for sunset cloud tint
  - Proposal: Keep the existing 3/5/7 km shells and `(0.0, 1.0, 0.0)` to `(0.2, 0.6, 0.2)` cloud-shell weights. Add a non-CLI warm factor that starts near Sun altitude `+8°`, peaks around `0°`, and fades by `-8°`; cap shell tint mixes at approximately `0.10` (3 km), `0.20` (5 km), and `0.30` (7 km).
  - Rationale: This keeps daytime clouds white, limits red contamination after sunset, and gives high clouds a stronger sunset response without assuming that all low clouds are brightly red.

- Topic: Use the solar-horizon sky colour as the cloud lower-light proxy
  - Decision: Prefer the existing `sky_color_near_solar_horizon()` result over a fixed warm RGB as the candidate colour source for sunset cloud tint. It averages the model colour from altitude `0` to `10` degrees at the solar azimuth and can use the same location/month aerosol value.
  - Rationale: This better represents reddish light scattered upward from the low atmosphere. The result should be used as a capped target tint rather than copied directly into the cloud pixels, because it includes atmospheric exposure, alpha, and potentially strong aerosol saturation.

- Topic: Implement multi-shell cloud tinting
  - Decision: Store per-shell amount arrays in the cloud-grid cache, render shells independently in all existing stripe modes, composite high-to-low, and use the cached modelled solar-horizon RGB with shell mix caps `0.22 / 0.15 / 0.08` for `3 / 5 / 7 km`.
  - Rationale: This preserves legacy single-field cache compatibility while allowing low-layer sunset reflection colour without changing the atmospheric sky model.

- Topic: Warm-colour activation gate
  - Decision: Remove the fixed `+8°` upper activation boundary. For Sun altitude `>= -8°`, derive warmness from both `R-B` and `R-G`; keep the tint disabled when either channel difference is not warm enough. Keep the `-8°` lower cutoff and shell mix caps unchanged.
  - Rationale: A low mix ratio is still enough to make daytime blue sky tint clouds blue. The two-channel gate allows warm sunset colours throughout the valid altitude range while preserving daytime cloud colour.
