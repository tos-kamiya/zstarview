# Session 2026-03-21

- Date: 2026-03-21
- Scope: CLI screenshot/export mode specification and design study

- Topic: CLI からの単発画像書き出しモード
  - Decision: GUI 常駐を伴わない「画像書き出して即終了」モードを追加する前提で、初期版は「最初に可視化可能になったフレーム」を保存対象とする。
  - Rationale: 既存起動経路では `initial_data_loaded` が最初の表示成立点であり、ここに合わせると通常起動と整合しやすい。雲・地形・都市輪郭・航空機まで無条件に待つ設計は、ネットワークや初回キャッシュ生成で待機時間が読めず、自動化用途と相性が悪い。
  - Alternatives Considered: 全有効レイヤーの完了待ちを既定にする案は、初回利用やオフライン時のハング・長時間待機リスクが高いため初期スコープから外す。

- Topic: 画像書き出し対応に向けた先行作業の切り分け
  - Decision: 新しい CLI 機能の実装は後回しにし、先に描画パイプラインを Mixin 依存から切り離す純リファクタリングとして進める。
  - Rationale: GUI と CLI ではデータ取得順序が異なってよく、先に描画本体を共通関数へ分離したほうが、後段の別 main / 別 orchestrator を安全に導入しやすい。

- Topic: 描画パイプライン分離の第1段
  - Decision: `src/zstarview/render/pipeline.py` を新設し、1フレーム描画に必要な入力を `RenderPipelineState` に集約したうえで、背景、sky/cloud、terrain、urban outline、aircraft、stars、planets、overlay、labels、status line の共通描画関数を移設した。
  - Rationale: まず描画本体を `SkyWindow` の状態管理から切り離し、GUI と将来の CLI が共有できる土台を作ることを優先した。
  - Notes: `ui/window_render.py` 側には既存呼び出し面とテスト互換のための薄いラッパを残し、`paintEvent()` の本命経路は共通パイプライン呼び出しへ寄せた。

- Topic: DSO hover の描画順序見直し
  - Decision: `draw_dso_hover_info()` は terrain 段から外し、通常描画では DSO shapes / 恒星 / 惑星の後、`draw_overlay_layer()` の直前に移した。
  - Rationale: DSO hover は地形・方位ラベル類よりも、恒星ホバーやオブジェクト overlay に近い HUD 的注釈として扱うほうが整理しやすい。
  - Notes: `tests/test_window_render_sync.py` に、terrain 段で DSO hover を描かないことと、通常描画で `dso-hover -> overlay` の順になることを追加で固定した。

- Topic: 天頂マーカーと方位ラベルの描画順序見直し
  - Decision: 天頂マーカーと方位ラベルは scene 中段から外し、背景直後に描く早い段へ移した。
  - Rationale: これらは HUD というよりガイド下敷きとして扱ってよく、雲や sky disc の下に入っても視認性上の問題は小さい。
  - Notes: 通常描画では `background -> direction-zenith -> sky-cloud` の順をテストで固定し、terrain / viewport interaction 側のラッパからは方位・天頂描画を外した。

- Topic: 天頂マーカーと方位ラベルの順序修正
  - Decision: 背景直後ではなく、`sky-cloud` 合成の直後に描く位置へ修正した。
  - Rationale: `SkyCompositorCache.draw()` が `SourceOver` で全面描画するため、背景直後に置くとガイド要素が空色・雲合成に完全に上書きされて消える。
  - Notes: 順序は `background -> sky-cloud -> guide` に修正し、天頂マーカーと方位ラベルは独立した guide layer として扱うよう命名も整理した。今回の再確認では `ruff check` は通過したが、テスト実行はローカルの依存解決不整合（`uv run` / `pytest` / `astropy`）により再取得できなかった。

- Topic: RenderPipelineState の分割
  - Decision: 描画入力を `RenderSceneData`、`RenderStyle`、`RenderHudState` の 3 つに分け、`RenderPipelineState` はそれらを束ねる薄い合成型に変更した。
  - Rationale: scene / style / HUD を明示的に分離しておくと、将来 CLI 用の静的描画では HUD 依存を薄くでき、スタイル値のまとまりも見通しやすくなる。
  - Notes: 第1段では property 経由の互換アクセスを残したが、その後の追加入力整理で、描画関数側は `state.scene` / `state.style` / `state.hud` を直接参照する形へ寄せた。`RenderPipelineState` 自体は `geometry`、`viewport_rect`、`content_fov_deg` を持つ薄い合成ルートに近づいた。`uv run pytest tests/test_window_render_sync.py tests/test_star_render_scale.py -q` は 19 件通過、`uv run ruff check src/zstarview/render/pipeline.py src/zstarview/ui/window_render.py tests/test_window_render_sync.py` も通過。

- Topic: `_render_pipeline_state()` の分解
  - Decision: `ui/window_render.py` の `_render_pipeline_state()` を、`_render_scene_data()`、`_render_style()`、`_render_hud_state()` に分けた。
  - Rationale: `RenderPipelineState` の組み立て責務を scene / style / HUD の単位へ分割し、将来は個別ラッパが必要な構成要素だけを選んで渡せるようにするため。
  - Notes: 現段階では個別ラッパがまだ `RenderPipelineState(...)` を直接束ねる箇所を残しているが、少なくとも「全てをまとめて返す専用 helper」への依存は外れた。`uv run pytest tests/test_window_render_sync.py tests/test_star_render_scale.py -q` は 19 件通過、`uv run ruff check src/zstarview/ui/window_render.py src/zstarview/render/pipeline.py tests/test_window_render_sync.py` も通過。

- Topic: `render_scene_into_painter()` の入力分解
  - Decision: `render_scene_into_painter()` は `RenderPipelineState` を直接受け取らず、`geometry`、`viewport_rect`、`scene`、`style`、`hud` を個別引数で受ける形へ変更した。
  - Rationale: 描画本線の関数シグネチャに依存関係を明示し、呼び出し側が `RenderPipelineState` を経由せず scene/style/hud を直接渡せるようにするため。
  - Notes: その後の追加入力整理で、下位の `draw_*` 関数群も `geometry`、`viewport_rect`、`scene`、`style`、`hud` ベースへ揃え、`RenderPipelineState` は完全に削除した。`uv run pytest tests/test_window_render_sync.py tests/test_star_render_scale.py -q` は 19 件通過、`uv run ruff check src/zstarview/render/pipeline.py src/zstarview/ui/window_render.py tests/test_window_render_sync.py` も通過。

- Topic: SkyWindowRenderMixin の未使用ラッパ整理

  - Rationale: `draw_background_layer`、`draw_guide_layer`、`draw_sky_cloud_layers`、`draw_planet_layer`、`draw_overlay_layer`、`draw_dso_hover_layer`、`draw_label_layer`、`draw_status_line` は shared pipeline 直呼び出しへ置き換わっており、Mixin に残す意味が薄かった。
  - Notes: GUI 固有の state/cache/hover 関連と、まだテスト・本番で意味を持つ互換ラッパだけを残した。`uv run pytest tests/test_window_render_sync.py tests/test_star_render_scale.py -q` は 19 件通過、`uv run ruff check src/zstarview/ui/window_render.py src/zstarview/render/pipeline.py tests/test_window_render_sync.py` も通過。

- Topic: Mixin 内の残存描画ロジックの shared pipeline への委譲
  - Decision: `SkyWindowRenderMixin._draw_viewport_interaction_layers()` と `_draw_terrain_layers()` は、自前で `render_draw` を組み立てて呼ぶのをやめ、`render.pipeline` の共通関数へ委譲する形に整理した。
  - Rationale: Mixin 側に残っていた重複ロジックを減らし、`window_render.py` の責務を「GUI state から scene/style/hud を作って pipeline を呼ぶ」薄いラッパへさらに寄せるため。
  - Notes: 互換ラッパが `SimpleNamespace` ベースのテストダブルからも呼べるよう、`_render_scene_data()`、`_render_style()`、`_render_hud_state()` は `getattr` ベースの既定値補完を入れた。テストも Mixin 内部呼び出しではなく `pipeline.py` の shared function を監視する方向へ更新した。`uv run pytest tests/test_window_render_sync.py tests/test_star_render_scale.py -q` は 19 件通過、`uv run ruff check src/zstarview/ui/window_render.py tests/test_window_render_sync.py src/zstarview/render/pipeline.py` も通過。
