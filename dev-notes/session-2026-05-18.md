- Topic: Water overlay simplification redesign
  - Decision: Replace the old vertex-spacing simplifier with distance-band
    grid snapping in `2^k m` cells, using a `0.5°` apparent-angle threshold
    per band and dropping rings that collapse to zero area.
  - Rationale: The previous simplifier still did too much per-footprint work
    for very large inland-water caches. Grid snapping keeps the algorithm
    linear in the number of vertices, makes the distance bands explicit, and
    gives a clear geometric rule for rejecting degenerate rings.
  - Alternatives Considered: Keeping vertex-spacing simplification would be
    simpler to preserve, but it did not match the intended cache-reduction
    model for long shoreline paths. Adding more progress logging alone would
    improve observability but not the underlying runtime.

- Topic: Water overlay simplification direction stability
  - Decision: Remove the global `seen_cells` dedupe from the grid-snapping
    simplifier and keep only consecutive duplicate suppression after snapping.
  - Rationale: The previous global dedupe made the surviving representative of
    a grid cell depend on ring traversal order, which could make near and far
    points swap roles when the same shoreline was walked in the opposite
    direction. Consecutive-only collapse keeps the simplifier direction-stable
    while still removing obvious repeated vertices.
  - Alternatives Considered: Choosing a per-cell representative by distance
    to the observer would also be deterministic, but it would add more
    bookkeeping without solving the repeated-cell topology issue as cleanly.

- Topic: Startup ephemeris caching for worker stability
  - Decision: Cache the loaded Skyfield ephemeris object in
    `zstarview.astro.load_ephemeris()` and guard first load with a lock.
  - Rationale: The crash report shows repeated Skyfield kernel activity in a
    background GUI worker thread while the app is running. Keeping one strong
    process-wide ephemeris instance avoids repeated kernel construction and
    garbage collection, which reduces the chance of native crashes in the
    `skyfield.jpllib` path.
  - Validation: Pending. Added a regression test that asserts the ephemeris
    loader is only invoked once per process.
- Topic: UI-owned ephemeris handoff
  - Decision: Ensure the GUI loads ephemeris on the UI thread during startup
    and passes that object into the sky worker instead of letting the worker
    fetch it itself.
  - Rationale: This makes thread ownership explicit. The UI thread owns the
    singleton kernel, and background tasks receive it as read-only input,
    which removes ambiguity about who initializes the Skyfield state.
