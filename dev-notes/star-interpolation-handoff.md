# 恒星表示補間 引き継ぎ書

最終更新: 2026-07-19

## 目的

zstarview の通常ビューアで、60 秒ごとの恒星・空スナップショット交換時に発生する画面の「カチッ」とした切り替えを緩和する。

重い天文計算の更新間隔は維持し、恒星の表示だけを軽量に補間する。まず通常ビューアの GUI を対象とし、Atlas と `zstarview-export-image` は従来経路を維持する。

## 現状

- sky worker が恒星、惑星、空色ディスクなどを含むスナップショットをバックグラウンドで生成する。
- GUI の既定の sky 更新間隔は 60 秒。
- 約 700ms 周期のスケジューラが更新期限を確認し、Qt の `update()` を通じて再描画を予約する。
- 人工衛星・航空機の位置予測は約 2 秒周期の短命レイヤーとして扱われる。
- 通常ビューアでは、恒星描画はベースシーンの描画中に行われる。
- 大きなウィンドウでは、恒星用の低解像度 `QImage` に恒星を描いてから画面へ拡大 blit する。
- 現状の描画コードでは、`vmag <= 4` と `vmag > 4` の両方が恒星描画経路に含まれる。明るい恒星の暗色下敷きとダイヤモンドは別パスだが、恒星補間用の独立レイヤーとしては未分離である。
- `vmag` は数値が小さいほど明るい。明るい恒星は `vmag <= 4`、暗い恒星は `vmag > 4`。

## 合意済みの目標構成

```text
空色ディスク・背景・地形・雲
        ↓
暗い恒星サーフェイス（vmag > 4、透明画像）
        ↓
明るい恒星の暗色下地（vmag <= 4、SourceOver）
        ↓
明るい恒星本体・ダイヤモンド（Plus 等）
        ↓
惑星、人工衛星、航空機、星座線、ラベルなど
```

- 暗い恒星サーフェイスは 60 秒スナップショット単位で生成し、補間中は画像を再生成しない。
- 明るい恒星、暗色下地、ダイヤモンドはサーフェイスへ焼き込まず、合成時に現在位置へ直接描画する案を第一候補とする。
- 空色ディスクは恒星サーフェイスから分離する。
- 暗色下地は半透明の黒または濃色として `SourceOver` で合成する。
- 暗色下地を恒星の加算画像へ混ぜて `Plus` 合成してはならない。黒が暗くならないためである。
- 暗い恒星サーフェイスには、スナップショット基準時刻からの経過時間に応じた 3x3 射影変換を適用する。
- 行列は画面中心だけで決めず、四隅付近、辺中央、中央など複数点を使って近似する。
- 四隅付近には `content_fov_deg` のオーバースキャン領域が含まれるため、誤差評価の対象にする。
- 星座線や恒星ラベルなど恒星位置に追随する要素は、同じ変換を適用するか、同じ補間時刻で再投影する。

## 時間更新方針

現行実装では、60 秒スナップショットの間を 2 秒周期で表示更新する。

- 0 秒: 新しいスナップショットを基準にする。行列をリセットする。
- 2 秒: 補間行列を経過時間から再計算し、表示フレームを更新する。
- 4 秒: 補間行列を経過時間から再計算し、表示フレームを更新する。
- ...
- 60 秒: 新しいスナップショットへ交換する。

行列は固定値ではなく、スナップショット基準時刻からの経過時間で算出する。現在の表示フレームは2秒周期で更新される。100〜250ms程度の短周期化は今後の比較対象とする。10秒バケットは補助的なキャッシュキーとして残っているが、2秒周期の表示更新を妨げない。

重要な分離は次の通り。

- sky worker: 60 秒ごとの重い天文計算
- 補間状態: 経過時間と 3x3 行列の更新
- repaint: `request_client_update()` による Qt の非同期再描画要求

行列の更新では、空色ディスク、地形、雲、都市アウトライン、夜間光などの重いキャッシュを無効化しない。

## 推奨する実装順

1. **測定と数学モデル**
   - 実装前に球面再投影と 3x3 近似の誤差を測る。
   - 行列近似の受け入れ基準を決める。

2. **恒星レイヤーの独立化**
   - まず補間なしで、暗い恒星サーフェイスと明るい恒星の直接描画を分離する。
   - 変更前後の見た目とピクセル差分を確認する。

3. **合成モードの整理**
   - 暗色下地を `SourceOver`、恒星光を `Plus` で扱う。
   - 黒い縁、透明端、画像拡大時の黒フリンジを確認する。

4. **補間行列の導入**
   - 暗い恒星サーフェイスにだけ行列を適用する。
   - 明るい恒星は同じ行列で直接描画する。

5. **再描画・キャッシュ統合**
   - sky worker を再実行せず、行列更新だけで表示を更新する。
   - 古い行列の表示画像がキャッシュから返らないことを確認する。

6. **追随要素と頻度評価**
   - 星座線、恒星ラベルを対応させる。
   - 10 秒、2 秒、短周期の各方式を比較する。

## 検証基準

### 視覚

- [ ] 60 秒ごとの「カチッ」とした切り替えが軽減される
- [ ] 四隅付近で恒星が大きくずれない
- [ ] 明るい恒星とダイヤモンドが過度にぼけない
- [ ] 明るい恒星の黒い下地が空色ディスク上で正しく暗くなる
- [ ] 恒星の二重描画、消失、重複した下地が発生しない
- [ ] サーフェイス境界やオーバースキャン境界で恒星が欠けない
- [ ] 星座線・恒星ラベルが恒星からずれない

### 性能

- [ ] 恒星補間中の repaint が sky worker の再計算を誘発しない
- [ ] 大画面での再描画時間が許容範囲に収まる
- [ ] 明るい恒星の直接描画数が増えても UI が固まらない
- [ ] 60 秒スナップショット更新の所要時間が悪化しない

### 回帰

- [ ] 視点変更と fast-mode が従来どおり動作する
- [ ] window resize 後に古いサーフェイスや行列を使わない
- [ ] `sky-opacity=0` で暗色下地が意図せず残らない
- [ ] Atlas の描画に影響しない
- [ ] export-image がアニメーション状態に依存しない

## 受け入れ基準の初期案

数値基準は実測後に確定する。初期評価では次を目安にする。

- 画面全体の95パーセンタイル位置誤差: 0.5px 以下を目標
- 四隅付近の最大位置誤差: 1px 前後を目標
- 明るい恒星の輪郭: 変換前後で明らかな二重像・黒フリンジがない
- 補間中の追加処理: sky worker の再計算を発生させない

数値基準を満たさなくても、実際の表示で違和感がない場合は、視覚評価と併記して判断する。逆に数値基準を満たしていても、明るい星の輪郭や下地に違和感があれば採用を保留する。

## 決定済み事項

- [x] 3x3行列は、厳密な球面回転を9対応点へ投影した最小二乗フィッティングで求める。
- [x] 対応点は四隅付近・辺中央・中央の9点とする。
- [x] 表示更新は2秒周期とする。行列自体は固定値ではなく経過時間から算出する。
- [x] 恒星サーフェイスは透明な`QImage`として保持する。
- [x] 補間対象は通常ビューアの恒星表示とし、Atlas・export-imageには適用しない。
- [x] 惑星・太陽・月は補間せず、2秒周期の専用workerで現在時刻の位置を直接計算する。
- [x] 空色ディスク、雲の色、夜間光は従来どおり60秒スナップショットの値を使用する。
