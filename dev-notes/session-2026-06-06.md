  - Decision: Added a dedicated runtime section that treats logs and diagnostic output as ASCII-only, separate from UI text.
  - Rationale: Terminal, log, CLI help, exception, and subprocess output are the common accidental sources of encoding trouble, so the rule should be explicit and easy to find.
  - Next step: Keep user-facing Japanese text in UI or documentation, and keep logs normalized or escaped when they may include non-ASCII external data.

- Topic: Specification output characters
  - Decision: Added a short specification subsection that states terminal, log, help, exception, and subprocess outputs should be ASCII-only, while UI strings may remain non-ASCII when needed.
  - Rationale: The design doc defines the operational rule, but the specification should also mention the user-visible output constraint so accidental encoding regressions are easier to spot.
  - Next step: Keep the specification wording short and avoid moving the detailed logging policy out of runtime.
