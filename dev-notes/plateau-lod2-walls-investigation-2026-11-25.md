# PLATEAU LOD2 壁面の調査と実装仕様案

作成日: 2026-11-25。対象: 近景壁の PLATEAU データと描画。実装前の提案であり、
現行の機能仕様ではない。

> **状態（2026-11-25）: 保留。** 壁データの容量を見積もっていないため、LOD2 壁面の
> 利用は一時的に見送る。キャッシュ管理の改修は `handoff-2026-11-25-plateau-cache-fixes.md`。

引き継ぎは `handoff-2026-11-24-nearby-building-walls.md`。

## 実データの調査

港区2025年の CityGML 建築物タイル `53393599_bldg_6697_op.gml` を調べた。
ファイルサイズは109,746,782 bytes、座標参照系は EPSG:6697。XML の `Building` の
子孫を数えた結果であり、国内全体の代表値ではない。

| 項目 | 件数 |
| --- | ---: |
| Building | 1,258 |
| LOD2 WallSurface のポリゴンを持つ Building | 1,258 |
| LOD2 壁ポリゴン | 22,206 |
| LOD3 壁ポリゴンを持つ Building | 11 |
| LOD3 壁ポリゴン | 6,063 |
| LOD2 と LOD3 壁の両方を持つ Building | 11 |
| BuildingPart | 0 |

LOD2 の壁ポリゴン数は建物当たり最大346、4面の建物は411棟。東京タワー
`bldg_7aff4a51-be8b-405b-abe4-ac489697cbc8` は LOD2 壁264ポリゴン、LOD3壁0。
このタイルでは LOD2/LOD3 壁の全28,269ポリゴンに外周が1本あり、内周はなく、
WallSurface 内に xlink 参照はなかった。外周の posList は閉鎖点を含む4点や5点が
多いが、より多い面もある。複数ポリゴンを含む WallSurface がある。穴、参照、
BuildingPart の不在はこのタイルに限った観察であり、他データでの不在を意味しない。
同じ建物に LOD2 と LOD3 が併存するため、タグ名だけの子孫走査は不可。

### 別地域の追加調査（2026-11-25）

PLATEAU CityGML カタログから次の3タイルを個別取得し、元 XML を調べた。LOD2 壁の
ポリゴンは、`WallSurface` の `lod2MultiSurface` 以下の `Polygon` を数えた。

| 地域・年度・タイル | 建物数 | LOD2 壁あり | LOD2 壁ポリゴン | 現行変換で除外される壁あり建物 |
| --- | ---: | ---: | ---: | ---: |
| 静岡市 2023・52384329 | 782 | 33 | 697 | 27 |
| 大阪市 2025・51357391 | 206 | 206 | 1,859 | 0 |
| 中央区 2025・53393671 | 70 | 70 | 1,051 | 24 |
| 港区 2025・53393599 | 1,258 | 1,258 | 22,206 | 115 |

静岡の LOD2 壁は33個の `WallSurface/lod2MultiSurface` に入り、すべてが複数
ポリゴンを含む。静岡では壁あり33棟のうち17棟に `RoofSurface` がない。ほかの3タイルの
壁あり建物には屋根面がある。4タイルの LOD2 壁はいずれも外周1本・穴なしで、座標は
閉じた `posList`、壁の `lod2MultiSurface` 以下に xlink はなく、`BuildingPart` は
なかった。調査範囲外の穴、参照、建物部分への対応は引き続き未実証である。

静岡の `RoofSurface` がない17棟を追加確認したところ、すべてに LOD0 `lod0RoofEdge`
と LOD1 `lod1Solid` があり、LOD1 solid には上面に当たる水平ポリゴンがある。さらに
17棟すべてで、LOD2 の `WallSurface` にも LOD1 上面と同じ標高の水平ポリゴンが含まれる。
その水平ポリゴンは17棟中4棟で LOD1 上面と頂点集合が一致したが、他は一致しない。
したがって `RoofSurface` 不在は屋根に相当する形状がないことを意味せず、LOD2 の
意味分類だけで実形状を推定できない例がある。水平面を傾斜だけで一律に除外しない。
この17棟のうち現行の高さ条件で採用されるのは5棟。

現行変換で除外された上表の166棟は、高さが取得できず、階数も有効な推定値として
扱えない。壁や輪郭の有無による除外ではない。静岡27、中央24、港115棟の合計であり、
建物高さを要求する現行 `BuildingFootprint` の制約が影響する。LOD2 壁があれば必ず
表示されるわけではない。高さを壁の標高差から推定して建物自体を新たに採用すると、
屋根線や高さフィルタなどにも影響するため、今回の仕様では従来の除外を維持し、
将来の別検討とする。壁なし建物でも欠損高さの除外例がある。

調査した4タイルのうち、現行変換で残る港区の5棟は、LOD2 壁の水平 bbox が現行の
輪郭 bbox より約0.05 m超外へ出る。最大は約25.5 m、東京タワーは約22.6 m。
経緯度の軸方向差を概算のメートル値に直した最大値であり、輪郭そのものからの最短距離
ではない。他の3タイルでは同じ条件の張り出しは0棟。小さな差は丸め誤差を含み得る。

静岡の [52384329](https://assets.cms.plateau.reearth.io/assets/6e/1b63f3-2c2b-4d3e-9c2b-ff6df591c2e3/22100_shizuoka-shi_city_2023_citygml_3_op/udx/bldg/52384329_bldg_6697_psc_op.gml)、
大阪の [51357391](https://assets.cms.plateau.reearth.io/assets/10/a0aecb-67d1-4463-92d5-d67c99f3b8b6/27100_osaka-shi_city_2025_citygml_1_op/udx/bldg/51357391_bldg_6697_op.gml)、
中央区の [53393671](https://assets.cms.plateau.reearth.io/assets/93/1f058b-e06b-445c-ae62-2e02cdf72849/13102_chuo-ku_pref_2025_citygml_1_op/udx/bldg/53393671_bldg_6697_op.gml) を使用。

PLATEAU は高さを東京湾平均海面を基準とする標高として説明している。
[国土交通省: CityGML の座標・高さとデータ変換](https://www.mlit.go.jp/plateau/learning/tpc03-4/)。
現行コードは LOD2 屋根の頂点標高を直接観測地点の標高と比較し、近似壁では建物
代表点の DEM 標高に高さを加える。両者は異なるデータ源であり、観測地点 DEM の
鉛直基準や地域差、誤差の厳密な一致は未検証。

現行の派生タイルは建物ID（`gml:id`）・高さ・LOD1/LOD0 輪郭と屋根面を保存し、壁面を
保存しない。既存キャッシュ4自治体（港区・千代田区・大阪市・松江市）約76万棟では、
`gml:id` 欠落による合成IDは0件、タイル内の重複IDも0件だった。
輪郭と bbox は LOD1 の最大リング由来であり、東京タワーの LOD2 壁はそこから
はみ出す。取得時の建物高さフィルタと輪郭ベースのタイル・建物候補選択もあるため、
壁生成部分だけの変更では詳細壁が候補から漏れ得る。現行の屋根抽出も全 RoofSurface
の posList を走査しており、LOD・ポリゴン・穴を区別しない。今回の壁の設計では
これを流用しない。屋根の抽出方法の変更は別途影響を評価する（40 m閾値の撤廃とは別）。

## 詳細仕様案

### 抽出と保存

- `Building` ごとに `boundedBy/WallSurface/lod2MultiSurface` 以下の各 `gml:Polygon` を
  抽出する。LOD1 solid と LOD3/4 は混ぜない。外周を閉じた `(lon, lat, elevation_m)`
  頂点列として保存し、面の順序とリングの向きを保持する。内周は描画時に無視し、穴は
  塗りつぶす。穴の有無・件数は診断に記録し、外周と区別する。元の内周の保存は任意とする。
- `gml:posList` の次元・座標系を確認し、有限の3次元座標、3個以上の異なる頂点、
  非ゼロ面積、閉じた単純なリング、対応可能な平面形状を検証する。XY 面積では垂直壁を
  判定できないため、3Dの局所平面に射影して検査する。実装時に許容誤差を数値化し、
  非平面・自己交差の判定をテストする。内周は無視するため、描画可能性の判定に使わない。
- 複数ポリゴンは別々に保持する。ローカル xlink、別ファイル参照、`pos` 列、特殊な
  曲面、未対応 CRS 等は、対応が実証されない限り未対応とする。未対応形状や不正面が
  壁の一部にある場合は欠けた詳細壁と全高近似壁を重ねず、当該建物全体を近似壁へ
  フォールバックし、診断件数を記録する。壁がない建物も近似壁とする。対応不能な
  データを正常な壁なしと区別する。実データを追加調査し、対応範囲を広げるか判断する。
- `WallSurface` ひとつを1ポリゴンとみなさず、同じ `lod2MultiSurface` にある複数の
  `Polygon` をすべて取得する。屋根面がなくても壁単独で利用できる。
- `BuildingPart` は親子の二重走査・二重描画を避ける必要がある。このサンプルにはなく、
  親と部分の範囲・ID の対応は未調査。実装前に別データで検証し、曖昧な親子形状は
  建物単位で近似壁に戻す。部分形状を黙って採用しない。
- 面の bbox を輪郭 bbox と別に保持し、壁のある建物の候補選択で両者の和集合を使う。
  変換時の高さフィルタで除外された建物は復元できないため、既定フィルタと対象建物数を
  実装時に確認する。LOD2 壁の利用可否は屋根面の有無に依存させない。LOD2 屋根表示の
  現行40 m閾値（`DETAILED_ROOF_MIN_BUILDING_HEIGHT_M`）は、壁面モードに限らず現行描画でも
  撤廃する（決定済み）。

### キャッシュと移行

具体的なディレクトリ構成、対応付け、更新手順は
`plateau-lod2-wall-cache-design-2026-11-25.md` を参照。キャッシュは自治体ごとに1世代
（`<code>/`）とし、元 ZIP のチェックサムで元データを識別する。`bldg/`（スキーマ3、輪郭・
高さ・屋根）は変更せず、同じディレクトリに壁専用の `walls/` を追加する。両者は
再取得または保存済み ZIP の再変換により、同じ準備処理で同時に生成し、`(タイル名, gml:id)`
で対応付ける。壁は壁半径内のタイルだけを読み込む。コマンドラインで現行描画と LOD2
壁面描画を切り替え、壁面描画では利用可能な詳細壁で近似壁を置き換える。旧形式の
キャッシュ（`<code>_<year>/`）は、新たに準備するまで現行描画で屋根データとして利用でき、
準備後は差し替えて削除する。準備CLIのオプション体系は作り直す。後から壁だけを補う独立した補助キャッシュの
案と、`bldg/` に壁を同居させてスキーマ4とする案は取り下げる。新しいデータを準備したら
旧キャッシュは破棄し、自治体ごとに1つだけ読み込む。Overture の形式は変更しない。

### 表示と判定

- 候補選択は次の順に行う。①索引の自治体・タイル bbox で検索半径と交差するタイルを
  読み込む。屋根と輪郭は `bldg/` の索引で都市アウトラインの検索半径と照合する。壁は
  `walls/` の索引（詳細壁の張り出しを含む bbox）で壁半径と照合し、該当タイルの壁だけを
  読む。都市・タイルの各段で、`bldg/` 側の範囲と壁の範囲の和集合を使う。
  ②既存の建物の重複排除と高さ条件を適用する。③輪郭の観測点包含を判定し、詳細壁のある
  建物は壁 bbox で壁半径外を粗く除外したうえで壁面までの正確な水平距離を求める。
  壁がない建物は既存の輪郭による判定を使う。bbox は絞り込み用であり、最終距離ではない。
  ④距離による除外・フェードと、壁の描画を行う。索引上の都市範囲だけ先に旧 bbox のまま
  判定するとタイルに到達する前に漏れるため、都市・タイル両方を更新する。
- 現行の `max_candidates` は屋根線の候補に適用され、壁の生成には直接適用されない。
  この性質を維持し、屋根線が間引かれた建物の詳細壁を候補から落とさない。都市アウトライン
  の検索半径は壁半径の上限である。壁半径0では詳細壁の生成を行わない。
- CityGML の LOD2 壁は既に3Dポリゴンである。利用可能な建物ではその壁ポリゴンを
  描画の入力とし、既存の平面輪郭と高さから垂直壁を生成する処理をスキップする。
  屋根から壁を生成する処理は現行実装にはなく、過去の比較試作のみである。詳細壁が
  ない、または建物単位で利用できない場合に限り、従来の近似壁を生成する。
- 詳細壁は頂点の標高を直接使い、観測地点標高との差を取る。建物代表点 DEM を重ねて
  足さない。既存の屋根と同じ基準を使うが、DEM と CityGML の誤差で地面や近似壁と
  隙間が生じ得る。観測地点の DEM が取得不能な場合の既存フォールバックも確認する。
- 候補の bbox は詳細壁を含める。距離・フェードは、詳細壁を使う建物について壁面の
  水平投影までの最短距離を使う。垂直壁の線分だけでなく、傾斜・水平に近い面の内部、
  凹形を考慮し、穴は無視する。詳細壁のない建物は既存の輪郭辺距離を維持する。建物ごとに同一の
  フェードを用い、最短距離5 m未満は従来どおり除外する。観測地点を含む建物は現行の
  輪郭による除外を維持しつつ、詳細形状が輪郭外に張り出す場合の安全な扱いをテストする。
- 詳細壁の水平投影が観測点を覆う場合は距離0とし、現行の5 m未満の除外を適用する。
  これは上空に張り出した壁でも建物全体が除外され得る保守的な扱いで、実地点の見た目を
  確認する。輪郭内の判定は従来どおり先に行う。投影が線分に退化する垂直壁では、面の
  投影領域ではなく線分までの最短距離を使う。穴は描画と同様に無視する。
- 元ポリゴンを3D空間から Alt/Az に変換し、投影誤差や視野クリッピングを扱うために
  必要な場合に限って面や辺を細分する。凹形の描画に三角形分割が必要かは、描画
  方式を比較して決める。分割する場合は局所3D面内で行い、凹形を保つ。穴は塗りつぶす。投影誤差、
  視野端、方位0/360度、天頂を検証する。現行の約2 m分割は比較の出発点であり、
  面数制限と品質は測定に基づき調整する。必要な処理に失敗した建物は近似壁へ戻す。
- 既存の矩形壁向け完全遮蔽判定を詳細壁に適用しない。詳細壁を他の壁の遮蔽判定に
  使うことも、正しさを検証するまで行わない。不確かな場合は残す。既存の単色マスクと
  不透明度の合成を維持し、面や三角形の重なりで濃くしない。半解像度描画を初期値とする。
- GUI と静止画の通常経路で適用し、壁半径0、都市アウトライン無効、半径上限、観測地点を
  含む建物の既存動作を維持する。replay は対象外。

## 実装前後の検証

1. 異なる自治体・整備年度の LOD2、穴・参照・BuildingPart・LOD3併存を含む実例を追加調査し、
   上記の未対応方針と基準を確定する。サンプル1タイルで全国的な互換性を主張しない。
2. 単体試験で複数ポリゴン、穴を塗りつぶす扱い、凹形、傾斜、ほぼ水平、無効・欠損、参照、LOD混在、
   親子、頂点順序、建物単位のフォールバック、壁 bbox と距離、標高、遮蔽・合成を検証する。
3. 旧・新キャッシュ、offline、元データなし、更新失敗と中断、GUI/静止画の設定を検証する。
4. 東京タワーの土台・脚・展望台を従来と比較し、通常建物も確認する。変換時間、面数、
   容量、初回表示、視線移動の応答とメモリを計測する。性能上の制限は計測後に定める。
5. 実装確定後、ユーザー向けの `docs/specification.md`、内部の `docs/design.md`、
   公開時の `release-notes.md` をそれぞれ更新する。現行設計書の LOD2 壁対象外という
   記述は実装が変わるまで現状の説明として残す。
