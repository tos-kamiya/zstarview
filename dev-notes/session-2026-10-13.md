# Session: 2026-10-13

Scope: Make cache history retention a persistent, bounded user setting.

- Topic: Configurable cache history retention
  - Decision: Store one retention-hours setting in `config.json`, expose it in
    the startup dialog's General tab, and apply it to cloud, aircraft,
    satellite, Geo-satellite, and `--place` launch history cleanup. Use a
    24-hour default and clamp values to 1 through 720 hours.
  - Rationale: One saved value keeps the related history stores aligned while
    preserving separate live freshness and stale-fallback behavior.

Session summary: Added a saved cache retention setting with a 1-hour minimum,
24-hour default, and 30-day maximum. Updated user and design documentation.
Tests were not run.

    that window. Preserve separate satellite freshness and stale-fallback rules.
  - Rationale: A longer history setting should extend the past-time range in
    which current live layers remain available, as requested.

Session summary: Connected the configured cache retention to the regular GUI
live-overlay window and updated the specifications. No tests were run.

- Topic: Explicit CLI command for cache retention
  - Decision: Add `zstarview --set-cache-retention-hours HOURS` as a persistent
    configuration command that accepts 1 through 720 hours, saves to
    `config.json`, and exits without opening the GUI.
  - Rationale: A command with an explicit `set` verb makes the persistent
    effect clear and keeps the setting separate from one-shot startup options.
