  - Decision: Keep the feature list entry focused on visible behavior and remove implementation/control details such as startup opacity, GUI toggling, and cache reuse.
  - Rationale: The `Features` section should stay scannable. Those details are lower-level controls or implementation notes rather than the core capability being advertised.

- Topic: Reorder README features around visual layers first
  - Decision: Reordered the feature bullets to present visible layers first in this order: celestial layers, satellite clouds, aircraft, urban outlines, terrain horizon, and guide overlays; CLI interaction and Python support follow afterward.
  - Rationale: This makes the section read like a layered rendering stack instead of mixing scene content, overlays, controls, and runtime support in one sequence.

  - Decision: Applied the same aircraft-overlay simplification and layer-first feature ordering to `README_ja-JP.md`, including consolidating guide-related items into one bullet.
  - Rationale: The English and Japanese READMEs should describe the same product structure and avoid drifting in emphasis or detail level.

- Topic: Mention sixel-capable terminal export in the feature list
  - Decision: Added a `zstarview-export-image` feature bullet immediately before Python support in both READMEs, describing headless image export and direct display in sixel-capable terminals.
  - Rationale: This is a user-visible CLI capability and belongs with the non-layer usage features near the end of the list.

  - Rationale: The PyPI page should present the same visual story and screenshot sequence as the repository README even though its links must target GitHub URLs.

- Topic: Skip incomplete Himawari ISatSS slots when selecting the latest cloud source
  - Decision: Updated the Himawari provider to reject a newly listed slot when its key count is still below the product's expected tile count, and fall back to the next older 10-minute slot instead.
  - Rationale: NOAA's Himawari S3 prefix can become visible before all tiles for a timeslot are published. Treating any non-empty prefix as complete caused Japan-visible scenes to regress from full coverage to 0% when a partially published newer slot replaced a stable older one.

- Topic: Bump the application version for the follow-up fix release
  - Decision: Increased the package version from `1.4.0` to `1.4.1` in `src/zstarview/__about__.py`.
  - Rationale: The Himawari incomplete-slot fix changes runtime behavior and should ship as a distinct patch release.

- Summary: Updated README variants for clearer feature/screenshot presentation, fixed Himawari cloud-source selection to skip incomplete latest slots, added a regression test, and bumped the app version to `1.4.1`.
