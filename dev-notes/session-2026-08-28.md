# Session 2026-08-28

Scope: Compare the Okayama north-facing cloud rendering with B13 only versus B13+B16.

- Topic: Okayama B13/B16 visual comparison
  - Decision: Use Okayama city center (34.6551, 133.9195), north azimuth 0 degrees,
    altitude 35 degrees, and a 600x600 output for both variants.
  - Result: Reused the same B13 source slot (2026-08-27 14:50 UTC), built one
    `b13-only-v1` grid and one `b13-b16-v2` grid, and exported both cloud layers.
    B16 changes the cloud mask/alpha in 12,880 pixels; the scene is sufficiently
    cloudy that the visual difference is subtle in the full layer.

- Topic: Comparison rendering correction
  - Decision: Match the GUI's `halftone2` renderer and `-A5 -Zn` view instead of
    using the diagnostic all-cell circle renderer.
  - Rationale: The all-cell renderer overlaps nearly every projected cell and
    incorrectly appears as a solid cloud disc. The GUI uses sparse quantized
    dots, which matches `shot1.png` and exposes the B16 comparison properly.
  - Result: Regenerated the two PNGs from cached 2026-08-27 14:50 UTC B13/B16
    data because the exact 15:10 UTC slot was not locally available and network
    access was unavailable.

- Topic: Increase B13/B16 shell redistribution for visual experiment
  - Decision: Raise `MAX_REDISTRIBUTION_STRENGTH` from `0.30` to `0.60` and
    update the specification/design references and regression expectation.
  - Result: Generated the 60% comparison set under
    `generated/okayama-b13-b16-60/`; targeted B13/B16 tests passed (4 tests).

- Topic: Broaden cloud shells
  - Decision: Change the default display shells to 3 through 10 km at 1 km
    intervals. Preserve the 5 km-centered legacy emphasis while adding small
    weights in the intervening and upper layers; keep B16 redistribution anchored
    on the nearest 5 km shell and route toward the nearest 3/7 km shells.
  - Result: Generated the comparison set under `generated/okayama-shells-3-10/`.
    Targeted grid and B13/B16 tests passed (17 tests).

- Topic: Restore conservative B13/B16 redistribution
  - Decision: Return the maximum redistribution strength from 60% to 30% while
    retaining the 3〜10 km, 1 km interval shell layout.
  - Result: Regenerated the comparison set under
    `generated/okayama-shells-3-10-30/`; targeted tests passed (17 tests).

- Topic: Implement three rendering groups over nine internal shells
  - Decision: Compute 3〜11 km at 1 km intervals, aggregate 3〜5, 6〜8, and
    9〜11 km into the existing low/middle/high `shell_amounts`, and apply B16
    redistribution after aggregation between those three groups.
  - Rationale: This preserves the established three-layer visual compositor
    while adding within-group height width; the 3/5/7 labels remain compatibility
    names until the visual result is reviewed.
  - Result: Targeted cloud/grid/hatch tests passed (45 tests), and comparison
    images were regenerated under `generated/okayama-shell-groups-3-11/`.

- Summary: The nine internal shells and three-group aggregation are now in the
  normal zstarview path, not only the comparison script. The GUI compositor
  receives three grouped fields, while B13/B16 sampling and redistribution are
  performed before that grouping. Targeted tests passed; a broader Qt test run
  later aborted in an existing offscreen Qt test process after many tests.

- Topic: Earth guide LOD implementation
  - Decision: Add four bundled Earth guide JSON assets and select them from
    `ScreenGeometry.radius` at 350, 700, and 1050 px boundaries. Force LOD 0
    whenever `fast_mode` is active.
  - Implementation: Reused the Natural Earth octilinear generator with
    tolerance/minimum-area pairs `2.0/8.0`, `1.4/4.0`, `0.9/2.0`, and
    `0.5/1.0` for LOD 0 through LOD 3. The generated payloads contain 486,
    571, 785, and 1413 total ring points respectively.
  - Rationale: Static LOD payloads restore additional island/coastline detail
    on large circular viewports without doing geographic simplification during
    rendering. The fast path remains deterministic and low-cost.
  - Validation: `tests/test_earth_guide_render.py` passed (17 tests);
    related overlay tests passed (68 tests total); Ruff and compile checks
    passed.

- Topic: Equal within-group shell allocation
  - Decision: Set each 3 km-wide group's three internal shells to equal
    `1/3` weights, making each rendered group a height-uniform column.
  - Rationale: Preserve the group-level legacy appearance while removing an
    additional preference for one height inside each group.

- Topic: Cloud edge coverage on phase-shifted grids
  - Decision: Generate halftone cell centers in a small ring beyond the cloud
    content disc, sized from the grid spacing, while retaining the actual disc
    clip for the final image.
  - Rationale: Different grid phases can place the nearest cell center just
    outside the disc, leaving an artificial inward edge on some window sizes.

- Topic: Earth guide resolution policy
  - Decision: Document four static Earth guide LODs selected by
    `ScreenGeometry.radius` at 350, 700, and 1050 px boundaries. `fast_mode`
    always uses LOD 0; normal rendering selects LOD 0 through LOD 3 by radius.
  - Rationale: Larger circular display areas can benefit from additional
    coastline and island detail, while the fixed low-resolution fast path keeps
    viewport interaction and resize rendering responsive. The radius is a
    better measure than raw window width or height because the viewport is
    circular and its effective size depends on layout and view altitude.
  - Scope: Update the user-facing specification, internal design reference,
    and Earth guide data regeneration notes only. Do not change runtime code or
    bundled JSON in this documentation change.

- Summary: Implemented and committed the four-level Earth guide LOD policy and
  fast-mode override in commit `2431994f`.
