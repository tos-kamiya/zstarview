  - Result: updated `docs/specification.md`, `docs/design.md`, and `docs/implementation-history.md`; no code changes were made yet.

  - Decision: keep `enlarge_moon` and hovered moon rendering filled even when `outline_bright_bodies` is enabled.
  - Rationale: the outline-only mode should suppress the ordinary bright-body footprint, but an explicit moon enlargement is a detail view and should preserve the rendered moon phase.
  - Result: reflected the revised rule in the specification and design docs, and updated the moon rendering path accordingly.

  - Decision: implemented `--outline-bright-bodies` across CLI parsing, GUI/export style propagation, star rendering, and solar-system rendering.
  - Rationale: the feature needed to work consistently in both the GUI and headless export path, and the shared render pipeline is the right place to enforce the mode.

- Topic: bright-star outline visibility
  - Decision: when `outline_bright_bodies` is enabled, render the star layer at full resolution instead of using the usual downscaled star buffer.
  - Rationale: the low-resolution star buffer can visually thicken the outline and make it look filled after upscaling, especially with larger `star_base_radius` values.
  - Result: the outline-only stars now stay hollow in the current test sweep.

  - Result: star outline appearance was tightened without changing planet or moon rendering.

- Topic: enlarged moon in outline mode
  - Decision: let `enlarge_moon` and hovered moon rendering use the normal filled moon artwork even when `outline_bright_bodies` is enabled.
  - Rationale: the outline-only mode should reduce footprint for ordinary bright bodies, but the enlarged moon view is explicitly meant to show the rendered moon, not a hollow marker.
  - Result: moon enlargement now bypasses the outline-only fallback while the rest of the outline-only behavior remains unchanged.
- Topic: bright-bodies mode rename
  - Decision: replace the boolean `--outline-bright-bodies` flag with `--bright-bodies {outline,fill}` and remove the legacy flag entirely.
  - Rationale: the actual requirement is a two-state rendering mode, and the enum-style option makes the default `outline` state explicit without overloading boolean semantics.
  - Result: the specification and design now describe `--bright-bodies` as the public option name and `outline` as the default mode.
