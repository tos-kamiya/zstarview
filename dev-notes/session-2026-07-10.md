# Session 2026-07-10

Scope: Rebuild object-viewer background separation from `df74f0f8`.

- Topic: Split scenic and object-viewer CLI arguments
  - Decision: Keep location, time, search, star, and overlay arguments in shared parser helpers, while registering sky-disc and night-light arguments only for the scenic viewer.
  - Rationale: The object viewer has a deliberately different presentation and should not expose controls for layers it disables. Its `-V` default and maximum are passed as parser configuration rather than hidden post-parse mutations.

- Topic: Object-viewer background isolation
  - Decision: Give the instrument presentation its own solid-background renderer instead of reusing the scenic radial background / window-border helper.
  - Rationale: The object viewer is intentionally flat and opaque, while scenic `zstarview` keeps theme-dependent chrome and gradients. Separate background code prevents object-viewer changes from leaking into scenic themes.

- Topic: Window border responsibility
  - Decision: Remove the theme-level outer-border flag and always draw the scenic window frame in `draw_window_border()`.
  - Rationale: Whether the frame is present is a presentation decision, not a theme decision. The theme should carry border color and chrome colors, while object-viewer uses its own rendering path to omit the frame entirely.

- Verification: `tests/test_object_viewer_profile.py` and `tests/test_viewer_startup_errors.py` passed (`10 passed`); Ruff and `git diff --check` passed. The full suite has two pre-existing failures in launch-profile JSON serialization and the theme error-message expectation.
