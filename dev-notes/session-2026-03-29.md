- Topic: Remove Pillow from the cloud runtime path
  - Decision: Change cloud rendering to produce `numpy` RGBA buffers instead of `PIL.Image`, and convert those buffers directly to `QImage` in the GUI/export layers.
  - Rationale: The cloud pipeline already computes pixel values in `numpy`, so using Pillow there only added an extra image wrapper and conversion step. Returning RGBA arrays keeps the cloud path lighter while preserving Qt integration.
  - Alternatives Considered: Replacing Pillow with another image library would add dependency churn without simplifying the pipeline; converting only part of the path would still leave the cloud runtime dependent on Pillow.

- Topic: Keep splash error visible on startup location failures
  - Decision: Move launch location resolution inside the startup `LaunchSetupError` handling block so location lookup failures use the same splash-delay path as other setup errors.
  - Rationale: A mistyped city name should leave the splash error visible briefly instead of bubbling out as an uncaught exception and terminating immediately.
  - Alternatives Considered: Handling `LocationResolveError` separately would duplicate startup cleanup and make the failure paths diverge again.

- Topic: Start removing Pillow from moon rendering
  - Decision: Change moon phase generation to return `numpy` RGBA buffers and draw the moon through `QImage` plus painter transforms instead of rotating a Pillow image.
  - Rationale: This keeps the moon path aligned with the newer cloud path and removes another runtime dependency edge on Pillow without changing the rendered result intentionally.
  - Alternatives Considered: Keeping the Pillow rotation path would be simpler short-term but would block further runtime dependency reduction.

- Topic: Move runtime Qt image helpers out of `utils/qt.py`
  - Decision: Split NumPy/QImage conversion helpers into `render/qt_image.py` and leave `utils/qt.py` for Pillow compatibility helpers only.
  - Rationale: The runtime render/export path should import the Qt/NumPy helpers directly without pulling in a mixed utility module that also carries optional Pillow glue.
  - Alternatives Considered: Keeping everything in `utils/qt.py` would still work, but it hides the runtime dependency boundary and makes future cleanup harder.

- Topic: Keep cloud layer state in NumPy until final draw
  - Decision: Change the cloud image state, export-image cloud fetch path, and cloud missing-mask path to keep `numpy` arrays as the stored/intermediate representation, converting to `QImage` only at the final composition output.
  - Rationale: The earlier path converted cloud RGBA data and missing masks into `QImage` eagerly, only to convert them back to `numpy` during hatching, masking, and compositing. Holding cloud data as `numpy` avoids those round-trips, removes unnecessary 4-channel expansion for the missing mask, and keeps GUI and export-image on the same representation.
  - Alternatives Considered: Keeping only the missing mask as `numpy` would help a little but still leave the main cloud image bouncing between `QImage` and `numpy`; replacing the cache with direct `QImage.bits()` sharing would be more brittle in PySide and harder to reason about safely.
