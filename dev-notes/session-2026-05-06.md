# Session 2026-05-06

- Scope: Investigate and fix transient stretched disc rendering during window resize.
- Focus: Confirm whether resize handling leaves stale sky/cloud disc images alive long enough for Qt to stretch them into an ellipse before the next repaint.

- Summary:
  - Fixed resize handling so the previous sky/cloud disc images are discarded immediately before the next repaint, preventing the old cached image from being stretched across the new aspect ratio.
  - Added a regression test that exercises `_handle_client_resize()` and verifies stale disc images, compositor cache state, and repaint requests are all refreshed on resize.
  - Validation: `uv run -p .venv/bin/python pytest tests/test_window_render_sync.py`, `uv run -p .venv/bin/python ruff check src/zstarview/gui/window.py tests/test_window_render_sync.py`.
  - Commit/push: not performed.

  - Decision: Changed the default `--sky-disc-style` value from `grid` to `smooth` across CLI parsing, GUI defaults, worker fallbacks, and export-image fallbacks.

  - Summary: Updated the CLI help/defaults, README tables, specification text, and the CLI default regression test.

  - Summary: Introduced `src/zstarview/debug_timing.py` and wired it into the render/update paths with timestamped, sequential log lines.
  - Validation: `uv run -p .venv/bin/python ruff check src/zstarview/debug_timing.py src/zstarview/render/earth_guide.py src/zstarview/gui/window_render.py src/zstarview/gui/window_updates.py`

- Topic: Present-frame cache key experiment
  - Decision: Temporarily removed `status_message` from the `present_frame` cache key.
  - Rationale: The earlier logs showed that cloud/status text changes were forcing repeated `present_frame` rebuilds during startup. Excluding the message lets us test whether those rebuilds were contributing to the darkening.
  - Summary: Kept the rest of the present-frame cache key unchanged and left the timing logs in place to compare hit/miss behavior after the change.
  - Validation: `uv run -p .venv/bin/python ruff check src/zstarview/gui/window_render.py`, `uv run -p .venv/bin/python pytest tests/test_window_render_sync.py`

- Topic: Stabilize overlay cache keys
  - Decision: Switched satellite and aircraft overlay stamps in the present-frame cache key from list identity to tuple-of-content stamps.
  - Rationale: The debug output showed that overlay lists were being replaced with new list objects even when the rendered content was effectively the same, which was forcing unnecessary present-frame rebuilds.
  - Summary: Kept the present-frame cache structure intact, but made the overlay portions content-based so stable overlay content no longer invalidates the cache.
  - Validation: `uv run -p .venv/bin/python ruff check src/zstarview/gui/window_render.py`, `uv run -p .venv/bin/python pytest tests/test_window_render_sync.py`

- Topic: Re-run the experiment without ground tint
  - Decision: Removed the ground tint overlay again so the next comparison can isolate whether the earth guide darkening only disappears when that fill is present.
  - Rationale: The current hypothesis is that the ground tint was masking a compositing issue rather than fixing it. Running without it makes any residual accumulation easier to see.
  - Summary: Restored the no-ground-fill path in the compositor and reverted the affected compositor regression tests to expect unfilled terrain-horizon output.
  - Validation: `uv run -p .venv/bin/python ruff check src/zstarview/gui/composite.py tests/clouddisc/test_cloud_missing_overlay.py`, `uv run -p .venv/bin/python pytest tests/clouddisc/test_cloud_missing_overlay.py tests/test_window_render_sync.py`

- Topic: Reset under earth guide instead of tinting ground
  - Decision: Keep ground tint disabled and instead clear the disc below the earth guide back to the theme background color before drawing the guide.
  - Rationale: The user-visible darkening was masked by the old ground tint, but the root issue is accumulated compositing. Reinitializing the lower disc preserves the no-tint behavior while preventing the guide from darkening over repeated repaints.
  - Summary: Added a neutral ground-reset pass in the compositor, threaded the theme background color through the sky pipeline, and added a regression test that verifies the lower disc is restored to the background color.
  - Validation: `uv run -p .venv/bin/python ruff check src/zstarview/gui/composite.py src/zstarview/render/pipeline.py tests/clouddisc/test_cloud_missing_overlay.py`, `uv run -p .venv/bin/python pytest tests/clouddisc/test_cloud_missing_overlay.py tests/test_window_render_sync.py`
