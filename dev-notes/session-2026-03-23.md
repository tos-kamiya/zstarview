# Session 2026-03-23

- Scope: Remove an unused render-pipeline wrapper and keep tests aligned with the runtime API split.

- Topic: Handle `render_scene_into_painter` that was only used by tests
  - Decision: Remove `render_scene_into_painter` from `src/zstarview/render/pipeline.py` and update the sync test to call `render_base_scene_into_painter` and `render_hud_overlay_into_painter` directly.
  - Rationale: The application runtime already uses the split base/HUD rendering entry points in `window_render.py` and `export_image.py`. Keeping an extra wrapper that is unused outside tests adds dead API surface and weakens the signal of which entry points are actually supported.

- Topic: Remove additional test-only helper APIs
  - Decision: Delete `CloudDisc.render_now`, `HimaProvider.fetch_bt_c13_from_local_dir`, `is_satellite_visible`, and `make_hatch_tile_qimage`, then rewrite tests around the remaining fetch/render and satellite-selection primitives.
  - Rationale: These call points were not used by the application runtime and mostly duplicated behavior already exposed through `fetch_source` plus `render_from_source`, `visible_satellites`, or lower-level helper paths. Removing them reduces dead surface area without changing production call flows.

- Topic: Reduce noisy satellite cache-miss stack traces in GUI startup logs
  - Decision: Treat expected satellite fetch misses such as `future view is not supported` and `no cached orbital elements within validity window` as non-warning availability failures inside `SatelliteController`, and preserve the specific failure message when every enabled satellite group fails.
  - Rationale: These cases are already handled in the controller and should not look like uncaught exceptions. The previous `warning(..., exc_info=True)` made normal cache-miss scenarios look like crashes and hid the useful failure reason behind a generic `failed to fetch orbital elements` banner.

- Topic: Drop artificial satellite support for time-shifted views
  - Decision: Change the policy so artificial satellites are available only for realtime views, and remove the satellite archive cache layer entirely.
  - Rationale: The current CelesTrak group API path only exposes current group snapshots. Realtime-only behavior is simpler, matches the upstream data source honestly, and avoids implying historical orbital snapshots that the app cannot fetch on demand.
