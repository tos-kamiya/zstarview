- Scope: Review the existing planetarium CLI and `nominatim_search.py`, then define a specification for location search by place/station names without starting implementation.

- Topic: CLI location search by place or station names via Nominatim
  - Decision: Keep the existing positional `location` argument and add an explicit opt-in resolver path for online search, rather than silently changing current city-name behavior.
  - Rationale: Current `location` resolution is offline-first with GeoNames, viewpoint datasets, and lat/lon parsing. Replacing that behavior would change existing matches, introduce network dependency into normal startup, and make last-location persistence less predictable. An explicit online path preserves compatibility while still enabling station/place lookup.
  - Alternatives Considered: Full replacement of city-name resolution with Nominatim was rejected for now because it broadens the meaning of existing inputs and couples default startup behavior to network availability and Nominatim policy constraints.

- Topic: Nominatim result selection, display, and persistence
  - Decision: `--place` uses the first normalized Nominatim candidate for startup, prints all matched candidates to the terminal when there are multiple, shows failures on both terminal and splash, keeps the long `display_name` as the GUI-visible location string, and persists Nominatim-resolved locations as a tagged object containing the raw result JSON.
  - Rationale: The app remains non-interactive at startup while still exposing ambiguity to the user. Keeping the full display name helps users notice mismatches. Persisting the resolved object avoids re-querying on next launch and preserves the exact selected place instead of a potentially unstable free-form query.
