# Session 2026-08-18

- Topic: Confirm GMN meteor trail refresh cadence
  - Decision: Document the behavior as hourly GUI refresh checks, while
    actual per-file network refetches occur only after the six-hour cache TTL;
    failed updates retry after ten minutes.
  - Rationale: The scheduler and meteor cache design distinguish checking for
    updates from downloading each cached GMN distribution file.

- Topic: Confirm startup GMN cache check
  - Decision: When meteor trails are enabled, schedule the first background
    meteor update immediately after startup initialization. The repository
    checks cached timestamps and refetches stale index or daily files.
  - Rationale: Startup sets `meteor_next_refresh_utc` to the current time;
    the normal scheduler then invokes the worker without waiting an hour.

- Topic: Confirm six-hour GMN TTL rationale
  - Decision: Treat the six-hour TTL as matching GMN's stated publication
    cadence, not as a value derived from an explicit API rate limit.
  - Rationale: The development record notes that GMN publishes updates every
    six hours and publishes no explicit request-rate limit; the TTL reduces
    redundant requests while tracking source freshness.

- Topic: Adjust schematic precipitation mark visibility
  - Decision: Reduce the precipitation tile line width to approximately one
    third of the previous `2.6 px` base width and double the precipitation
    line alpha, clamping the result to 255.
  - Rationale: The precipitation display was confirmed at a wet coordinate,
    and the marks should be less visually heavy while remaining easier to see.

- Topic: Scale precipitation line spacing with tile size
  - Decision: Set the parallel-line spacing to `0.25` times the square tile
    side, multiplied by the viewer line-width scale, instead of using a fixed
    pixel spacing.
  - Rationale: Fixed spacing made the two lines in the small observer tile
    resemble the outline of a thick line. Proportional spacing preserves the
    same visual relationship between lines and tile size at every distance.

- Topic: Scale precipitation line width with tile size
  - Decision: Derive the solid line width from `0.0325` times the tile side,
    multiplied by the viewer line-width scale, with a small rendering floor.
  - Rationale: Line width and spacing now share the tile's visual scale, so
    the schematic mark does not change character as distance changes.

- Topic: Replace the observer mark with a nearer sunflower sample
  - Decision: Remove the observer-only precipitation primitive and use the
    existing 48-point golden-angle layout from `0 km` to `32 km` instead of
    querying a separate observer point.
  - Rationale: The nearest normal sample can reuse the same model value at the
    available data resolution, while keeping tile size, spacing, and line
    count consistent across the entire display.
