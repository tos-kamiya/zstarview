- Topic: Spacecraft search labeling and Horizons-backed target expansion
  - Decision: Treat JWST, Voyager 1, Voyager 2, Parker, Europa Clipper, Lucy, Psyche, JUICE, Solar Orbiter, and BepiColombo as JPL-backed spacecraft with a fixed `Spacecraft` search-result label. Keep `ISS` as the only `Satellite` search label and the only app-side satellite resolution path.
  - Rationale: The requested new artificial objects use the same Horizons-backed spacecraft model as the existing non-ISS objects. A fixed label prevents confusing spacecraft with satellites, small bodies, boosters, or same-name mission targets in search results while preserving the existing ISS-specific TLE/OMM path.
  - Alternatives Considered: Reusing `Satellite` for all artificial objects was rejected because it hides the data-path distinction and is misleading for interplanetary probes and space telescopes. Allowing raw JPL result labels was rejected because names like Lucy and Psyche can resolve to ambiguous non-spacecraft records.

- Topic: Horizons spacecraft request pacing
  - Decision: Allow Horizons-backed spacecraft to appear progressively after startup by processing Horizons requests through a queue with at least 30 seconds between requests. Use fresh or stale cache immediately when available, and update the overlay as each queued spacecraft request completes.
  - Rationale: The expanded target list can otherwise create a burst of lookup/vector requests that may trigger transient JPL server errors. A gradual queue keeps the UI responsive, avoids blocking other layers, and makes a 10-minute startup fill-in acceptable for optional spacecraft markers.
  - Alternatives Considered: Fetching all spacecraft in parallel was rejected because it increases load and observed transient failures. Waiting for all spacecraft before showing the layer was rejected because it would hide valid cached or early successful targets.
