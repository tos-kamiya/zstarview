# Session 2026-09-06

Scope: investigate a second GUI segmentation fault during tropical-cyclone
overlay refresh after native astronomy work was serialized.

- Topic: Second SIGSEGV location
  - Finding: The crash occurred in Python 3.14.7 while
    `TropicalCycloneController._cache_payload()` converted polygon data to
    nested Python lists. No NumPy, Astropy, or Skyfield frame appears in the
    Python traceback for that worker.
  - Finding: The GUI render thread was concurrently in Qt/Python HUD label
    rendering, while another pool thread was waiting in the executor. The fault
    handler reported that the current worker was garbage-collecting.
  - Result: This is not evidence that the previous meteor lock failed, nor
    proof of the same NumPy race. It points instead to a broader native
    extension or CPython/GC interaction. Prior heap corruption is a hypothesis,
    not an established finding.

- Topic: Process-isolation redesign handoff
  - Decision: Document a staged redesign in
    `handoff-process-isolation-2026-09-06.md`; do not implement it yet.
  - Rationale: Include independent threads and scientific calculations in
    rendering paths, not only the shared executor. Separate fault containment
    from unconfirmed root-cause claims. The existing cloud worker uses pickle
    artifacts as well as JSON and needs an explicit migration adapter.
  - Validation: Reviewed current process/thread entry points and checked the
    documentation diff. No runtime changes or tests were performed this turn.

Summary: Created the implementation handoff and clarified diagnostic uncertainty.

- Topic: First process-isolation implementation slice
  - Decision: Add `zstarview.processes` with a versioned JSON request/result contract
    and a non-blocking supervisor that keeps one running request plus the newest
    pending request. Do not connect existing GUI controllers yet.
  - Rationale: This isolates the failure/recovery contract from Qt and from the
    unconfirmed crash cause. It provides a small, testable boundary before moving
    cyclone conversion or astronomy work out of the GUI.
  - Validation: `pytest tests/test_process_isolation.py tests/test_application_services.py tests/test_worker_pool.py` passed (7 tests); Ruff and `git diff --check` passed.

Summary: Added the first process-isolation foundation and its failure-mode tests.
No commit, tag, or push. Follow-up: connect the protocol to cyclone acquisition only
after reviewing stale-result handling and artifact retention policy.

- Topic: Tropical cyclone process migration
  - Decision: Connect normal `TropicalCycloneController.update()` calls to a dedicated
    `python -m zstarview.tropical_cyclones.worker` subprocess. The worker owns HTTP,
    cache access, and snapshot/polygon dictionary conversion; the GUI receives only a
    validated JSON payload artifact. Keep `_run_update()` temporarily for comparison
    and existing direct unit tests.
  - Rationale: Tropical cyclone polygon conversion was the smallest practical first
    production migration unit. It removes that conversion from GUI worker threads
    without introducing pickle or Qt objects across the process boundary.
  - Validation: Added an end-to-end worker artifact test; related tests passed (35);
    full suite passed (1661); Ruff and `git diff --check` passed.
  - Follow-up: Add bounded artifact retention and controlled worker restart policy
    before migrating another controller.

- Topic: Cyclone worker lifecycle hardening
  - Decision: Add explicit artifact release after GUI consumption, bounded retained
    job directories, and retry of worker exit/timeout only. Cyclone uses at most two
    restarts with backoff; invalid manifests and ordinary worker failures remain
    terminal.
  - Rationale: A successful process boundary is incomplete if payload directories
    grow without bound or a transient child crash leaves the latest request stalled.
    Retrying ordinary fetch failures would obscure service failures and add needless
    traffic.
  - Validation: Added restart and retention tests; related tests passed (37).

- Topic: Remove the legacy cyclone GUI worker path
  - Decision: Delete `TropicalCycloneController._run_update()` and its shared
    `ApplicationServices` executor usage. Keep the `services` constructor argument
    temporarily as a compatibility no-op for callers that construct all controllers
    through the shared window setup.
  - Rationale: The process boundary is now the only normal cyclone update path;
    retaining the old implementation would leave an untested duplicate that could
    accidentally reintroduce GUI-side network and polygon conversion work.
  - Validation: Added a QCoreApplication integration test covering QTimer polling,
    subprocess result loading, signal delivery, and shutdown. Related tests passed
    (38); full-suite validation follows.
