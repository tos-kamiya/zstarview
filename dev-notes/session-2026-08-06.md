# Session 2026-08-06

Scope: Investigate the report that zstarview's sunset colors begin later than the real sky.

- Topic: Sunset color appears late in real-time viewing
  - Finding: The Sun marker is refreshed by the lightweight dynamic-planet path about every 2 seconds, while the sky-color disc is generated as part of the heavy sky snapshot on the default 60-second schedule. The atmospheric model itself does produce sunset colors below the horizon, but the displayed disc can retain the prior sun altitude until the next snapshot (and longer if the worker is busy).
  - Implication: The primary issue is stale sky-disc input/update cadence, not the astronomical Sun position calculation. A future fix should decouple a lightweight twilight/color adjustment or interpolation from the heavy sky-disc regeneration rather than simply moving the Sun marker.

- Topic: CAMS access and licensing
  - Finding: ADS/CAMS data are free and open subject to accepting the relevant dataset licence. Programmatic access uses a CDS account/API credentials; dataset licences must be accepted through the ADS web interface before API retrieval. ADS resource limits are dynamic and dataset-specific, with requests queued when limits are exceeded; the current documentation lists per-dataset field and volume limits rather than a universal requests-per-minute quota.
  - Implementation implication: Use narrow single-point/nearby-cell requests, cache results locally, never embed a developer API key in a distributed client, and fall back to a fixed profile when the user has no credentials or the service is unavailable. Include the required CAMS attribution and modified-data disclaimer in user-facing documentation.

- Topic: CAMS refresh and unavailable-data fallback
  - Decision: The normal distributed application will bundle a compact global approximately 80 km, monthly AOD550 climatology extracted from CAMS. It will not require users to create an account or configure API credentials. If the bundled asset is unavailable or invalid, use a slightly clean-air fixed profile. Keep live CAMS retrieval as an optional future advanced path with the previously defined hourly throttle and 24-hour stale fallback.
  - Rationale: Requiring CAMS credentials would make the normal application inconvenient. A compact derived climatology preserves regional and seasonal variation without runtime network dependency or large raw CAMS files; the clean fallback keeps the application usable if the asset is unavailable.

- Topic: CAMS climatology preparation sample
  - Decision: Use the CAMS EAC4 monthly reanalysis for the preparation sample. Its ADS regular grid is approximately 0.75 degrees / 80 km, so the sample must not present it as native 40 km data. The script downloads only total AOD550 for a selected year range and renders calendar-month maps from the local NetCDF.
  - Rationale: The monthly reanalysis is appropriate for a static climatology and avoids bundling forecast fields. Keeping the download path separate from rendering allows the user to authenticate locally without placing credentials in the repository.

- Topic: CAMS archive contains two NetCDF files
  - Finding: A successful ADS request returned both `data_allhours_sfc.nc`
    (`marsStream: moda`) and `data_byhour_sfc.nc` (`marsStream: mnth`).
  - Decision: Select `data_allhours_sfc.nc` automatically for the monthly
    climatology and continue extracting it to the conventional `.nc` path.
  - Rationale: `moda` is the monthly mean of daily means and is the suitable
    product for a static calendar-month climatology; the previous single-file
    assumption incorrectly treated the valid multi-product archive as an
    error.

- Topic: Build the bundled CAMS climatology asset
  - Decision: Keep the downloaded ZIP, selected source NetCDF, and generation
    scripts under `raw-data/cams/`; place only the compressed twelve-month
    `aod550` array under `src/zstarview/data/aerosol/`.
  - Rationale: This keeps reproducibility materials separate from the
    distributable asset. The package asset is approximately 4.6 MB instead of
    shipping the approximately 74 MB source NetCDF.
