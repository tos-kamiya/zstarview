# Session 2026-06-15

Scope: Trial a two-layer street-light appearance by stacking a half-height copy of each night-light band.

- Topic: Night-light two-layer preview
  - Decision: Keep the current night-light band geometry, but draw a second copy of each band with the same lower edge and half the height.
  - Rationale: This is a cheap way to inspect a softer stacked look before replacing the layered polygon renderer with a low-resolution float glow buffer.
  - Follow-up: If the look is acceptable, migrate the glow to an off-screen grayscale buffer and blur/tint it during compositing.

- Topic: Night-light three-layer refinement
  - Decision: Split the preview stack into three bands at 1/3, 2/3, and full height above the lower edge.
  - Rationale: This keeps the lower ridge boundary unchanged while providing a gentler brightness falloff than the earlier two-layer variant.

- Topic: Night-light four-layer refinement
  - Decision: Expand the stacked preview to four bands at 1.0, 0.75, 0.5, and 0.25 of the upper span.
  - Rationale: This is a small step toward a smoother graded look while keeping the current polygon renderer intact for comparison.

- Topic: Night-light off-screen glow design
  - Decision: Plan a low-resolution float glow buffer for street lights and ridge glow, then blur, tint, and composite it back into RGBA.
  - Rationale: The current stacked polygon path is useful for previewing shape, but a float mask is a better fit for smoother gradients, less banding, and future brightness scaling.

- Topic: GlowMask alpha-only
  - Decision: Keep the intermediate glow mask as alpha-only `float32` data instead of storing RGB in the buffer.
  - Rationale: The glow color can stay fixed at tint/composite time, while alpha preserves the continuous brightness field that needs smoothing and scaling.

- Topic: Ridge glow outer layer
  - Decision: Replace the outermost ridge glow hatch with a solid fill at half alpha.
  - Rationale: The hatch existed only to emulate a 50% fill. A plain fill makes the outer layer consistent with the other ridge glow bands and simplifies the eventual glow-mask rasterization path.

- Topic: GlowMask scale reduction
  - Decision: Reduce the glow mask resolution from quarter scale to eighth scale in both axes.
  - Rationale: A smaller mask should further soften the stacked glow preview and reduce the cost of rasterization before the final alpha blur and tint pass.

- Topic: Direct glow drawing removal
  - Decision: Stop drawing street-light and ridge glow directly at full resolution in the compositor; keep only the low-resolution GlowMask path.
  - Rationale: The direct path duplicates the glow content and fights the new off-screen blur/tint pipeline. Removing it makes the compositing flow easier to reason about and keeps the preview aligned with the intended final design.

- Topic: GlowMask scale restore
  - Decision: Restore the GlowMask scale from 1/8 back to 1/4 in each axis.
  - Rationale: The 1/8 mask softened the glow too aggressively and made the result look too dim. Returning to 1/4 keeps the off-screen blur path while preserving more of the original brightness.

- Topic: Glow base color lift
  - Decision: Use a brightness-maximized HSV base color for GlowMask tinting, and let alpha control the fade.
  - Rationale: Multiplying RGB by alpha before premultiplication was dimming the glow twice. Raising the tint color's value to the maximum preserves the intended color while keeping alpha as the single brightness control.

- Topic: Night-light coefficient cleanup
  - Decision: Remove the separate night-light coefficient constants for minimum brightness and minimum width scale, and inline the fixed values at the use sites.
  - Rationale: These values are no longer meant to be tuned independently; keeping them as named knobs suggested that they were still part of the public adjustment surface.

- Topic: Night-light opacity normalization
  - Decision: Divide the street-light opacity input by four inside the night-light renderer.
  - Rationale: The stacked 4-layer preview now overlaps at the brightest bands, so the user-facing opacity should be normalized before per-layer alpha is applied.

- Topic: Fast-mode glow skip
  - Decision: Skip the off-screen GlowMask path entirely when fast-mode is enabled.
  - Rationale: Fast-mode is intended to avoid extra compositing work, and the glow mask is a separate blur/tint pass that should not run in that mode.

- Topic: Ridge outer layer alpha cleanup
  - Decision: Replace the ridge glow layer scale coefficients with direct alpha values and set the outermost layer alpha to 0.05.
  - Rationale: The layer brightness is now intended to be expressed directly in the spec list, without an extra multiplier on the final layer.
