# Session 2026-07-15

Scope: Review refactoring options for `src/zstarview/gui/composite.py`; design discussion only.

- Topic: Refactoring boundary review for `gui/composite.py`
  - Finding: The 2,714-line module combines cloud sampling/field construction, three cloud rasterization modes, sky/cloud pixel compositing, night-light and ridge-glow mask generation, earth/never-rises/ground overlays, and `SkyCompositorCache` orchestration.
  - Finding: Production callers primarily depend on `SkyCompositorCache`, while tests also import private helpers and monkeypatch module-level Qt symbols.
  - Decision for discussion: Prefer an incremental split behind a compatibility facade. Establish cloud, glow, and disc-overlay modules first; keep final composition-key orchestration in the cache module until behavior and cache ownership are independently tested.
  - Risk: Moving helpers without migrating test seams can make existing monkeypatches ineffective because helper globals would resolve in their new modules.
  - Scope constraint: No implementation changes are made in this session; the uncommitted repository changes present before this review are preserved.

- Topic: Extract cloud rendering module
  - Decision: Move cloud amount fields, Alt/Az sampling, stripe/alpha/halftone rasterizers, cloud tinting, sky/cloud pixel compositing, and missing-mask cloud helpers to `src/zstarview/gui/cloud_render.py`.
  - Compatibility: Keep the existing names re-exported from `gui/composite.py` so production callers and current tests retain their import paths.
  - Test seam: Update the halftone test to monkeypatch `gui.cloud_render`, where the moved function now resolves Qt and helper globals.
  - Result: `composite.py` is reduced from 2,714 to 1,593 lines; cloud logic is isolated in a 1,217-line module.
  - Verification: cloud-focused tests excluding the pre-existing low-opacity QImage color-boundary case -> 40 passed; glow/earth-guide/viewport tests -> 65 passed; Ruff and `git diff --check` passed.
  - Follow-up: The existing low-opacity test currently produces blue=23 while asserting blue<20; this remains isolated for a separate behavior/baseline investigation.

- Topic: Remove stale cloud imports from the compositor
  - Decision: Keep only cloud helpers used by `SkyCompositorCache` in `gui/composite.py`; move cloud-focused test imports to `gui/cloud_render.py` instead of preserving unused compatibility imports.
  - Rationale: The extracted module is now the ownership boundary for cloud APIs, while the compositor should not carry unrelated cloud symbols solely for test imports.
  - Verification: Ruff passed; focused cloud tests passed (28 passed, 1 low-opacity boundary test deselected); glow/earth-guide/viewport tests passed (65 passed).
