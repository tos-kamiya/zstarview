- Topic: Default-argument audit for `is_in_fov_func`
  - Decision: Keep `is_in_fov_func` as an explicit parameter on the four terrain overlay helpers.
  - Rationale: The parameter is not dead surface area here. It controls the visibility gate for terrain horizon, secondary ridges, urban outlines, and water dots, and the tests intentionally override it to force fully visible paths. Removing it would only move the dependency injection to module-level monkeypatching and make the tests less direct.
  - Notes: If API reduction is still desired later, the safer follow-up would be to remove the parameter only after updating the tests to patch `zstarview.render.terrain.is_in_fov` consistently and confirming there is no external caller relying on the seam.
