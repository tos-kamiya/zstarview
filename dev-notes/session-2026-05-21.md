# Session 2026-05-21

- Topic: Aircraft debug snapshot save flow simplification
  - Decision: Replace the queued payload/QTimer snapshot path with a single pending output path stored on `SkyWindowCoreMixin`, then consume and clear it during paint.
  - Rationale: The prior deferred callback flow was hard to reason about and had stale-callback edge cases. Storing only the output path keeps the behavior aligned with "save on next update" and makes the code easier to verify.
  - Notes: Updated terrain regression tests to assert that the path is queued, saved, and cleared via the paint flush path.

- Topic: Remove unused overlay refresh aliases
  - Decision: Delete `refresh_projected_satellite_overlay` and `refresh_projected_aircraft_overlay`.
  - Rationale: They were thin wrappers with no call sites in the tree, so they added API surface without value. The active paths already use `reproject_satellite_overlay` and `reproject_aircraft_overlay`.

- Topic: Terrain ridge naming
  - Decision: Standardize the terrain naming pair to `terrain_horizon` for the primary line and `terrain_secondary_ridges` for the banded secondary layers.
  - Rationale: The pair now reads symmetrically and matches how the renderer treats the main horizon versus the distance-band ridge overlays.
  - Notes: Updated the state, render pipeline, controllers, export payloads, and regression tests to use the new names.

- Topic: Remove test-only direction hover wrapper
  - Decision: Delete `draw_direction_hover_guide` and keep the direction-hover coverage focused on `resolve_direction_marker_hover` and `draw_direction_grid_overlay`.
  - Rationale: The wrapper had no production callers after the ViewerData refactor, so it was pure API surface. The underlying helpers already cover the actual runtime behavior.

- Topic: Collapse direction grid wrapper
  - Decision: Make `draw_direction_grid_overlay` the implementation directly and remove the private `_draw_direction_grid` layer.
  - Rationale: The wrapper only converted `ViewerData` into `view_center` and FOV scalars. Keeping the public function as the implementation removes a thin indirection while preserving the external API.
