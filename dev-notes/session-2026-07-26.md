- Topic: 32x16 coastline vector tile size experiment
  - Decision: Generate one GeoJSON tile per existing 32 x 16 global tile. Each tile stores source polygon boundary geometries clipped to the tile bounds; empty tiles use a `.0` marker. This is a size experiment, not yet a runtime format decision.
  - Result: All 512 vector tiles were generated under `raw-data/coastline_vector_tiles_32x16/`. There are 479 GeoJSON tiles and 33 empty markers, totaling approximately 2.50 GiB uncompressed.
  - Result: The largest observed tile is `tile_y12_x9.geojson` at 252,291,387 bytes (about 252.3 MB). A gzip level-9 stream of that tile is 51,129,037 bytes (about 48.8 MiB). The next-largest sampled tiles were also above 100 MB uncompressed.
  - Caveat: This prototype keeps full GeoJSON coordinate text and clipped boundary feature overhead. Topology-aware vector tiles, coordinate quantization, simplification, and binary encoding could reduce the size substantially, but were not applied here.

- Topic: Selective 4x4 subdivision of the eight largest vector tiles
  - Decision: Replace the eight largest parent GeoJSON tiles with 4 x 4 geographic child tiles for a size experiment; keep the other 504 parent tiles unchanged. The child tiles are clipped from the parent boundary geometries and use names such as `tile_y12_x9_q11.geojson`.
  - Result: 128 child outputs were generated: 111 GeoJSON files and 17 empty `.0` markers. The child GeoJSON total is 1,008,239,114 bytes (0.939 GiB). The largest child is `tile_y12_x9_q11.geojson` at 72,884,341 bytes (69.51 MiB); the largest sampled gzip result is 15,809,127 bytes (15.07 MiB) for `tile_y2_x17_q13.geojson`.
  - Conclusion: Fixed 4x4 subdivision materially reduces the worst-case tile from 252.3MB to 72.9MB uncompressed, but does not meet a 50MB uncompressed target. A second subdivision level or coordinate quantization/simplification would be needed for that target.

- Topic: Final coastline data distribution design
  - Decision: Distribute the static coastline vector cache through a separate GitHub Release, with one asset per x column of the 32×16 grid. A dedicated CLI selects assets from `--lon-min` and `--lon-max`, or downloads all assets with `--all`; the GUI never downloads automatically.
