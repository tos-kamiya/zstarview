# Session 2026-04-09

- Scope: Investigate abrupt ISS appearance near screen edge and implement a fix if the cause is in rendering/visibility logic.

- Topic: ISS overlay appears abruptly near the edge of the visible sky
  - Decision: Keep the satellite visibility gate driven by `content_fov_deg`, but rescale satellite screen projection so the requested content FOV maps to the viewport edge instead of hard-coding the edge to 90 degrees.
  - Rationale: `draw_satellite_overlay()` already used `is_in_fov(..., fov_deg=content_fov_deg)`, but `altaz_to_normalized_xy()` always normalized with `90 deg -> radius 1.0`. With the default `content_fov_deg=100`, satellites between 90 and 100 degrees from the view center were considered in-FOV but still projected outside the screen, then appeared suddenly once they crossed 90 degrees. Scaling the projected radius by `90 / content_fov_deg` aligns the overlay with the requested FOV without adding alpha fades.
  - Alternatives Considered: Alpha fade near the edge was rejected because it would hide the projection mismatch instead of fixing it.

- Topic: Validation
  - Decision: Add a render test that places a satellite exactly 100 degrees from the view center and verifies it lands on the viewport edge when `content_fov_deg=100`.
  - Rationale: This directly exercises the regression and proves the overlay now honors the requested FOV in screen-space.
