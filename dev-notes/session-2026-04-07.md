# Session 2026-04-07

- Scope: Refactor sky window rendering so the current frameless presentation becomes a reusable client-area component, and add an option to launch in a standard decorated window.

- Topic: Share the same sky-view client area between frameless and decorated windows
  - Decision: Keep `SkyWindow` as the `QMainWindow` host and move paint/input/resize responsibilities for the visible sky area into a dedicated central `SkyWindowClientWidget`.
  - Rationale: This preserves the existing controllers, timers, menu actions, and geometry persistence while making the rendered sky view explicitly client-area based. It also keeps the frameless drag behavior host-specific instead of mixing it into the render widget.
  - Alternatives Considered: Replacing `SkyWindow` with a pure `QWidget` and introducing a new host wrapper was possible, but it would have required wider changes to fullscreen handling, action ownership, and existing tests.

- Topic: Window decoration mode
  - Decision: Add CLI option `--window-frame {frameless,window}` with default `frameless`, and carry it through `SkyWindowRuntimeOptions`.
  - Rationale: This keeps the current default behavior unchanged while allowing a standard titled/bordered OS window when requested.

- Topic: Frameless dragging after central-widget refactor
  - Decision: Extend `DraggableWindow` so dragging can be initiated from registered drag-target widgets via an event filter.
  - Rationale: Once the sky view became a central widget, mouse events no longer naturally reached the host window. The event-filter approach keeps dragging working without coupling the client widget to host movement internals.
