# Session 2026-07-08

Scope: White-background object viewer specification and design discussion.

- Topic: White-background object viewer documentation split
  - Decision: Keep the new viewer's user-facing specification and internal design in separate documents: `docs/object-viewer-specification.md` and `docs/design/object-viewer.md`.
  - Rationale: The viewer is intended as a separate application entry, not a transient `zstarview` display mode. Separate docs keep the existing `zstarview` specification focused on the starry-sky viewer while still documenting the shared architecture and intended defaults.
  - Alternatives Considered: Adding a large section to `docs/specification.md` and `docs/design.md`; rejected because it would mix two user-facing product concepts in the same primary spec.

- Topic: White-background rendering defaults
  - Decision: The object viewer should use a fully white background, black labels, visible geographic helper layers, and a dedicated bright-star rendering path with outline and body separated into two passes.
  - Rationale: Geographic helper layers help users identify place and direction, while the white background requires different contrast rules from the dark sky viewer. Separating star outlines from star bodies prevents outlines from overpainting nearby star colors.

- Topic: Small star cutoff
  - Decision: Stars whose projected apparent diameter is below 1.0 px should not be drawn in the white-background viewer.
  - Rationale: Subpixel star rendering works for dark backgrounds but becomes either invisible or noisy on white backgrounds.
