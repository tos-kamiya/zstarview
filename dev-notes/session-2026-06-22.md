Scope: remove the legacy cloud-image render path and keep the alt/az cloud-grid path only.

- Topic: remove legacy cloud image inputs from render pipeline
  - Decision: `RenderSceneData`, `SkyCompositorCache.draw()`, and the export-image render path now consume only `cloud_missing_mask` and `cloud_altaz_grid` for cloud rendering.
  - Rationale: the old `cloud_image` / `cloud_img` path was no longer needed once cloud stripes were generated directly from the alt/az grid. Removing it avoids the broken fallback path and keeps the compositor deterministic.
  - Notes: helper functions that still accept an image for other purposes were renamed to avoid `cloud_img` identifiers where practical.

- Topic: remove standalone cloud-image CLI
  - Decision: delete `src/zstarview/cloudimage.py` and its dedicated test file.
  - Rationale: the standalone PNG generator is now redundant after the alt/az-grid cloud path became the primary implementation. Keeping the module would preserve a separate code path that no longer matches the supported rendering flow.
  - Notes: the geosatellite projection helpers remain in place; only the separate debug/standalone wrapper was removed.

- Topic: verify render recovery behavior
  - Decision: keep the immediate redraw path working when fast mode returns to normal mode, using the already-mapped cloud data when present.
  - Rationale: the compositor now renders directly from the cached alt/az grid, so it can paint clouds without first rebuilding a cloud-image intermediate.
