# Session 2026-06-22

Scope: investigate and fix cloud alt/az grid rendering and coverage calculation.

- Topic: alt/az cloud grid density and coverage
  - Decision: Reworked `build_altaz_grid` to sample the full observer-centric alt/az grid directly, instead of projecting a small local lat/lon patch into alt/az cells.
  - Rationale: The local-patch approach left most of the grid empty, which showed up as a low `coverage_ratio` and a broad yellow missing-data band near the horizon. Sampling the full sky grid makes the cache camera-independent in the intended sense and keeps the missing mask tied to actual source holes rather than sparse rasterization.
  - Decision: Count any finite satellite sample as coverage, even when BT maps to zero cloud amount.
  - Rationale: Coverage is a data-completeness signal, not a cloudiness signal. Treating clear-sky cells as uncovered would incorrectly lower coverage and break the status line.

- Topic: direct cloud stripes from `CloudAltAzGrid`
  - Decision: Added a compositor path that samples `CloudAltAzGrid` directly in screen space and feeds that sampled map into the existing stripe logic, instead of rebuilding a `CloudAmountField` from the rendered RGBA image.
  - Rationale: The RGBA round-trip discarded source structure and made the stripe appearance depend on an intermediate image rather than the cached grid itself. Reading the grid directly keeps the stripe style tied to the same source of truth as the cloud circles and avoids another lossy resampling step.
  - Decision: Extended the export-image cloud fetch result to carry the optional `CloudAltAzGrid` so the final scene can use the same direct path.
  - Rationale: GUI and export-image should render the same cached source data through the same compositor path when `--cloud-altaz-grid` is enabled.

  - Decision: Remove the --cloud-altaz-grid feature flag and the legacy render_from_source_with_coverage path. Always build the alt/az grid after fetching cloud source data and render from that grid. Keep CloudAmountField only for the --geo-satellite path, which still delivers a plain RGBA disc.
