- Topic: Sky-disc alpha whitening
  - Decision: Adjusted `sky_color_samples()` so higher alpha values not only raise opacity but also reduce saturation a bit and blend slightly toward white.
  - Rationale: The previous model made the disc feel too strong and colorful when alpha was high; a mild desaturation keeps the sky disc visually closer to the intended pale haze while preserving the low-alpha look.
  - Validation: Sampled `sky_color_samples()` at alpha `0.2`, `0.5`, and `1.0` and confirmed the higher-alpha output moved closer to white.

- Topic: Standalone sky-disc preview app
  - Decision: Added `dev-samples/sky_disc_preview_app.py` as a self-contained Qt preview with sliders for sun altitude, sun azimuth, alpha, exposure, saturation, and disc opacity.
  - Rationale: This makes it possible to inspect sky-disc color behavior outside the main app without touching production UI code.
  - Validation: `ruff check dev-samples/sky_disc_preview_app.py` and `.venv/bin/python -m py_compile dev-samples/sky_disc_preview_app.py`

- Topic: Sky-disc model redesign
  - Decision: Reworked `src/zstarview/render/sky_disc.py` so the sky color model is built from sun altitude, sun/view angular distance, and view altitude directly, then reduced `sky_color_samples()` to exposure plus alpha/eclipsing scaling. Removed the separate luma clip, tone mapping, and post-hoc white blend.
  - Rationale: The previous implementation mixed model construction with appearance grading, which made the color controls hard to reason about. Folding haze and chromatic balance back into the sky model makes the behavior easier to tune and aligns the renderer with the requested empirical structure.
  - Validation: `ruff check src/zstarview/render/sky_disc.py tests/test_sky_disc_viewport_and_ground_tint.py dev-samples/sky_disc_preview_app.py` and `pytest tests/test_sky_disc_viewport_and_ground_tint.py -q`
