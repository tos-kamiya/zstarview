- Topic: Resize viewport interaction cloud buffers
  - Decision: Stop preserving the visible cloud bitmap when the client area is resized; resize now enters the same viewport interaction path as other fast redraw triggers.
  - Rationale: This removes a resize-only special case before further refactoring and keeps stale cloud render buffers from being reused across size changes.
  - Validation: `uv run -p .venv/bin/python pytest tests/terrain/test_terrain_horizon_ui.py -k "resize or viewport_interaction"`; `uv run -p .venv/bin/python pytest tests/test_window_render_sync.py -k "key_press_rotates_view_immediately or key_release_ends_viewport_interaction_mode or end_viewport_interaction_mode"`

- Topic: Frameless window drag and fast-mode
  - Decision: Do not enter viewport interaction mode for mouse-driven frameless window drag.
  - Rationale: Wayland system move does not visibly redraw the main window during drag, while Windows drag became less smooth when fast-mode repaint was triggered at drag start. Keeping drag independent avoids click flicker and drag-start repaint stalls.
  - Alternatives Considered: Delaying fast-mode until movement was detected via `moveEvent`; this remained environment-dependent because native system move events differ across compositors and platforms.
