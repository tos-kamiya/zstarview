# Session 2026-07-25

- Scope: Investigate the recent slowdown of the sky-blue disc rendering.

- Topic: Sky-disc slowdown diagnosis
  - Finding: The GUI passes the full client size to `draw_sky_color_disc()` on each sky snapshot, while the existing `sky_disc_base_size = 1024` state is not used by that path.
  - Finding: A cold smooth-disc render measured about 250 ms at 1920x1080 and 970 ms at 3840x2160. Profiling at 1920x1080 attributed about 163 ms to vectorized color evaluation and 52 ms to inverse projection. A cache hit was about 0.02 ms, but small Sun-coordinate changes intentionally produce cache misses.
  - Decision: Treat full-resolution raster work as the primary optimization target. First candidate is a geometry-aware reduced-resolution sky surface, scaled during composition; second candidate is caching projection/direction arrays separately from Sun-dependent color. Keep the 0.75-degree overscan behavior unchanged until image-boundary tests cover the optimized path.
  - Rationale: The recent color-gradient additions add per-pixel operations, but the measured cost is dominated by the number of pixels processed. The overscan itself changes the selected pixel count only slightly and is unlikely to explain the regression.

- Summary: Investigation completed; no production code changed. Working-tree build and scheduled screenshot artifacts were left untouched.

- Topic: Sky-disc and star-layer relationship
  - Finding: `sky_disc_image` contains only the sky-color raster. `SkyCompositorCache` first composites it with clouds, ground reset, and atmospheric overlays; the normal render pipeline then draws stars in a separate pass. In scenic presentation, the base frame is created without stars and the present frame adds the star surface afterward.
  - Decision: A reduced-resolution sky-disc surface can be introduced without lowering the star-render resolution. Preserve the existing separate bright-star path so bright stars remain crisp.

- Topic: Reduced-resolution sky-disc implementation
  - Decision: Use a fixed `0.5` scale for both sky-disc surface axes. Scale the image dimensions, disc center, and disc radius together, then rely on the existing compositor scaling to restore the final window size.
  - Rationale: This reduces the sky-disc pixel count to one quarter while leaving the star surfaces and bright-star pass unchanged. The scale is centralized as `SKY_DISC_RENDER_SCALE` for later visual tuning.
  - Validation: Targeted sky/startup tests passed (58 tests); the full suite passed (1303 tests); Ruff and `git diff --check` passed.
  - Measurement: A cold smooth-disc render improved from about 250 ms to 72 ms at 1920x1080, and from about 970 ms to 266 ms at 3840x2160 in the local benchmark.

- Topic: Further sky-disc resolution reduction
  - Decision: Change `SKY_DISC_RENDER_SCALE` from `0.5` to `0.25`, reducing both axes to one quarter and the total pixel count to one sixteenth.
  - Rationale: The user confirmed the half-axis version visually and requested a more aggressive reduction. The existing compositor continues to upscale the background layer while stellar rendering remains unchanged.
  - Validation: Targeted sky/startup tests passed (58 tests); Ruff and `git diff --check` passed. Local cold-render measurements were about 17 ms at 1920x1080 and 67 ms at 3840x2160.

- Topic: Sky-disc FOV-edge coverage
  - Decision: Round the reduced sky-disc width, height, and radius upward with `ceil` instead of rounding to the nearest integer.
  - Rationale: Extra pixels at the reduced surface edge are safer than losing coverage after scaling back to the window, where truncation can expose jagged gaps at the content-FOV boundary.
  - Validation: Targeted sky/startup tests passed (59 tests); Ruff and `git diff --check` passed.

- Topic: Keep export-image sky-disc quality independent
  - Decision: Apply the quarter-resolution surface by default only through `SkyDataWorker`; keep direct `compute_sky_snapshot()` callers such as export-image at full requested resolution unless they explicitly pass a scale.
  - Rationale: The optimization targets interactive GUI responsiveness, while high-resolution export should not inherit an unintended quality reduction.
  - Validation: Targeted sky/startup/shutdown tests passed (73 tests); Ruff and `git diff --check` passed.
