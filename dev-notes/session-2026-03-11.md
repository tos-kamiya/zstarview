- Topic: Multi-radius urban skyline overlays for tower viewpoints
  - Decision: Change skyline generation and app loading to use cumulative distance bands at `0.1, 0.2, 0.5, 1, 2, 5, 10, 20 km`, and render every loaded band as a white overlay line.
  - Rationale: A single far-distance skyline is physically correct but not very informative from tall towers because most structures remain below the eye line. Distance-layered overlays make the urban envelope easier to inspect while keeping the runtime model precomputed and lightweight.
  - Alternatives Considered: Keeping a single skyline line was rejected because it hid useful near-vs-far structure. Using only up to `5 km` was rejected because landmarks such as Tokyo Tower are farther away.

- Topic: Azimuth sampling density for distant narrow targets
  - Decision: Reduce the default skyline sampling step from `0.5°` to `0.1°` in both skyline generation CLIs.
  - Rationale: `0.5°` bins can skip or under-represent narrow distant structures depending on their apparent angular width. `0.1°` is still cheap for precomputation and materially reduces that risk.
