- Topic: Diagnose apparent three-week-old meteor trails from the reported CLI
  command
  - Finding: `-a0.4` enables aircraft and `-P0.4` enables precipitation;
    `-B` selects the building-top observer height. Meteor trails are enabled
    independently at their default opacity of `0.5` because the command does
    not set `--meteor-trails-opacity`.
  - Finding: The meteor layer loads actual GMN trajectory summaries, not
    random trails or a forecast. The repository searches up to seven days
    behind the display time, then selects a 24-hour window ending at the
    newest observation found. It does not filter or color trails by shower.
  - Finding: The renderer keeps historical trails at their observed Alt/Az
    and labels each trail with its age. The status line exposes the decisive
    age range as `M {count}, {oldest}-{newest}h ago` and appends `cache` when
    stale index/file data was used.
  - Result: A Perseid-like concentration cannot be identified as a shower
    from this view alone. If the status age is recent, the trails are recent
    GMN observations (possibly associated with a shower, but shower code is
    not displayed). If it is about 3 weeks, investigate stale cache or an
    unexpectedly shifted display time; `-P0.4` is also an independent source
    of many line-like marks.

- Topic: Diagnose Himawari export-image cloud timeout after B13/B16 addition
  - Scope: Compare the Himawari download path before and after the 2026-08-27
    B13/B16 change, and trace export-image timeout boundaries.
  - Finding: The B16 companion path adds one S3 listing plus one sequential
    download for every selected B13 tile. Each S3 request still uses the
    5-second connect / 30-second read configuration, but export-image keeps
    its 90-second per-layer wall-clock deadline.
  - Finding: Export-image calls `CloudDisc.fetch_source()` in a daemon thread;
    it does not use the GUI cloud subprocess, whose default worker timeout is
    900 seconds. The export thread also does not pass an abort event into the
    provider, so a timed-out export may leave the download thread running.
  - Result: The stricter condition is the unchanged 90-second export layer
    deadline relative to the doubled sequential Himawari work, not a reduced
    per-request network timeout. A timeout is therefore plausible when the
    selected footprint has enough uncached tiles or a slow S3 response.

- Topic: Compare GOES C13/C16 acquisition with Himawari
  - Finding: GOES also performs an additional same-scan C16 listing and one
    C16 download after C13 succeeds, but C13 and C16 are single ABI files,
    unlike Himawari's multiple selected tiles.
  - Finding: GOES C13 may additionally try multiple satellites and two search
    passes when the primary lookup fails. The same unchanged 5-second connect,
    30-second read request limits and 90-second export layer deadline apply.
  - Result: GOES has the same structural increase in work, but the normal
    successful path is substantially less exposed than Himawari. GOES can
    still hit the 90-second deadline during failover, slow listings, uncached
    downloads, or repeated failed search attempts.

- Topic: Timeout mitigation proposal for multi-band cloud acquisition
  - Decision: Prefer a cloud-specific timeout over increasing the shared
    external-layer timeout. Raise the cloud default conservatively to 180
    seconds, while retaining the existing 90-second default for other layers.
  - Decision: Treat B13/C13 as the required base result and B16/C16 as a
    best-effort enhancement. Once the remaining cloud budget is low, skip the
    companion band and complete with the base band.
  - Decision: Thread one monotonic deadline and cooperative abort event from
    export-image through CloudDisc and both providers. Bound each listing or
    download by the smaller of its configured request timeout and remaining
    cloud budget, and stop before starting the next tile.
  - Rationale: This preserves useful cloud output under slow networks,
    prevents abandoned daemon downloads after export abort, and avoids making
    unrelated external layers wait longer. Add elapsed-time and B13/B16 file
    counts to diagnostics before changing the default.

- Topic: Remove contained PLATEAU roof surfaces from urban outlines
  - Decision: Treat a projected roof surface fully contained by an equal-or-
    larger surface as an internal boundary and omit it when its mean roof
    elevation is within the distance-dependent tolerance. Keep contained
    surfaces at materially different elevations and keep the existing shared-
    edge merging behavior unchanged.
  - Rationale: The fixed negative elevation tolerance in the outer-surface
    selection disabled this filtering at every distance, allowing same-height
    nested or duplicate LOD2 roof boundaries to produce extra lines.
  - Validation: Focused urban-outline tests passed (19 tests).
