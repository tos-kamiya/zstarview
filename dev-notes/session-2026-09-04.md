  - Decision: Trace paint, hover, resize, scheduler, and worker-result paths before changing code.
  - Rationale: The report concerns event-loop starvation; existing uncommitted work and session notes must be preserved while isolating synchronous GUI-thread work.

- Topic: Reimplement asynchronous normal frames after the reverted attempt
  - Decision: Treat the prior asynchronous-render entry above as historical;
    that implementation was reverted because a pre-resize resolution could be
    generated and presented after resize. Reimplement the worker boundary with
    an explicit desired-request key containing client size plus base/present
    frame keys. At paint time, use a completed normal frame only when its key
    and image dimensions match the current client; otherwise draw the existing
    capped fast path without entering `viewport_interaction_mode`.
  - Rationale: Qt has no portable resize-finished event. Correctness therefore
    comes from validating current state at presentation and completion, not
    from predicting the final resize event. A monotonic generation rejects old
    results, same-request deduplication prevents paint storms, and one active
    plus one latest queued request skips obsolete intermediate sizes.
  - Edge Case: Returning to the active request's old size still creates a new
    desired generation. This prevents an active result invalidated by an
    intervening size from becoming current again.
  - Failure Handling: Clear the deduplication key when the latest result has
    invalid dimensions or fails, allowing a later paint to retry. Dimension
    mismatches request an immediate repaint; worker exceptions wait for a
    later normal update to avoid a tight failure loop.
  - Follow-up: Do not advance the resize/base generation for the two-second
    present-frame key. A 4K render can exceed that interval, so treating every
    present update as a new generation starved normal-frame acceptance and
    left fullscreen display on the capped fallback. Accept a same-generation,
    current-size result and retain a completed full-resolution frame while
    only its present key is refreshed.
