# Session 2026-09-23

Scope: Investigate missing building outlines in `zstarview-export-image` screenshots.

- Topic: Exported images with apparently missing building outlines
  - Decision: Keep an existing non-empty Overture tile when a refresh produces
    an empty dataset, and log the outline count for each export.
  - Rationale: The 02:48 Sagrada Familia screenshot shows building outlines;
    the 02:54 screenshot does not. Both Overture caches were refreshed at
    02:54 UTC, and their derived tiles contain zero buildings. The expiration
    path did run, but silently replaced useful cache data with empty results.
    The helper-module split did not change that fetch path.
  - Implementation: The importer now refuses to overwrite a populated tile
    with an empty result, retries legacy empty caches immediately, and applies
    the normal 30-day TTL to known-empty caches and empty refreshes. Export
    logs now include the resolved outline count.
  - Validation: Inspected both screenshots, cache metadata and derived tile
    payloads. Automated tests were not run.
  - Follow-up finding: Hapeville's 2.5 km building cache has 5,399 converted
    buildings from release 2026-08-19.0, fetched on 2026-08-24. The Sagrada
    Familia `building` and `building_part` tiles from that same release each
    have zero converted buildings. This rules against a general CLI or schema
    failure but leaves a location-specific source-data change or missing-height
    attributes possible. Raw Overture feature counts were not retained.
  - Raw-data investigation: Overture Maps CLI 1.0.2 with STAC returned
    "No data found" for the Sagrada Familia bbox and release 2026-08-19.0, but
    exited successfully. Repeating the same requests with `--no-stac` returned
    31,404 building and 63,077 building_part features. The current converter
    accepts 24,063 and 51,645 respectively; the rest lack supported positive
    height/floor attributes. This identifies the empty STAC query as the
    immediate cause, not a general data attribute or license change.
  - Implementation: Pin Overture CLI downloads to the resolved release. If a
    STAC query returns zero raw features, retry once without STAC. Record raw
    feature counts in derived tiles and log raw/converted counts.
  - STAC catalog inspection: The downloaded 2026-08-19.0
    `collections.parquet` has 987 rows and its `collection` field is null in
    all rows. The installed CLI 1.0.2 filters that field against `building` or
    `building_part`, so all rows are rejected. Independently matching the
  bounding boxes and asset paths finds one intersecting asset for each type,
  both pointing at the Sagrada Familia area. This confirms a mismatch between
  the published STAC index and the CLI's STAC filter, rather than a zstarview
  bbox construction error.
- Follow-up: A zero-building result from the final `--no-stac` attempt is
  stored with `building_count: 0`, so it is retried after the 30-day empty
  cache interval. If a refresh yields zero while a populated tile exists, the
  populated tile is retained and `empty_refresh_checked_at_utc` suppresses
  another attempt for the same 30-day interval. There is no six-hour retry
  path. `git diff --check` passed; automated tests were not run.
- Completion: README cache-removal instructions were added in English and
  Japanese, including a directory-to-data table. Commit `217809c8` contains the
  Overture recovery fix; commit `7f4b1635` contains the README instructions.
  Version `1.59.2` and its release notes are prepared in a separate commit.
