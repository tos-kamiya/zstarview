Scope: 矢印キー長押し時の fast-mode 回転の飛び対策。

- Topic: 矢印キーのリピートを描画1回につき1ステップに制限
  - Decision: 押下中の自動リピートは受け取るが、前回の回転ステップがまだ描画されていなければ捨てる。描画開始時（`paintEvent`）に描画待ちを解除する。最初の押下とキー解放の処理は従来どおり。
  - Rationale: キーリピートは約30ms間隔（xset: delay 500ms, rate 33/s）で届き、操作中の描画は1フレーム90-150msかかる。Qtは描画要求をまとめるため、描画の合間に3-6回分（15-30度）が処理され、画面上で角度が飛んで見えていた。利用者の要望で、回転速度が描画速度に依存する（約8fpsで毎秒40度前後）ことを受け入れて、1コマ5度の滑らかさを優先した。
  - 安全策: 実ウィンドウの自動テストで、描画待ちが解除されないまま約4秒間リピートがすべて捨てられ回転が止まる事象が1回出た（原因は未確定。描画中に入力が処理される経路などが考えられる）。対策として、捨てるときにも再描画を要求し、最後の回転から250ms（`VIEWPORT_ROTATION_PAINT_WAIT_S`）以上経ったリピートは描画を待たずに回す。利用者が実機で5度ずつ滑らかに回ることを確認した。
  - Alternatives Considered: 前回描画からの経過時間に応じて回転量を決める方式は、回転速度が環境に依存しない利点があるが、1コマの飛びが描画時間に比例するため今回は採用しなかった。
  - 補足: 先に報告された「fast-modeで更新されず、離すと大きく回った画面になる」現象は再現しなかった。GNOME Wayland でリモート操作の許可前に xdotool の入力が数秒遅れてまとめて届いた自動テストを見ていた可能性が高い。許可はプロセスごとに求められる模様で、自動操作時に警告音が出ることがあったため、以降の確認は利用者が実機で行った。

## SkyWindow ミックスインの型チェック（`attr-defined`/`call-overload` の除外を撤廃）

- Topic: ミックスイン間の宣言の置き場所
  - Decision: 属性は `SkyWindowSharedState`（約150件、カテゴリ別）、別のミックスインや `SkyWindowCoreMixin` が定義するメソッドは新設の `gui/window_shared_methods.py` の `SkyWindowSharedMethods`（約75件、定義元ファイル別）に宣言した。メソッドのスタブは `TYPE_CHECKING` ブロック内だけに置く。
  - Rationale: `SkyWindowClientWidget` は描画ミックスインを合成し、未定義の属性を `__getattr__` で所有ウィンドウに転送する。実行時にスタブがあると転送より先に見つかってしまい、挙動が変わる。属性の注釈は値を持たないため実行時のクラス属性にならない。実行時にスタブ・`_owner` がクラス属性として存在しないことを確認した。
  - 型は、`reveal_type` で `SkyWindow` の推論結果（`window.py` の `__init__` 由来）を取り出して使った。メソッドのシグネチャは定義元からそのまま写した（食い違えば mypy が報告する）。

- Topic: Qt の親ウィジェットとしての `self`（`call-overload` 8件）
  - Decision: `SkyWindowActionsMixin` と描画ミックスインにも、`window_input.py` と同じく型チェック時だけ `QWidget` を基底として見せた。描画ミックスインの基底は `window_render_cache.py` の `_RenderMixinBase`（型チェック時は `SkyWindowSharedState` と `QWidget`、実行時は `object`）。
