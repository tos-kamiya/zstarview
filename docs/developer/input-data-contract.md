# 入力データ契約ガイド

最終更新: 2026-02-28

この文書は、描画・天体計算・クラウド投影で使う入力データの型/単位/座標系の規約です。
将来の変更では、本ガイドを優先して整合を保ってください。

## 1. 角度・座標系の基本規約

- 角度は原則として `deg`（度）を使う。
- 方位角 `az` は `0=N, 90=E, 180=S, 270=W` とする。
- 視点中心 `view_center` は `(alt_deg, az_deg)` の順とする。
- 新規APIでは `altaz` 順（`alt_deg` → `az_deg`）を採用する。

## 2. 命名規約

- 角度: `*_deg`
- ピクセル: `*_px`
- 距離(km): `*_km`
- 時間差: `timedelta` を使い、生の時間数値は境界でのみ扱う。

例:
- `view_alt_deg`, `width_px`, `height_px`, `radius_px`, `cloud_shell_km`

## 3. 型規約

- `types.py` の単位付きエイリアスを使う:
  - `AltDeg`, `AzDeg`, `LatDeg`, `LonDeg`
  - `LocationLatLon`, `ViewCenterAltAz`
- 星空テーブルは `StarsTable(TypedDict)` を使い、キー契約を固定する:
  - `name`, `alt`, `az`, `vmag`, `bv`

## 4. API互換と移行

- 引数順を変更する場合は段階導入する:
  - 新APIを追加
  - 内部呼び出しを新APIへ移行
  - 互換ラッパーを廃止予定として明示
  - 内部利用が消えた時点でラッパーを削除

## 5. Docstring規約

- 単位・座標系・順序・範囲を明記する。
- 実装と食い違う説明は禁止する。
  - 例: 正規化座標は `90deg -> 1.0` 基準であり、値が `1.0` を超える場合がある。

## 6. レビュー観点（チェックリスト）

- 引数名に単位が含まれているか（`*_deg/*_px/*_km`）。
- `alt/az` の順序が規約どおりか。
- 観測者座標系と画面座標系が混在していないか。
- 型注釈が `types.py` の契約に沿っているか。
- docstring と実装が一致しているか。
