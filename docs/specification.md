# zstarview 仕様書（初版）

最終更新: 2026-03-08

## 1. 目的

`zstarview` は、指定した地点・時刻の星空をデスクトップ上に描画するアプリケーションである。  
昼間や曇天時にも視覚的に理解しやすい表示を提供することを目的とする。

## 2. スコープ

- 対象:
  - 地点（都市名または緯度経度）と時刻に基づく天体表示
  - 星・太陽・月・惑星、地平線、天の赤道、黄道の描画
  - 雲レイヤー（衛星IRデータ）重畳表示
  - CLI起動、GNOME用 `.desktop` 生成
- 非対象:
  - 天文学的な厳密検証用途の計算保証
  - 小惑星等の網羅的天体表示
  - マルチユーザー設定同期

## 3. 用語

- 視点中心: 表示中心の高度・方位（`-A`, `-Z`）
- 実時間表示: 現在UTC基準（`--hours/--days/--datetime` 未使用）
- 時間シフト表示: `--hours/--days/--datetime` を使用した表示
- CloudDisc: 衛星IRデータから雲の円盤画像を生成する内部モジュール

## 4. ユースケース

1. 都市名を指定して現在の星空を表示する。
2. 緯度経度を直接指定して星空を表示する。
3. 方位・高度を変えて全天の任意方向を観察する。
4. 時間シフトして過去/未来の空を観察する。
5. 雲表示の不調時でも、星空描画は継続する。

## 5. 機能要件

### 5.1 入力と起動

- CLI引数:
  - `city`（省略可能）
  - `--hours`, `--days`, `--datetime`
  - `--view-center-az`, `--view-center-alt`
  - `--vmag-limit`, `--star-base-radius`
  - `--sky-opacity`, `--cloud-opacity`
  - `--enlarge-moon`, `--sky-update-interval`
  - `-t`, `--theme`（`night` / `day` / `white`）
- `city` は以下を受け入れる:
  - 都市名 (`Tokyo`)
  - `CC/City` 形式 (`JP/Tokyo`)
  - `geonameid` 数値
  - 緯度経度 (`35.68;139.76`, `N35.68;E139.76`)

### 5.2 都市解決

- GeoNamesデータを使用して都市候補を検索する。
- 複数候補は人口順優先。
- 都市解決後、次回起動用に地点情報を保存する。
  - 都市入力: `CC/Name`
  - 座標入力: `lat;lon`

### 5.3 星空描画

- 描画対象:
  - 星（等級・B-V 色指数反映）
  - 太陽・月・惑星
  - 地平線・天の赤道・黄道
  - 地形地平線ポリライン（有効時のみ）
- 90度以上（`BACKGROUND_FIELD_OF_VIEW_DEG1`）の背景領域では、星の矩形描画の長辺が2ピクセル以下のサブピクセルサイズの星は描画対象から除外し、背景の透明度とノイズを維持する。
- ビュー円ディスク配置:
  - `width < height`（縦長・正方形寄り）: ウィンドウ中央の内接円を使う。
  - `width >= height`（横長）: 天球円の上端を上マージンへ内接させる。
  - 横長時の半径は `r = min((width - 20)/2, (height - 20)/(1 + alt/90))` を用いる（`alt` は仰角[deg]）。
  - 横長時の中心Yは `center_y = 10 + r` とし、天球円が上端からはみ出さないことを保証する。
- オーバーレイ:
  - 方位ラベル
  - 時刻/地点/ハイライト天体情報
  - ステータス行（クラウド取得エラー、地形地平線取得エラーなど）

### 5.3.1 地形地平線ポリライン

- DEM を用いて観測地点から周囲地形の見かけ地平線を計算し、既存の幾何学的地平線に追加の緑色ポリラインとして重畳表示する。
- 見かけ地平線計算には地球曲率と大気屈折を含める。
- 地形地平線は既存の天球投影にそのまま重畳し、terrain 専用の高さ強調は行わない。
- 地形に遮蔽物がない方向では、地形地平線が 0 度未満になることを許容する。
- 地形地平線の制御は opacity で行う。
  - `opacity > 0`: DEM 取得・計算・描画を有効化
  - `opacity == 0`: DEM 取得・計算・描画をすべて無効化
- デフォルトでは非ゼロ opacity とし、有効状態で起動する。
- GUI の `Terrain Horizon` トグルは opacity を `0` と既定値の間で切り替える。
- CLI 起動時に opacity `0` が指定された場合、その起動中は GUI から再有効化できない。
- DEM データはキャッシュして再利用するが、計算済みポリラインは永続化しない。
- DEM 取得失敗時は bottom status line に terrain 用の失敗状態を表示し、そのセッション中は自動再試行しない。

### 5.4 更新処理

- 星空更新:
  - バックグラウンドで天体計算・空色ディスク生成
  - UIへシグナルで結果反映
- 雲更新:
  - CloudDiscで衛星データから雲画像生成
  - 更新中/失敗時のバナー表示
  - 再描画要求はQtシグナル経由でUIスレッドに配送
  - 終了シーケンス開始後は新規更新を停止し、終了時の再描画シグナル送出は抑止する
- 地形地平線更新:
  - DEM 取得とポリライン計算はバックグラウンドで実行する
  - 起動時の更新タイミングは雲更新と同様とする
  - 失敗時は同一セッション中に自動再試行しない

### 5.5 雲表示の制約

- 時間シフト表示時は雲表示を無効化する（現在データのみ取得可能なため）。
- 衛星データが欠落/タイムアウトしてもアプリ全体は継続動作する。

## 6. 非機能要件

- 応答性:
  - UIスレッドをブロックしない（重処理はバックグラウンドへ）
- 可観測性:
  - 標準エラーとログファイルに記録する
- 耐障害性:
  - 一時的なネットワーク不調時も致命停止しない
- 保守性:
  - 描画、天体計算、クラウド取得をモジュール分離する

## 7. 外部依存

- GUI: `PySide6`
- 天文計算: `astropy`, `skyfield`
- データ処理: `numpy`, `polars`, `xarray`
- 衛星データ: `boto3`, `botocore`, `satpy`
- 画像: `Pillow`

## 8. エラーハンドリング方針

- 起動不能（都市データ/星データ読込失敗など）:
  - 起動処理を中断し、ログを残して終了する。
- 雲取得失敗:
  - 失敗内容をバナー表示し、次回更新を継続する。
- 地形地平線取得失敗:
  - 失敗内容をステータス行に表示し、当該セッション中は自動再試行しない。

## 9. 既知の制約

- 雲データは外部公開S3に依存し、オフライン時は利用不可。
- 高い `vmag-limit` は描画/計算負荷を増加させる。
- 天文計算精度は使用ライブラリと入力データ品質に依存する。

## 10. 受け入れ観点（抜粋）

- 指定都市で起動し、星・惑星・補助線が描画される。
- `--datetime` 指定時に星空時刻が反映される。
- `--datetime` 使用時、雲表示が無効化される。
- 雲取得失敗時、バナー表示されるがアプリは動作継続する。
- 地点保存が1経路で行われ、座標入力が上書き破壊されない。
