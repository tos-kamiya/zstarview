# zstarview 設計書（初版）

最終更新: 2026-03-01

## 1. 設計方針

- UI責務と計算責務を分離する。
- 長時間処理はバックグラウンドスレッドで実行する。
- 失敗しやすい外部I/O（S3）を局所化し、例外をドメイン例外に正規化する。
- 描画は純粋関数寄りに保ち、状態管理は `SkyWindow` に集約する。

## 2. モジュール構成

### 2.1 エントリ/起動

- `src/zstarview/zstarview.py`
  - CLI引数解析
  - ログ初期化
  - 都市解決・時刻解釈・星カタログ読み込み
  - `SkyWindow` 起動

### 2.2 ドメイン計算

- `src/zstarview/astro.py`
  - 天体位置計算
  - 可視判定
  - 補助線（地平線/赤道/黄道）点列生成
  - 食情報計算

### 2.3 描画

- `src/zstarview/render/draw.py`
  - 背景、星、惑星、ラベル、オーバーレイ描画
- `src/zstarview/render/draw_sky_disc.py`
  - 太陽高度・食係数を用いた空色ディスク生成

### 2.4 UI

- `src/zstarview/ui/window.py`
  - メインウィンドウ
  - 入力イベント
  - タイマー管理
  - ワーカー/コントローラ連携と描画統合
- `src/zstarview/ui/sky_worker.py`
  - 星空更新計算（天体計算 + 空色ディスク）をバックグラウンドで実行
  - `data_ready` シグナルで結果返却
- `src/zstarview/ui/cloud_controller.py`
  - 雲更新（取得・例外正規化・running/pending制御・清掃トリガ）をバックグラウンドで実行
  - `cloud_started` / `cloud_ready` / `cloud_failed` シグナルでUIへ通知
- `src/zstarview/ui/composite.py`
  - 空色/雲合成、ハッチ処理、合成キャッシュ
- `src/zstarview/ui/cloud_state.py`
  - 雲画像・メタ・バナーの状態保持

### 2.5 クラウドデータ

- `src/zstarview/clouddisc/core.py`
  - 衛星選択、投影、サンプリング、画像化のオーケストレーション
- `src/zstarview/clouddisc/providers/goes.py`
- `src/zstarview/clouddisc/providers/hima.py`
- `src/zstarview/clouddisc/providers/_s3_io.py`
  - S3一覧/ダウンロードの共通I/Oヘルパー
  - タイムアウト/一般失敗を `TimeoutError` / `DownloadError` へ正規化

## 3. 主要データ構造

- `types.ViewerData`
  - 観測地点、タイムゾーン、都市名、視点中心
- `types.CelestialData`
  - 描画対象の天体データ一式
- `clouddisc.types.CloudMeta`
  - クラウド画像のデータソース情報

## 4. 処理フロー

### 4.1 起動フロー

1. `main()` が CLI とロガーを初期化。
2. `_startup_resolve_city()` で地点を決定し、次回用設定を保存。
3. 時刻オフセットと星カタログを読み込み。
4. `SkyWindow` を生成し、初回データ読み込み後に表示。

### 4.2 星空更新フロー

1. `SkyWindow.start_background_sky_data_update()` が `SkyDataWorker.update()` を呼ぶ。
2. `SkyDataWorker` がバックグラウンドスレッドで天体計算と空色ディスク生成。
3. `data_ready` シグナルで `SkyWindow._on_sky_data_calculated()` に反映。

### 4.3 雲更新フロー

1. `SkyWindow.start_background_cloud_update()` が `CloudController.update()` を呼ぶ。
2. `CloudController` が `CloudDisc.render_now()` を実行し、例外をUI向けステータスへ正規化。
3. `cloud_ready` / `cloud_failed` シグナルで `SkyWindow` に結果を返す。
4. `SkyWindow` が `CloudImageState` と合成キャッシュを更新し、再描画要求をUIスレッドへ配送。
5. `cloud_failed` 受信時はバナー表示に加え、雲画像とストライプ密度をクリアし、雲は描画しない。
6. 終了開始時（`aboutToQuit` / `closeEvent`）はタイマー停止に加えて `CloudController.shutdown()` を呼び、以後の更新受付を抑止。

## 5. スレッドモデル

- UIスレッド:
  - Qtイベントループ、描画、ウィジェット状態更新
- バックグラウンド:
  - 星空計算: `SkyDataWorker`
  - 雲更新: `SkyWindow` 管理スレッド
  - キャッシュ清掃: 雲更新側の補助スレッド

注意:
- UI操作（再描画要求を含む）はシグナル経由でUIスレッドに戻す。
- シャットダウン中はワーカー側 `emit` を抑止し、Qtオブジェクト破棄後のシグナル送出例外を回避する。

## 6. エラーモデル

- 起動系エラー:
  - `StartupAbortError` で起動シーケンスを中断
- クラウド系エラー:
  - `CloudDiscError` 派生（`TimeoutError`, `DownloadError`, `DataNotFoundError`, `RenderError`）
  - UIはバナー表示し、当該時点の雲レイヤーはクリアして非表示
  - 更新ループは継続

## 7. 設定/永続化

- 設定ファイル:
  - `~/.config/zstarview/config.json`
- 保存情報:
  - 最終地点（都市形式または座標形式）
- キャッシュ:
  - 衛星データ・エフェメリスはキャッシュディレクトリに配置

## 8. テスト戦略（現状と推奨）

- 現状:
  - 軽量な回帰テストを追加済み
    - 起動時地点保存経路のガード
    - 共通S3 I/Oの例外変換
- 推奨:
  - `astro.py` の純計算関数テストを拡張
  - `ui` はシグナル発火と状態遷移を中心にモックテスト
  - ネットワーク実アクセスを避け、providerはモック前提で検証

## 9. 今後の設計課題

- 高密度恒星表示（`vmag <= 10`）での操作応答改善（一部実装済み）
  - 背景:
    - `vmag <= 10` では星数が数十万規模になり、視点操作時の再計算・再描画の双方がボトルネック化する。
    - 現状は視点回転（`view_center` 変更）時にも星データ更新ワーカーが走るため、キー操作の追従が鈍る。
  - 方針:
    - 「操作中は軽量表示、停止後に精細化」の2段階描画へ移行する。
    - 観測地点固定（セッション中に `lat/lon` 不変）を前提に、再利用可能な前計算を増やす。
  - 実装状況:
    - 実装済み:
      - `SkyWindow` にインタラクション状態（回転/リサイズ中）とアイドル復帰タイマーを追加。
      - 操作中は星描画の有効 `vmag` 上限を抑える LOD を導入（最終品質へ自動復帰）。
      - LOD境界ロジックの純関数テストを追加。
    - 未実装:
      - 操作中の星データ再計算抑制（再投影優先化）。
      - 色・アルファ・描画バケット前処理のキャッシュ化。
      - 計算時間/描画時間/段階星数のデバッグログ可視化。
  - テスト方針:
    - LOD境界（`6, 7, 8`）の選別ロジックを純関数としてテストする。
    - UI側は「操作中に軽量段」「停止後に高密度段へ復帰」の状態遷移をテストする。
  - 受け入れ条件:
    - 矢印キー連続操作時にフレーム落ち体感が現状より明確に軽減されること。
    - 操作停止後に最終的な描画品質（`vmag` 上限）へ戻ること。
    - 既存の低密度表示（例: `vmag <= 6`）で表示崩れ・回帰がないこと。

- INPROGRESS: 星カタログ生成の正本化（Hipparcos + Tycho-2 統合）
  - 目的:
    - `zstarview` 側を星データ生成の正本にし、`zstarview-vr` へ同一データを供給する。
    - `vmag <= 6` の既存見え方を維持しつつ、`6 < vmag <= 9` の密度を改善して天の川の連続性を高める。
  - スコープ:
    - 入力は Hipparcos と Tycho-2。
    - 出力は既存描画系で扱える正規化済みカタログ（`ra, dec, vmag, bv, source_id` 相当）とする。
    - 必要に応じて `<=6`, `<=7`, `<=8`, `<=9` の段階データを生成する。
  - 処理方針:
    - 単位・列名・欠損値の正規化を先に行う。
    - 重複天体は HIP/TYC 識別子と角距離近傍判定で統合する。
    - 優先ルールは「明るい側は Hipparcos 優先、暗い側は Tycho-2 補完」を基本とする。
  - 実装ステップ:
    - `scripts/` に生成スクリプトを追加し、再現可能な1コマンド生成を提供する。
    - 生成統計（件数、等級ヒストグラム、欠損率、重複解消件数）を出力する。
    - 回帰テストで既知の明るい恒星・総件数レンジ・重複除去結果を検証する。
    - `src/zstarview/data/` の成果物を更新し、既存ロード経路との互換を確認する。
  - 連携方針:
    - `zstarview-vr` は生成済みデータの取り込み専用にし、独自生成ロジックを持たない。
    - データ更新手順は `zstarview` 側ドキュメントに一本化する。
  - 受け入れ条件:
    - `vmag <= 6` の見え方が大きく劣化しないこと。
    - `vmag <= 9` で天の川の連続性が改善すること。
    - Desktop/VR で同一データから描画可能であること。

- 全天球の円形ビュー化 + 地平線下ティント表示（実装済み）
  - 背景:
    - VR版（`../zstarview-vr`）では全天球前提で、地平線下（alt < 0）にも薄い色を残して視認性を上げている。
  - 実装内容:
    - ビューは常に円ディスクで表示する。
    - 縦長・正方形寄り（`width < height`）では、従来どおり中央内接の円を使う。
    - 横長（`width >= height`）では、円の上端が上マージンに必ず内接するように配置する（上端からはみ出さない）。
    - 横長時の半径は次式で決める。
      - `r = min((width - 20)/2, (height - 20)/(1 + alt/90))`
      - `center_y = top_margin + r`（`top_margin = 10`）
    - これにより、地面側を下へ逃がしつつ、地面以外の見切れを抑える。
    - 地平線下も描画対象とし、完全黒つぶしではなく薄い透過ティントを付与する。
  - 色/強度（現行調整値）:
    - 地平線下ティント色: `RGB = (0.12, 0.19, 0.27)`（VR `groundColor` 相当）。
    - 地平線下は `GROUND_BASE_DARKNESS = 0.03` で一度暗化した後、`GROUND_TINT_STRENGTH = 0.20` でティントを混合する。
    - `sky_opacity` は地平線上（`alt >= 0`）にのみ適用し、地平線下（`alt < 0`）には適用しない。
  - 描画仕様:
    - 空ディスク生成時、各画素の逆投影で `alt` を算出する。
    - `alt >= 0` は現行空色を使用。
    - `alt < 0` は `groundBase = skyColor * 0.03` を作り、`mix(groundBase, groundTint, 0.20)` で色を作る（ハード境界で開始）。
    - 最終的なディスクは従来どおり円形マスクでクリップする。
  - 恒久不可視領域（never rises）:
    - 観測緯度と視線方向から赤緯を算出し、その緯度で恒久的に昇らない領域へ赤ティントを付与する。
    - ティント色/強度は `RGB = (0.42, 0.07, 0.07)`, `strength = 0.16`。
    - 適用順は地平線下暗化/ティントの後段（最終段）とし、視認性を確保する。
  - 雲表示との整合:
    - 雲の可視下限は `alt_min_deg = 0.0` を維持し、地平線下には描画しない。
    - したがって地平線下の色は「空ディスク（背景）のみ」が表示される。
  - 受け入れ観点:
    - 横長時でも天球円が上端からはみ出さない。
    - 横長時に仰角を下げるほど半径が大きくなり、地平線が下寄りに表示される。
    - 縦長・正方形寄りでは従来どおり中央内接表示となる。
    - 地平線下に薄い青灰色のティントが常時見える。
    - 星の視認性が極端に悪化しない（少なくとも現行 `sky_opacity=0.2` 同等の見え方を維持）。

- 雲ストライプの低雲量抑制（実装済み）
  - 背景:
    - 現行は `weight -> alpha` が線形で、低雲量でも `alpha > 0` ならストライプが見える。
  - 仕様案:
    - 正規化雲量 `w` に対し、`w <= 0.03` は 0（ノイズ床）。
    - `0.03 < w < 0.08` は `smoothstep` でなだらかに立ち上げる。
    - `w >= 0.08` は `(w - 0.08) / (1 - 0.08)` で再スケールして濃い雲のレンジを維持する。
  - 適用位置:
    - 雲量からアルファへ変換する段階（ストライプ化・密度場サンプリングの前段）に適用する。
  - 期待効果:
    - 晴天域の薄い縞ノイズを抑制しつつ、閾値近傍の点滅（on/off）を軽減する。
  - 懸念と検証観点:
    - 薄雲の見え方が弱くなり過ぎないかを、快晴・薄雲・前線域の3ケースで目視比較する。

- 雲の地平線下マージン設定（実装済み）
  - 方針:
    - 雲表示はヒント用途のため、地平線下の描画マージンは設けない。
  - 実装内容:
    - `alt_min_deg` は実運用値・デフォルト値ともに `0.0` へ統一する。
  - 補足:
    - 幾何学的な完全クリップではなく、投影時の可視判定しきい値で運用する。

- 地平線方位マーカーを「地平線垂直の固定長マーカー線」に変更（実装済み）
  - 背景:
    - 画面相対の縦線マーカーは、天頂付近や低仰角時に不自然な見え方になりやすい。
  - 実装内容:
    - 方位マーカーは地平線上の方位点（N/NE/E/SE/S/SW/W/NW）に描く短線とする。
    - 各点で地平線接線を有限差分で推定し、その接線に垂直な方向へマーカー線を描く。
    - マーカー長は固定ピクセル長（仰角・視点に依存しない見た目長）で描画する。
    - 色は地平線ラインと同色とする。
    - 方位ラベルとの干渉時は、ラベル側を外周方向へ `+4px` オフセットする。
  - 受け入れ観点:
    - 天頂表示（例: `A=90`）でも、画面固定の縦線ではなく地平線垂直方向として描画される。
    - 低仰角表示（例: `A=5`）でも、マーカー長が一定で視認性が安定する。

- `CloudController` 抽出後の責務整理は、必要時に再評価する（現時点では `SkyWindow` 側との分担は実用上バランスが取れている）。
- 描画パイプラインの入力データ契約（型/単位）は規約化済み。将来の変更は `docs/developer/input-data-contract.md` に従う。
- 仕様変更時に追従しやすいよう、CLI仕様と内部データ仕様の対応表を追加する。
- 惑星表示スタイル（実装済み）
  - 惑星記号（emoji）は廃止済み。惑星（Mercury〜Pluto）は「有色の円マーカー + クロスゲージ」で表示する。
  - 惑星名ラベルは常時表示する（ホバー依存にしない）。
  - 太陽は既存どおりクロス、月は既存どおり位相ディスク+クロスを維持する。
  - 惑星は地平線上下を問わず、FOV内であれば表示対象とする。
  - 等級反映:
    - `astro.calculate_planets()` で Skyfield `planetary_magnitude()` により惑星 `vmag` を算出する。
    - `render/draw.py` の `planet_disc_style_from_vmag()` で `vmag` を円マーカーの半径/アルファに変換する。
    - `render/draw.py` の `planet_bloom_profile_from_vmag()` でブルーム強度を計算し、加算合成で光彩を重畳する。
  - クリッピング仕様（重要）:
    - 惑星ディスク（半径/本体アルファ）は `vmag` を `[-1.5, 6.0]` にクリップして算出する。
    - 一方でブルームは実等級（`-1.5` より明るい領域）を追加反映し、金星などの超明るいケースをサイズ肥大なしで表現する。
- ダイナミックなタイムシフト操作（`-H` のGUI版）を追加する。
  - 目的:
    - 現在は `-H` が起動時固定値のため、実行中に時刻を前後できない。
    - GUI上で前進/巻き戻し/停止を行えるようにし、時刻探索を容易にする。
  - 仕様案:
    - キー操作中心で実装（メニュー操作には依存しない）。
    - 想定キーは `<` / `>`（実体は `Shift+,` / `Shift+.`）。キーボード配列差を考慮して予備キー併設も検討。
    - 押しっぱなし操作は `keyPressEvent`/`keyReleaseEvent` で押下状態を保持し、`QTimer` で連続更新する。
    - OSのキーリピート速度に依存しないため、操作感を一定化できる。
  - 内部設計案:
    - `SkyWindow` に時間制御状態を追加:
      - `time_shift_base: timedelta`
      - `play_rate: float`（正: 未来方向、負: 過去方向）
      - `last_tick_monotonic: float`
    - 実効オフセット:
      - `effective_delta_t = time_shift_base + elapsed * play_rate`
    - 星空更新は既存 `SkyDataWorker` 経路を再利用し、`delta_t` のみ動的更新する。
  - UI表示案:
    - オーバーレイへ `Shift` と `Rate` を追加表示（例: `Shift +02:30:00  Rate +10x`）。
  - 雲表示との整合:
    - 現在仕様どおり、実時間以外は雲を無効化する。
    - `effective_delta_t` が 0 近傍（しきい値例: ±30秒）のときのみ雲有効とし、境界チラつきを抑制する。
  - 段階導入:
    - PR1: 時間制御状態 + キー入力 + オーバーレイ表示
    - PR2: 速度プリセット/リセット導入と境界条件調整
    - PR3: 必要に応じてキー割当の設定化
